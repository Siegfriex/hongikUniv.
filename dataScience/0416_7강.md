## 2. 의사결정 4유형

### 2.1 한 줄 정의
데이터 기반 의사결정 4유형은 **현황 파악 -> 원인 규명 -> 미래 예측 -> 행동 추천**의 계단이다.

### 2.2 유형별 설명
- **기술적 분석 (Descriptive)**: "무슨 일이 있었는가?"
- **진단적 분석 (Diagnostic)**: "왜 그렇게 되었는가?" (root cause, confounding factors 구분)
- **예측적 분석 (Predictive)**: "앞으로 무엇이 일어날 것인가?"
- **처방적 분석 (Prescriptive)**: "그래서 무엇을 해야 하는가?"

### 2.3 사례 연결
- **Amazon 예측 배송**: 검색기록/장바구니/구매패턴 기반 수요예측 후 선배송  
  -> predictive + prescriptive 결합 사례
- **반도체 제조**:
  - 수율/불량률 대시보드 -> descriptive
  - 노광장비 광원 편차 원인 추적 -> diagnostic
  - 배치 수율 사전예측 -> predictive
  - 예방정비 시점 추천 -> prescriptive

### 2.4 자주 하는 실수
"불량률이 높다"는 **기술**, "왜 높아졌는지 원인을 찾는다"는 **진단**이다. 두 단계를 섞지 않아야 한다.

### 2.5 시험 답안형 한 줄
기술적 분석은 현황을 요약하고, 진단적 분석은 원인을 규명하며, 예측적 분석은 미래 결과를 추정하고, 처방적 분석은 최적 행동을 제안한다.

## 3. 텍스트 마이닝

### 3.1 한 줄 정의
텍스트 마이닝은 **텍스트 데이터로부터 의미 있는 정보와 실행 가능한 지식을 추출하는 과정**이다.

### 3.2 개념 구분
- `Text Mining`: 과정 중심(알고리즘/기법 강조)
- `Text Analytics`: 결과 활용 중심(문제 해결/의사결정)

### 3.3 왜 필요한가
- 비정형 데이터(특히 텍스트)의 폭증
- 데이터 소스: 이메일, 채팅, SNS, 리뷰, 문서, 로그
- 사람이 전량 읽고 분석하기 어려움
- 따라서 텍스트를 계산 가능한 형태로 바꿔야 함

### 3.4 핵심 병목
`text -> numerical vector` 변환이 핵심이다.  
이 과정에서 의미/문맥 보존이 어렵고, 아래 이슈가 난도를 높인다.
- 오탈자
- 띄어쓰기
- 동음이의어
- 이음동의어
- 신조어
- 한국어 교착어 특성

### 3.5 응용 5축
- 요약/시각화: 키워드, co-occurrence, 중요문장 추출
- 문서 분류: 스팸 필터링 등
- 감성 분석: 긍정/부정/중립
- 문서 군집화: 레이블 없이 유사 문서 묶기
- NLU/QA: 의도/맥락 기반 답변

### 3.6 텍스트 마이닝 프로세스 4단계
1. 문제 정의 및 필요 데이터 정의
2. 데이터 수집/획득
3. 데이터 전처리
4. 모델링 및 평가

### 3.7 개념 연결
- 선행: structured/semi-structured/unstructured, raw data 이해
- 후속: 분류/군집/추천/QA로 확장
- 유사: opinion mining, social network analytics, cluster analysis

### 3.8 텍스트 전처리 파이프라인 논리 (이미지 해설)
이 슬라이드는 텍스트 마이닝 전체가 아니라, **Text Mining Process 3단계(데이터 전처리)**를 시각 압축한 것이다.

파이프라인:
- Raw text
- Tokenization
- Text cleaning
- POS tagging
- Stopwords
- Lemmatization
- Cleaned text

핵심 메시지:
- 원문 텍스트를 바로 모델에 넣지 않는다.
- 분석 가능한 언어 단위로 분해하고, 잡음을 제거하고, 형태를 표준화한다.
- `Cleaned text`는 끝이 아니라, 벡터화(TF-IDF/BoW/Embedding) 직전의 중간 산출물이다.

### 3.9 단계별 해설 (시험 답안형)
1. **Tokenization**: 텍스트를 문장/단어/형태소 단위로 분리하는 단계  
   - 목적: 모델이 사용할 feature 단위 생성  
   - 한국어 포인트: 교착어 특성으로 형태소 기반 토큰화 중요

2. **Text cleaning**: 분석 잡음 제거 단계  
   - 예: 특수문자, HTML, URL, 중복 공백, 비분석성 문자열  
   - 주의: 감성분석에서는 느낌표/이모지/반복문자까지 신호가 될 수 있어 과한 제거 금지

3. **POS tagging**: 각 토큰의 품사 태깅 단계  
   - 목적: 토큰의 문법/의미 역할 부여
   - 효과: 과업별 feature 선택 가능(키워드 추출은 명사, 감성은 형용사/부사 등)

4. **Stopwords**: 구별력이 낮은 단어 제거 단계  
   - 목적: 핵심 정보 대비 노이즈 축소
   - 주의: QA/요약/생성 과업은 기능어 제거 시 문맥 손상이 생길 수 있어 task-dependent

5. **Lemmatization**: 활용형을 기본형으로 통일하는 단계  
   - 목적: 의미가 같은 단어 변형을 하나로 묶어 feature 분산 감소
   - 직관: 텍스트판 단위 통일(숫자 데이터의 단위 정합과 유사)

### 3.10 이 슬라이드의 진짜 포인트
- 이 그림은 "단계 나열"이 아니라 **표현 변환 관계(raw form -> cleaned representation)**를 보여준다.
- 따라서 전처리 성능이 벡터화 품질과 모델 성능을 직접 좌우한다.
- 6강 전처리(정제/정규화/변환)의 텍스트 특화 버전으로 이해하면 정확하다.

### 3.11 확인 질문 (구술 대비)
1. Tokenization은 무엇을 쪼개고, lemmatization은 무엇을 통일하는가?
2. Stopword 제거는 모든 과업에서 항상 유효한가?
3. 왜 이 단계 다음에 TF-IDF/Embedding 같은 벡터화가 와야 하는가?

### 3.12 텍스트 전처리 시험 답안 한 줄
텍스트 전처리는 raw text를 토큰화, 정제, 품사 태깅, 불용어 제거, 표제어 추출로 정규화해 분석 가능한 cleaned text로 변환하는 단계이며, 이후 벡터화와 모델링 성능을 좌우하는 핵심 과정이다.

## 4. 분석기법 선택

### 4.1 핵심 문장
질문 유형에 따라 모델 유형이 달라진다.

### 4.2 질문 -> 분석기법 매핑
- How much / how many? -> regression (연속형 예측)
- Which category? -> classification (범주 분류)
- Which group? -> clustering (유사 집단 탐색)
- Is this weird? -> anomaly detection (이상치 탐지)
- Which option? -> recommendation (선택지 추천)

### 4.3 지도/비지도 구분
- **지도학습**: 입력 \(x\) + 정답 \(y\), 회귀/분류
- **비지도학습**: 입력 \(x\)만으로 군집/이상치 탐지

### 4.4 시험 포인트
분류와 군집을 헷갈리지 말 것.
- 분류: 정답 레이블 있음
- 군집: 레이블 없음, 유사도 기반 그룹화

## 5. 추천시스템

### 5.1 한 줄 정의
추천시스템은 사용자에게 적절한 아이템을 제안하는 데이터 기반 의사결정 시스템이다.

### 5.2 비즈니스 맥락
- 업셀링(up-selling), 크로스셀링(cross-selling)
- 롱테일 환경에서 히트/니치 균형
- 연관규칙, market basket analysis, 협업필터링

### 5.2.1 질답 보강: 업셀링은 크로스셀링의 필요조건인가?
질문:
- A: 업셀링이 크로스셀링의 필요조건이다.
- B: 둘은 상관은 있을 수 있으나 필요조건 관계는 아니다.

정리:
- 교과서적으로는 **B가 더 타당**하다.
- 업셀링과 크로스셀링은 추천시스템/판매전략 안에서 함께 등장할 수 있지만, 개념적으로는 병렬 전략이다.

왜 B가 맞는가:
- 크로스셀링은 업셀링 없이도 성립한다.  
  예: 노트북 구매 시 마우스/슬리브 추천
- 업셀링도 크로스셀링 없이 성립한다.  
  예: 기본 요금제 대신 프리미엄 요금제 추천

결론:
- 둘은 동시 운영 가능성이 높은 **유사 전략**이지만, 서로의 필요조건은 아니다.
- 차이는 추천 대상 구조에 있다.
  - 업셀링: 같은 카테고리 내 상위/고가 대안 제안
  - 크로스셀링: 현재 선택과 보완재 관계의 타 품목 제안

시험 답안형 한 줄:
"업셀링과 크로스셀링은 모두 매출 증대를 위한 추천 전략이지만, 업셀링은 상위 대안을 제안하고 크로스셀링은 보완재를 제안하므로, 상관관계는 있을 수 있어도 필요조건 관계는 아니다."

### 5.2.2 질답 보강: 왜 비지도학습으로 분류하는가?
핵심 결론:
- 업셀링/크로스셀링 자체는 **마케팅·경영전략**의 언어다.
- 이를 구현하는 추천 로직 중 일부(연관규칙/군집)는 **비지도학습**으로 분류될 수 있다.
- 따라서 "추천시스템 전체 = 비지도학습"은 과도한 단순화다.

질문 분해:
1. 연관규칙은 패턴 발견인데 왜 학습인가?
2. 업셀링/크로스셀링은 전략인데 왜 비지도와 묶이나?
3. 추천시스템은 전체가 비지도인가?

왜 학습인가:
- 기계학습에서 학습은 라벨 예측만이 아니라 데이터의 구조/규칙/분포를 추정하는 과정까지 포함한다.
- 연관규칙, 군집, 이상치 탐지는 정답 \(y\) 없이 패턴을 찾으므로 비지도학습 축에 놓인다.

왜 비지도인가 (연관규칙 기준):
- 거래 데이터에는 보통 "정답 추천목록" 라벨이 없다.
- 대신 공출현 패턴을 찾아 규칙을 만든다.  
  예: `우유 -> 빵`
- 이때 `support`, `confidence`, `lift`로 규칙을 평가한다.

전략과 학습의 층위 구분:
- **전략 층위**: 업셀링/크로스셀링을 할지 결정
- **분석 층위**: 연관규칙/협업필터링/분류모델 등으로 추천 로직 구현
- **운영 층위**: 노출 위치, UI, SLA, 실험(A/B) 운영

정확한 표현:
- 부정확: "업셀링/크로스셀링은 비지도학습이다."
- 정확: "업셀링/크로스셀링 전략을 실행하기 위해 비지도학습 기반 추천기법을 사용할 수 있다."

추천시스템 전체 관점:
- 연관규칙 기반 추천: 비지도적 패턴 발견
- 군집 기반 추천: 비지도학습
- 클릭/구매 예측 추천: 지도학습으로도 구현 가능
- 즉, 추천은 "문제 유형"이고 지도/비지도는 "해결 방식"이다.

상관 vs 인과 재확인:
- 연관규칙의 높은 confidence/lift는 공출현 경향을 의미한다.
- 이것이 곧 인과관계를 증명하지는 않는다.

시험 답안형 한 줄:
"업셀링과 크로스셀링은 마케팅 전략 개념이며, 이를 지원하는 추천시스템은 연관규칙·군집 같은 비지도학습 기반 방법도, 예측 기반 지도학습 방법도 사용할 수 있으므로 추천시스템 전체를 비지도학습으로 단정할 수 없다."

재확인 문제:
"장바구니에서 라면을 담은 고객이 김치도 자주 산다"는 규칙을 Apriori로 발견한 경우는
- 비즈니스 전략 그 자체가 아니라,
- **비지도학습 기반 패턴 발견 결과**에 해당한다.

### 5.3 협업필터링 핵심 수식
- 단순 가중평균:
\[
\hat{r}_{u,i}=\frac{\sum_{v \in N(u)} sim(u,v)\,r_{v,i}}{\sum_{v \in N(u)} |sim(u,v)|}
\]

- 편차 가중평균:
\[
\hat{r}_{u,i}=\bar{r}_u+\frac{\sum_{v \in N(u)} sim(u,v)\,(r_{v,i}-\bar{r}_v)}{\sum_{v \in N(u)} |sim(u,v)|}
\]

기호:
- \(N(u)\): 사용자 \(u\)의 이웃 집합
- \(sim(u,v)\): 사용자 유사도(코사인/피어슨)
- \(r_{v,i}\): 이웃 \(v\)의 아이템 \(i\) 평점
- \(\bar{r}_u, \bar{r}_v\): 각 사용자 평균 평점

### 5.3.1 수식 보강: 사용자-아이템 행렬에 실제 대입
핵심 포인트:
- 이 수식은 추상 공식이 아니라, **User-Item Matrix의 결측값(`?`)을 메우는 계산식**이다.
- 목표 예시: 사용자1의 영화 C 평점 \(\hat{r}_{1,C}\) 예측.

예시 행렬(강의 이미지 맥락):
- 사용자1: A=5, B=5, C=?, D=5, E=1
- 사용자2: A=5, B=3, C=5, D=4, E=2
- 사용자3: A=1, B=2, C=3, D=4, E=2
- 사용자4: A=4, B=2, C=5, D=4, E=2
- 사용자5: A=1, B=1, C=3, D=5, E=4

사용자 기반 CF(User-based):
1) 사용자1과 다른 사용자들의 유사도 \(sim(1,v)\) 계산  
2) 영화 C를 실제 평가한 이웃들의 \(r_{v,C}\)를 가중평균

코사인 유사도 예시값:
- \(sim(1,2)\approx0.9678\)
- \(sim(1,3)\approx0.8488\)
- \(sim(1,4)\approx0.9431\)
- \(sim(1,5)\approx0.6822\)

대입식:
\[
\hat{r}_{1,C}
=
\frac{
0.9678\cdot5 + 0.8488\cdot3 + 0.9431\cdot5 + 0.6822\cdot3
}{
0.9678 + 0.8488 + 0.9431 + 0.6822
}
\approx 4.11
\]

해석:
- 사용자1은 영화 C를 약 4점 이상으로 평가할 가능성이 높다.
- 즉 "나와 취향이 비슷한 사람들이 C를 높게 줬으니 나도 높게 줄 것"이라는 가정이 수치화된 결과다.

top-k 이웃 효과:
- 전체 이웃이 아닌 상위 유사도 이웃(예: 사용자2,4)만 쓰면 예측값이 더 높아져 5점에 가까워질 수 있다.
- 따라서 \(N(u)\) 선택(top-k, threshold)이 결과를 크게 좌우한다.

### 5.3.2 아이템 기반 CF(Item-based)와의 대응
아이템 기반은 "비슷한 사용자" 대신 "비슷한 아이템"을 사용한다.

\[
\hat{r}_{u,i}
=
\frac{\sum_{j \in N(i)} sim(i,j)\,r_{u,j}}
{\sum_{j \in N(i)} |sim(i,j)|}
\]

- 사용자 기반: 영화 C를 본 "비슷한 사람"의 평점을 참고
- 아이템 기반: 영화 C와 "비슷한 영화"에 대해 내가 준 평점을 참고

요약 비교:
- User-based: 사람 중심 유사도
- Item-based: 아이템 중심 유사도
- 둘 다 결측 평점을 유사도 가중평균으로 추정한다.

### 5.3.3 왜 편차 가중평균이 필요한가
단순 가중평균의 한계:
- 사용자마다 평점 성향(후함/짬)을 보정하지 못한다.
- 항상 4~5를 주는 사용자와 항상 2~3을 주는 사용자를 같은 척도로 취급하면 왜곡이 생길 수 있다.

그래서 편차 가중평균을 사용:
\[
\hat{r}_{u,i}=\bar{r}_u+\frac{\sum_{v \in N(u)} sim(u,v)\,(r_{v,i}-\bar{r}_v)}{\sum_{v \in N(u)} |sim(u,v)|}
\]

핵심:
- 이웃의 "절대 점수"가 아니라 "본인 평균 대비 편차"를 반영해 개인화 정확도를 높인다.

도출 논리(시험 서술형 핵심):
1. **단순식 출발**
\[
\hat{r}_{u,i}=\frac{\sum_{v \in N(u)} sim(u,v)\,r_{v,i}}{\sum_{v \in N(u)} |sim(u,v)|}
\]
2. **문제 발견**: \(r_{v,i}\) 자체를 쓰면 이웃의 평점 스타일(후한/짠)이 그대로 섞인다.
3. **해결 아이디어**: 절대평점 대신 편차 \((r_{v,i}-\bar{r}_v)\)를 사용한다.
4. **편차 가중평균 계산**: 유사도로 가중해 이웃의 "기준 대비 초과선호"를 평균낸다.
5. **타깃 기준 복원**: 상대값만으로는 최종 점수가 아니므로 타깃 평균 \(\bar{r}_u\)를 더한다.

즉 구조는:
- 절대평점 평균 -> 편차 평균 -> 타깃 기준 복원

왜 \(\bar{r}_v\)는 빼고 \(\bar{r}_u\)는 더하나:
- \(\bar{r}_v\)를 빼는 이유: 이웃 \(v\)의 개인적 평점 습관 제거
- \(\bar{r}_u\)를 더하는 이유: 타깃 \(u\)의 평점 스케일로 결과 복원
- 암기 문장: **뺄 때는 이웃 기준 제거, 더할 때는 타깃 기준 부여**

직관 예시:
- 후한 이웃 평균이 4.8인데 특정 아이템에 5점 -> 편차 \(+0.2\)
- 짠 이웃 평균이 2.2인데 같은 아이템에 3점 -> 편차 \(+0.8\)
- 절대평점은 5 > 3이지만, 기준 대비 선호 강도는 \(+0.8\)이 더 크다.

타깃 복원 예시:
- \(\bar{r}_u=3.0\), 편차 가중평균 결과가 \(+1.2\)라면
\[
\hat{r}_{u,i}=3.0+1.2=4.2
\]
- 편차가 \(-0.8\)이면
\[
\hat{r}_{u,i}=3.0-0.8=2.2
\]

해석:
- 편차식은 절대 선호를 직접 평균내는 식이 아니라,
- 타깃 사용자 baseline 위아래 이동량을 추정하는 식이다.

### 5.3.4 시험 답안형 정리
- 정의형: "협업필터링은 사용자-아이템 행렬의 결측 평점을 유사도 가중평균으로 예측해 추천을 생성하는 방법이다."
- 비교형: "사용자 기반은 유사 사용자 평점을, 아이템 기반은 유사 아이템에 대한 내 평점을 활용한다."
- 심화형: "단순 가중평균은 평점 성향 보정이 어려워 편차 가중평균이 필요하다."

### 5.4 Netflix 사례 핵심 시사점
- Netflix Prize는 고성능 모델을 만들었지만, 현업 적용은 별개 문제였다.
- 이유: 복잡도, 실행속도, 설명가능성, 운영성 제약
- 따라서 핵심 문장: **고성능 알고리즘 != 고성과 시스템**

실무에서 함께 봐야 할 것:
- 예측 정확도
- top-k 추천 품질
- 응답속도/SLA
- 운영 복잡도
- UI/A-B 테스트 효과

## 6. 데이터 시각화

### 6.1 한 줄 정의
데이터 시각화는 정리된 데이터를 사람의 이해와 행동으로 바꾸는 표현 과정이다.

### 6.2 파이프라인 위치
`DATA -> SORTED -> ARRANGED -> PRESENTED VISUALLY`  
즉, 시각화는 분석 이후의 포장이 아니라 분석을 의사결정으로 연결하는 마지막 단계다.

### 6.3 시각화 용도
1. 이해를 쉽게 만들기
2. 추세/이상치 식별
3. 스토리 전달
4. 주장 강화
5. 중요 요소 강조

### 6.4 성공 요소 3축
- 통계와 미학의 조화
- 목적 중심 설계
- 인지/심리 규칙 반영(색상 코드 포함)

### 6.5 효과적인 시각화 6원칙
1. 목적과 대상 명확화
2. 적절한 시각화 선택
3. 문자/레이블 절제
4. 색으로 핵심 강조
5. 오도 가능성 회피
6. 단순함 유지

### 6.6 주요 기법
- 시간: 막대, 누적막대, 점그래프
- 분포: 파이, 도넛, 트리맵
- 관계: 산점도, 버블, 히스토그램
- 비교: 히트맵, 레이더/스파이더
- 공간: 지도 매핑(geospatial)

핵심은 차트 이름 암기가 아니라 **질문-차트 적합성**이다.
- 두 변수 관계 -> scatter plot
- 지리 정보 -> map
- 계층 비중 -> tree map

### 6.7 자주 하는 실수
시각화를 "예쁘게 꾸미는 작업"으로 오해하면 안 된다.  
품질 기준은 미적 화려함이 아니라 **오도 가능성 최소화 + 메시지 정확 전달**이다.

### 6.8 시험 답안형 한 줄
데이터 시각화는 raw data를 전처리/정렬/구조화한 뒤 인사이트를 직관적으로 전달해 의사결정을 지원하는 과정이다.
