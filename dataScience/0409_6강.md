## 1. 6강 개요

- 이번 강의는 모델링 자체보다 **분석 이전 단계(데이터 준비/전처리/탐색)**의 중요성을 강조한다.
- 설문 결과 기준으로 데이터 과학자의 시간 대부분은 모델 튜닝이 아니라 데이터 정비에 소요된다.
- 핵심 흐름은 다음과 같다.

`Raw data 확보 -> 변수/타입 확인 -> 전처리(필터링/변환/통합) -> EDA -> 본 분석`

## 2. 데이터 준비와 Raw Data

### 2.1 데이터 준비 시간 비중

- 2016년 데이터 과학자 대상 설문에서 전체 업무 시간의 약 **79%**가 데이터 준비에 사용됨.
- 세부 비중:

| 작업 | 비중 |
|------|------|
| 데이터세트 수집 | 19% |
| 정제/정리 | 60% |
| 훈련용 세트 구축 | 3% |
| 패턴 분석 | 9% |
| 알고리즘 개선 | 4% |
| 기타 | 5% |

즉, 실무에서 "분석 성능" 이전에 "데이터 품질"이 우선 과제다.

### 2.2 Raw Data의 두 축

| 구분 | 설명 | 예시 |
|------|------|------|
| 정성 데이터 (Qualitative) | 숫자가 아닌 언어/이미지 중심, 해석 의존성이 큼 | 인터뷰, 리뷰 텍스트, SNS 포스팅, 주관식 응답 |
| 정량 데이터 (Quantitative) | 수치로 측정 가능, 통계 계산이 용이 | 매출액, 시험점수, 방문횟수, 키/몸무게 |

### 2.3 소셜 데이터의 난점

1. 비정형성으로 문맥 파악이 어렵고 노이즈가 많다.
2. API 정책 변화로 수집 난이도가 높다.
3. 유의미한 패턴을 찾기까지 정제 비용이 크다.

## 3. 데이터 확인: 단변수·이변수·다변수

### 3.1 변수 확인 체크리스트

- 독립/종속 변수 구분
- 변수 유형(범주형/연속형) 파악
- 데이터 타입(date, character, numeric 등) 확인

### 3.2 단변수(Univariate)

- Five-number summary
- 평균/최빈값/중앙값
- 히스토그램, 박스플롯
- 예시: `iris` 데이터셋 (`R: View()`, `Python: describe()`)

### 3.3 이변수(Bivariate) 분석 매트릭스

| 변수 조합 | 시각화/표 | 분석 방법 |
|----------|-----------|-----------|
| 연속형-연속형 | 산점도 | 상관관계 분석 |
| 범주형-범주형 | 도수표, 누적막대 | 카이제곱 독립성 검정 |
| 범주형-연속형 | 범주별 히스토그램, 박스플롯 | 2집단: t/z 검정, 3집단 이상: ANOVA |

### 3.4 이변수 사례

- 연속형-연속형: `SNS 광고비(X)`와 `신규 가입자수(Y)` 관계 분석
- 범주형-범주형: 성별과 스마트폰 브랜드 선호도(카이제곱 검정)
- 범주형-연속형: 학력수준별 평균소득 비교(ANOVA)

### 3.5 다변수(Multivariate)

- 3개 이상 변수의 관계를 함께 시각화/분석
- 범주형 변수가 포함되면 범주별로 분할 탐색
- 예시: `iris`의 연속형(sepal/petal) + 범주형(species)

## 4. 데이터 전처리(Preprocessing)

### 4.1 전처리 정의

- 수집 데이터의 불완전/오염/비표준 문제를 해결해 분석 가능한 형태로 바꾸는 과정
- 데이터 품질 검증과 형식 변환을 포함
- 데이터 정제(cleaning)와 실무적으로 겹치는 개념

### 4.2 전처리 전 질문

- 결측이 있는가?
- 틀린 값이 있는가?
- 단위가 섞여 있는가? (inch/cm, pound/kg)
- 분석 가능한 형식인가?
- 추가 가공이 필요한가?

### 4.3 전처리 3가지 형태

1. 데이터 필터링 (결측치/틀린값/이상치)
2. 데이터 변환 (이산화/정규화/표준화/로그변환)
3. 데이터 통합 (식별자 기반 결합, 단위 통일, 중복 제거)

### 4.4 데이터 필터링

#### 결측치 (Missing Value)

- 결측 포함 샘플 제거
- 평균/중앙값/인접값/예측값으로 대체
- `NA`로 표시 후 분석 단계에서 처리

#### 틀린값 (Invalid Data)

- 예: 숫자 칸 문자열, 비현실적 입력값
- 결측치보다 발견이 어렵고, 규칙 기반 검증이 필요

#### 이상치 (Outlier/Anomaly)

- 일반 범위를 벗어나지만 "틀린 값"과는 다름
- 예: 키 3.7m(틀린값), 2.1m(이상치 가능)
- 발견 방법: 기초통계, 박스플롯, 히스토그램, 시계열, 통계검정(Grubbs), ML 기법(k-means 등)

### 4.5 데이터 변환

#### 이산화(Binning)

- 연속형을 구간 기반 범주로 변환
- 예: 나이(10대/20대/30대), 소득(저/중/고)

#### 정규화(Normalization)

- 스케일 차이를 줄여 비교/학습 안정화
- 대표 방식:
  - MaxAbs: 절대최대값 기준, `[-1, 1]`
  - Min-Max: 최소/최대 매핑, `[0, 1]`

#### 표준화(Standardization)

- 평균 0, 표준편차 1 기준(Z-score)
- 같은 평균이라도 분산이 다른 집단 비교에 유리

#### 로그 변환(Log Transform)

- 한쪽으로 치우친 분포(skewed)나 범위 격차가 큰 데이터 압축
- 오더 차이가 큰 값을 동일 축에서 해석하기 쉬움

### 4.6 데이터 통합

- 출처가 다른 연관 데이터를 하나의 데이터셋으로 결합
- 핵심 체크:
  - 유일 식별자 존재 여부
  - 단위/표현 방식 통일
  - 중복 레코드 검출/제거
- 실무에서 전처리/가공은 전체 분석 시간의 큰 비중(약 60~70%)을 차지

## 5. 전처리 예시: 와인 소비량-질환 사망률

### 데이터 설명

- `Country`: 국가
- `Alcohol`: 1인당 와인 소비량(리터)
- `Deaths`: 음주 관련 사망자 수(10만 명당)
- `Heart`: 심장질환 사망자 수(10만 명당)
- `Liver`: 간질환 사망자 수(10만 명당)

### 전처리 단계

1. 노이즈 완화: 음수값 처리
2. 결측치 대체: 평균값 처리
3. 통합: 인도 state 평균 활용/기타 항목 평균 보정
4. 축소: 과도한 소수점/불필요 컬럼 정리
5. 이산화: Alcohol 구간화

예시 구간:

- `[0,1) -> 0`
- `[1,2) -> 1`
- `[2,5) -> 2`
- `[5,inf) -> 3`

## 6. 데이터 탐색(EDA)

### 6.1 EDA 정의와 목적

- 본 분석 전에 데이터의 전반적 특성을 파악하는 탐색 단계
- 데이터 적합성 점검, 추가 수집 필요성 판단, 가설 보완/생성에 기여
- John W. Tukey(1977) 관점: 하나의 가설만 보지 말고 다양한 시각에서 자료를 살펴라

### 6.2 CDA vs EDA

| 구분 | CDA (확증적 분석) | EDA (탐색적 분석) |
|------|-------------------|-------------------|
| 출발점 | 가설 검정 | 데이터 탐험 |
| 초점 | 채택/기각 | 구조/패턴 발견 |
| 장점 | 명확한 검정 절차 | 새로운 인사이트 발굴 |

### 6.3 EDA 질문 리스트

- 데이터셋 크기와 범위는?
- 주어진 데이터가 전체인가, 일부 샘플인가?
- 모집단 대표성은 충분한가?
- 이상치/노이즈는 어느 정도인가?
- 원본이 아닌 임의 가공 데이터가 섞였는가?
- 식별자와 중복 문제는 없는가?
- 두 데이터셋 결합 시 같은 기준으로 수집됐는가?
- 누락값은 얼마나, 왜 발생했는가?

### 6.4 질문의 저의: 왜 묻고, 무엇을 확인하며, 무엇을 할 것인가

| EDA 질문 | 질문의 저의(왜?) | 무엇을 확인? | 왜 중요한가? | 질문 후 해야 할 일 |
|----------|------------------|---------------|--------------|--------------------|
| 데이터셋 크기와 범위는? | 통계적으로 의미 있는 분석이 가능한지 사전 점검 | 행/열 수, 기간 범위, 클래스별 표본수 | 표본이 작거나 기간이 짧으면 결과가 불안정 | 최소 표본 기준 설정, 부족 시 수집 확대 또는 문제 재정의 |
| 전체 데이터인가 일부 샘플인가? | 결론 일반화 가능 범위를 명확히 하기 위함 | 샘플링 방식(무작위/편의), 추출 비율, 누락 구간 | 샘플 바이어스가 크면 모델이 실제를 반영하지 못함 | 샘플링 로그 확보, 층화 재추출, 가중치 보정 검토 |
| 모집단을 잘 대표하는가? | "이 데이터로 의사결정해도 되는가"를 검증 | 인구통계/시간/지역 분포 비교, 기준 통계와 괴리 | 대표성 부족은 편향된 정책/예측으로 직결 | 대표성 리포트 작성, 부족 집단 추가 수집 계획 수립 |
| 이상치/노이즈가 심한가? | 신호와 오류를 분리해 분석 신뢰도를 높이기 위함 | IQR, z-score, 박스플롯, 도메인 규칙 위반 비율 | 이상치가 평균/회귀계수를 왜곡해 잘못된 결론 유도 | 오류값 정정/제거, 진짜 이상현상은 별도 태깅 후 원인 분석 |
| 원본이 아닌 임의 가공 데이터가 섞였는가? | 데이터 계보(Lineage)와 재현 가능성 확보 | 생성 컬럼 여부, 수작업 수정 로그, 가공 버전 | 출처 불명 데이터는 검증 불가, 재현 불가 리스크 큼 | 원본/가공 분리 저장, 데이터 사전/변경 이력 문서화 |
| 식별자가 존재하며 중복되지 않는가? | 레코드 단위의 일관성과 조인 정확도 확인 | Primary key 결측률, 중복률, 복합키 충돌 | ID 오류는 중복 집계/잘못된 결합을 초래 | PK 규칙 정의, 중복 제거 정책 적용, 결측 ID 처리 룰 확정 |
| 결합 대상 데이터셋이 같은 기준인가? | 서로 다른 데이터의 비교/통합 가능성 점검 | 단위(cm/inch), 시간대, 코드체계, 수집 시점 | 기준 불일치 상태의 통합은 해석 오류를 만든다 | 단위 표준화, 코드 매핑 테이블 구축, 조인 키 검증 테스트 |
| 누락값은 얼마나, 왜 누락됐는가? | 결측 메커니즘(MCAR/MAR/MNAR) 파악 | 컬럼별 결측률, 패턴(집단/시간별), 수집 프로세스 이슈 | 잘못된 결측 처리 시 편향 증가, 성능 저하 | 삭제/대체/모델기반 대치 중 선택, 결측 플래그 변수 추가 |

강의 포인트: EDA 질문은 "확인용 질문"이 아니라 **데이터 리스크를 조기 차단하는 의사결정 질문**이다.

### 6.5 EDA 4단계

1. 분석 목적/변수 정의 확인
2. 데이터 전체 훑기(head/tail, 결측/이상치)
3. 개별 속성 분포/범위 점검
4. 속성 간 관계 분석(상관, 시각화)

### 6.6 EDA의 4대 주제

1. 저항성(이상치에 덜 민감한 지표 활용, 예: 평균 대신 중앙값)
2. 잔차 해석(흐름에서 벗어난 값의 원인 탐색)
3. 자료 재표현(로그/제곱근/역수 변환)
4. 현시성(그래프 기반 전달: box/scatter/stem-leaf 등)

### 6.7 상관계수 해석 주의

- 상관이 크다고 인과를 의미하지 않는다.
- 가능성:
  - 제3의 교락변수 존재
  - 인과 방향이 반대일 수 있음

### 6.8 EDA 과정 4단계의 구체화 (강의 슬라이드 기반)

#### 1단계: 분석 목적과 변수 확인

- 무엇을 예측/설명할지 목표를 먼저 고정한다.
- 변수 사전(data dictionary) 점검:
  - 변수명, 의미, 단위, 타입(범주형/연속형), 결측 허용 여부
- 독립/종속 변수를 명시하고, 해석 단위를 일치시킨다.

#### 2단계: 데이터 전체 스캔

- `head/tail`, 기본 통계(`describe`)로 전반 상태 확인
- 즉시 확인할 위험 신호:
  - 결측치 대량 발생 컬럼
  - 타입 불일치(숫자 칸 문자열)
  - 비현실적 값(도메인 규칙 위반)
- 이 단계의 목적은 "바로 모델링"이 아니라 **데이터 문제 지도(risk map)** 작성이다.

#### 3단계: 개별 속성(단변수) 점검

- 각 변수의 범위/분포가 기대와 맞는지 확인
- 대표 도구: 히스토그램, 박스플롯, 사분위수, 중앙값
- 분포가 한쪽으로 치우치면(log-skew) 로그 변환 등 재표현을 검토

#### 4단계: 속성 간 관계(이변수/다변수) 탐색

- 산점도/교차표/상관계수로 변수 간 패턴 확인
- 단변수에서 못 본 구조(군집, 비선형, 교호작용)를 찾는 단계
- 결과는 "가설 검정의 종결"이 아니라 **다음 분석 가설 생성**으로 연결

### 6.9 이미지 슬라이드 전사 요약: 핵심 워딩과 개념

1. **저항성(Resistance to Outliers)**  
   이상치/결측/입력오류 영향이 작은 통계량으로 데이터 파악(예: 평균 대신 중앙값).

2. **잔차 해석(Residual)**  
   흐름(추세선)에서 벗어난 정도를 보고, 왜 벗어났는지 원인을 해석.

3. **산포도와 공분산(Covariance)**  
   산포도는 X-Y 관계를 시각화, 공분산은 관계 방향을 수치화.

4. **공분산 계산 예시(슬라이드)**  
   \[
   s_{xy}=\frac{1}{n-1}\sum_{i=1}^{n}(X_i-\bar X)(Y_i-\bar Y)
   \]
   슬라이드 합계값 기준:
   \[
   s_{xy}=\frac{1}{5-1}\times 67,200=16,800
   \]
   포인트: 공분산은 **부호(방향)**는 유의미하지만, 크기는 스케일 영향으로 직접 비교가 어렵다.

5. **상관계수(Correlation Coefficient)**  
   공분산을 표준편차로 정규화한 지표:
   \[
   \rho=\frac{\sigma_{xy}}{\sigma_x\sigma_y}
   \]
   값 범위는 \([-1,1]\), 방향(+/-)과 선형 결합 강도를 표현.

### 6.10 상관분석 방법론: 무엇을 왜 쓰는가

| 방법 | 언제 쓰나 | 장점 | 주의사항 |
|------|-----------|------|----------|
| Pearson | 연속형-연속형, 선형관계 가정 가능 | 해석 직관적, 가장 보편적 | 이상치/비선형/심한 비정규에 민감 |
| Spearman (순위상관) | 단조(monotonic) 관계, 서열형 데이터 | 비선형 단조관계 포착, 이상치에 상대적으로 강함 | 값 자체가 아니라 순위 기준 |
| Kendall \(\tau\) | 표본이 작거나 동순위가 많은 서열 자료 | 확률적 해석이 쉬움(일치쌍-불일치쌍) | 계산량이 크고 수치가 Pearson보다 작게 나오는 경향 |

실무 선택 규칙(강의용 한 줄):
- **선형 + 연속형**이면 Pearson,
- **단조지만 선형 아님/서열형**이면 Spearman,
- **작은 표본·동순위 많음**이면 Kendall.

### 6.11 증명형 예제: 공분산에서 상관계수로 이어가기

슬라이드 공분산 예시를 그대로 활용하면:

1. 공분산(표본):
\[
s_{xy}=16,800
\]

2. 표준화 전 공분산의 한계:
- 단위(만원, 원, 달러 등)가 바뀌면 공분산 크기도 바뀜
- 즉, 크기 자체로 관계 강도를 비교하기 어려움

3. 상관계수로 정규화:
\[
r=\frac{\sum (X_i-\bar X)(Y_i-\bar Y)}
{\sqrt{\sum (X_i-\bar X)^2\sum (Y_i-\bar Y)^2}}
\]

슬라이드 표(중심화 값) 기준으로 계산하면 \(r \approx 0.74\)로 **양(+)의 중간~강한 선형관계**를 해석할 수 있다.

강의 해석 문장:
- "광고비가 증가할수록 매출이 증가하는 경향은 있다. 다만 이것만으로 광고비가 매출의 원인이라고 단정할 수는 없다."

### 6.12 상관 \(\neq\) 인과: 왜 교락을 반드시 확인해야 하나

- 상관은 "같이 변한다"를 말하고, 인과는 "원인-결과"를 말한다.
- 교락변수 \(C\)가 \(X, Y\)를 동시에 움직이면 \(X\)와 \(Y\)는 강한 상관을 보일 수 있다.

예:
- 아이스크림 판매량(X)과 익사 사고(Y)는 양의 상관이 있을 수 있음
- 그러나 공통 원인 \(C\)=기온(여름)이 둘 다 증가시키는 교락 가능성

따라서 상관분석 이후 최소 점검:
1. 시간 선후관계 확인
2. 교락 후보 변수 통제(회귀/층화/매칭)
3. 가능하면 실험/준실험 설계로 인과 검증

### 6.13 웹 그라운딩 기반 보강 포인트 (강의 인텔리전스)

- NIST: 상관계수는 선형관계 강도/방향 지표이며, \(r=0\)은 "선형관계 없음"이지 "관계 없음"이 아님.
- NIST/실무 문헌: 공분산은 스케일 의존적이어서 직접 강도 비교에 부적절.
- CRISP-DM/IBM: 데이터 이해-준비 단계가 프로젝트 시간의 큰 비중을 차지.
- 비모수 상관: Spearman/Kendall은 순위 기반으로 비선형 단조 관계나 서열형 자료에 유리.

## 10. 데이터분석 및 시각화 (6강 확장)

### 10.1 데이터 기반 의사결정: Amazon 예측 배송 사례

- 핵심 개념: `Shipment in transit before you buy the product`
- 고객의 검색 기록/장바구니/구매 패턴으로 수요를 예측해, 구매 전에 물류 거점에 선배치
- 주문 발생 시 근거리 출고로 리드타임 단축
- 기대 효과:
  - 고객만족도 증가
  - 판매량 확대
  - 재고 효율성 개선

강의 해석:
- 이 사례는 단순 예측이 아니라 **예측 + 처방**의 결합 사례다.
- "무엇이 일어날까?"를 넘어 "무엇을 먼저 해야 하나?"로 이어진다.

### 10.2 데이터 기반 의사결정 4유형

| 유형 | 핵심 질문 | 산출물 | 대표 예시 |
|------|-----------|--------|-----------|
| 기술적(Descriptive) | 무슨 일이 일어났는가? | 대시보드/KPI 현황 | 지난달 매출, 방문자 수 |
| 진단적(Diagnostic) | 왜 일어났는가? | 원인 분석, 분해 리포트 | 이탈 증가 원인 분석 |
| 예측적(Predictive) | 앞으로 무엇이 일어날까? | 예측값/확률 | 다음 분기 매출 예측 |
| 처방적(Prescriptive) | 무엇을 해야 하는가? | 액션 추천/최적화안 | 쿠폰 전략, 물류 전략 |

포인트:
- 기술 -> 진단 -> 예측 -> 처방으로 갈수록 **가치와 복잡도**가 함께 증가한다.

슬라이드 핵심 정의(영문 대응):
- **Descriptive**: what happened를 설명한다.
- **Diagnostic**: why it happened를 설명한다.
- **Predictive**: what might happen을 예측한다.
- **Prescriptive**: 예측 결과를 바탕으로 어떤 action을 취할지 권고한다.

시험 답안형 한 줄:
- "데이터 기반 의사결정은 과거/현재의 현상 설명(기술)에서 원인 규명(진단), 미래 예측(예측), 실행 권고(처방)로 확장되는 단계적 분석 체계다."

### 10.3 반도체 제조 사례로 보는 4유형

- 기술: 웨이퍼 수량/수율/불량률/가동시간 집계
- 진단: 특정 공정(예: 포토) 불량 원인 추적
- 예측: 배치 수율 사전 예측
- 처방: 예방정비 시점 추천으로 생산 손실 최소화

### 10.4 데이터사이언스 주제별 분석기법 맵

Microsoft Azure 질문 프레임을 강의 흐름에 연결:

| 질문 형태 | 분석 과제 | 대표 방법 |
|-----------|-----------|-----------|
| How much / how many? | 수치 예측 | 회귀(Regression) |
| Which category? | 범주 예측 | 분류(Classification) |
| Which group? | 숨은 군집 탐색 | 군집화(Clustering) |
| Is this weird? | 이상 패턴 탐지 | 이상치 탐지(Anomaly Detection) |
| Which option should be taken? | 행동 대안 추천 | 추천시스템(Recommendation) |

### 10.5 머신러닝 방법론 분류 정리

#### 지도학습 (Supervised Learning)
- 입력 \(x\)와 정답 \(y\)를 함께 학습
- 회귀: 연속형 출력 (집값, 온도)
- 분류: 범주형 출력 (스팸 여부, 질병 유무)

#### 비지도학습 (Unsupervised Learning)
- 정답 없이 입력 \(x\)만으로 구조 탐색
- 군집화: 유사한 데이터 그룹화
- 이상치 탐지: 정상 분포에서 벗어난 샘플 식별

#### 추천시스템
- 사용자-아이템 상호작용 기반 선호 예측
- 업셀링/크로스셀링과 직접 연결

### 10.6 텍스트 마이닝: 정의, 동기, 응용

#### 정의
- 텍스트로부터 고품질 정보/지식을 자동 추출하는 과정
- Mining은 과정(알고리즘), Analytics는 활용(의사결정)에 강조점

#### 정형 vs 비정형 데이터
- 정형(Structured): 사전에 정의된 스키마/테이블 구조에 저장, 처리/질의가 용이
- 비정형(Unstructured): 고정 스키마 없이 원시 형태(텍스트, 이미지, 오디오, 비디오, 문서 등)로 저장
- 강의 기준 포인트: 기업 데이터에서 정형은 일부(약 20%), 비정형이 다수(약 80%)를 차지

#### 동기
- 비정형 데이터의 급증
- 이메일/SNS/리뷰/로그 등 텍스트 소스의 폭발
- 사람의 수작업 독해만으로는 처리 불가
- Web scraping/API를 통한 수집이 쉬워져 텍스트 데이터 활용 기회가 증가
- 읽을 수 있는 텍스트가 많아졌지만, "읽을 수 있다"와 "분석 가능하다"는 다르므로 방법론이 필요

#### 주요 응용
- 요약/키워드 추출/시각화
- 문서 분류(스팸 필터링)
- 감성 분석(긍정/부정/중립)
- 문서 군집화(레이블 없이 주제 탐색)
- NLU/QA(질의 의도 해석과 답변 생성)

#### Summarization & Visualization 응용 사례 (강의 원자료 반영)

1) 연설문 요약/시각화
- 단순 단어 빈도 집계를 넘어, 키워드 맥락과 메시지 프레이밍을 함께 해석
- 정치/경영/역사 연구 등에서 담론 구조를 비교하는 근거로 사용
- 예: 대선 수락 연설문에서 핵심 어휘(people, country, America 등) 집중도를 통해 메시지 축을 해석

2) 담화 네트워크 기반 시기 비교
- 시기별 연설/담화 텍스트에서 키워드 추출 후 co-occurrence 네트워크 구축
- 기간별 중심 키워드, 연결강도, 커뮤니티 구조 변화를 비교해 담론 전환 시점을 분석
- 강의 제시 구간:
  - 기간1(2012.1.1~2013.3.30): 권력기반 강화기
  - 기간2(2013.3.31~2016.5.6): 경제·핵 병진노선 추진기
  - 기간3(2016.5.7~2018.4.20): 경제건설 총력기

3) 특허 문서 요약 기반 기술동향 분석
- 특허 본문에서 중요 문장 추출 + 키워드 분석 + 인용관계 네트워크 결합
- 클러스터링/연결망 시각화를 통해 기술 트렌드와 공백 영역(white space) 파악
- 연구개발 의사결정(우선 투자 분야, 협업 후보 탐색)에 직접 활용 가능

### 10.7 텍스트 마이닝 도전과제

- 텍스트 -> 수치 벡터 변환 필요(문맥 보존이 핵심)
- 한국어 포함 언어 특성 이슈:
  - 오탈자
  - 띄어쓰기/형태소 경계
  - 동음이의어
  - 이음동의어(표기 다양성)
  - 문맥 의존 의미
  - 신조어/도메인 약어

강의 포인트:
- 모델 고도화 이전에 전처리/정규화/토큰화 품질이 성능을 좌우한다.

### 10.8 텍스트 마이닝 프로세스 (4단계)

1. 문제 정의 및 필요 데이터 정의
2. 데이터 수집/획득(API, 스크래핑 등)
3. 데이터 전처리(정규화, 토큰화, 불용어 처리 등)
4. 모델링/평가(분류/군집/요약/감성 등)

### 10.9 추천시스템 핵심 정리

#### 협업필터링 직관
- 유사 사용자 이웃 \(N(u)\), 유사도 \(sim(u,v)\), 이웃 평점 \(r_{v,i}\) 사용
- 사용자 프로파일이 부족해도 과거 상호작용으로 추천 가능

#### 단순 가중평균
\[
\hat r_{u,i} = \frac{\sum_{v \in N(u)} sim(u,v)\,r_{v,i}}
{\sum_{v \in N(u)} |sim(u,v)|}
\]

기호 해석:
- \(N(u)\): 사용자 \(u\)와 유사도가 높고 아이템 \(i\)를 평가한 이웃 사용자 집합
- \(sim(u,v)\): 사용자 \(u\)와 \(v\)의 유사도 (주로 코사인 유사도 또는 피어슨 상관계수)
- \(r_{v,i}\): 이웃 사용자 \(v\)가 아이템 \(i\)에 실제로 부여한 평점
- \(\hat r_{u,i}\): 타겟 사용자 \(u\)의 아이템 \(i\) 예측 평점

해석:
- 유사도가 큰 이웃의 평점일수록 더 큰 가중치를 부여한다.
- 분모에 \(|sim(u,v)|\)를 두어 가중치 크기를 정규화해 예측값 스케일을 안정화한다.

#### 편차 기반 가중평균
\[
\hat r_{u,i} = \bar r_u +
\frac{\sum_{v \in N(u)} sim(u,v)\,(r_{v,i}-\bar r_v)}
{\sum_{v \in N(u)} |sim(u,v)|}
\]

#### Netflix 인사이트
- 대회 성능이 높아도 현업 적용성(복잡도/속도/설명력)이 낮으면 채택이 어려움
- 실무는 "최고 성능"보다 "운영 가능한 성능"이 더 중요

### 10.10 데이터 시각화: 단계와 설계 원칙

#### 시각화 단계
`DATA -> SORTED -> ARRANGED -> PRESENTED VISUALLY`

- DATA: 원시 데이터
- SORTED: 분류/전처리
- ARRANGED: 정렬/구조화 + EDA
- PRESENTED: 시각적 제시 + 스토리텔링

#### 시각화 용도
1. 이해를 쉽게 만든다
2. 추세/이상치를 식별한다
3. 데이터의 이야기를 전달한다
4. 주장/의견을 강화한다
5. 핵심을 강조한다

#### 효과적인 시각화 6원칙
1. 목적과 청중을 먼저 정의
2. 데이터 성격에 맞는 차트 선택
3. 텍스트/레이블은 정보 전달에만 사용
4. 색은 강조를 위해 제한적으로 사용
5. 오해를 부르는 표현(축 왜곡 등) 회피
6. 단순하고 일관된 레이아웃 유지

### 10.11 주요 시각화 방법 매핑

| 관점 | 차트 예시 | 언제 쓰나 |
|------|-----------|-----------|
| 시간 | 막대/누적막대/점그래프 | 시계열 변화 추적 |
| 분포 | 히스토그램/박스플롯/트리맵 | 분포, 치우침, 이상치 확인 |
| 관계 | 산점도/버블차트 | 두 변수 관계/상관 탐색 |
| 비교 | 히트맵/레이더/평행좌표 | 집단·다변수 비교 |
| 공간 | 지도 시각화 | 지역 패턴 분석 |

주의:
- 파이/도넛은 비중 비교에만 제한적으로 사용
- 관계 시각화의 기본은 산점도(축/단위 명확화 필수)

### 10.12 본 페이즈 핵심 요약

- 분석은 질문 구조(기술/진단/예측/처방)로 시작해야 한다.
- 텍스트 마이닝은 비정형 데이터 시대의 핵심 분석 축이며, 전처리 품질이 성능을 좌우한다.
- 추천시스템은 예측력만이 아니라 실행속도/설명력/운영성의 균형이 중요하다.
- 시각화는 미적 요소보다 목적 전달이 우선이며, 차트 선택과 해석 윤리가 성패를 좌우한다.

## 11. 원자료 처리 기반 통합 리포맷 (A~E)

이 섹션은 6강 전체를 "원문 -> 가공 -> 분석 -> 적용" 순서로 재정리한 표준 출력본이다.

### 11.1 데이터 기반 의사결정 4유형

#### A. 원문 핵심 추출
- Descriptive: what happened
- Diagnostic: why it happened
- Predictive: what might happen
- Prescriptive: recommend action based on forecast

#### B. 개념 설명(정의 + 쉬운말)
- 기술적 분석은 "무슨 일이 있었는지"를 보여주는 현황 파악 단계다.
- 진단적 분석은 "왜 그랬는지" 원인을 파고드는 단계다.
- 예측적 분석은 "앞으로 어떻게 될지"를 확률/수치로 예측한다.
- 처방적 분석은 예측 결과를 바탕으로 "무엇을 할지" 실행안을 제시한다.

#### C. 질문의 저의(왜 중요한가)
- 데이터 활용의 최종 목적은 리포트 생산이 아니라 **행동 가능한 의사결정**이기 때문이다.

#### D. 적용 방법(지표/행동)
- 기술: KPI 대시보드(매출/방문자/수율)
- 진단: 원인 분해(Root Cause, 세그먼트 분해)
- 예측: 회귀/분류 모델로 미래값 추정
- 처방: 정책 시뮬레이션, 추천전략, 최적화

#### E. 시험 답안형 한 줄
- "데이터 기반 의사결정은 현상 설명(기술)에서 원인 규명(진단), 미래 예측(예측), 실행 권고(처방)로 고도화되는 단계적 체계다."

### 11.2 EDA 질문과 전처리 판단

#### A. 원문 핵심 추출
- 데이터셋 크기/대표성/결측/이상치/식별자/결합기준을 질문한다.

#### B. 개념 설명(정의 + 쉬운말)
- EDA 질문은 데이터 품질을 확인하기 위한 체크리스트이며, 분석 실패를 사전에 막는 장치다.

#### C. 질문의 저의(왜 중요한가)
- 잘못된 데이터로 정교한 모델을 만들어도 결론은 왜곡된다.

#### D. 적용 방법(지표/행동)
- 결측률, 중복률, 타입 오류율, 이상치 비율 측정
- 단위 통일(cm/inch), 키 정합성 검증, 결합 전후 행 수 점검
- 결측 메커니즘(MCAR/MAR/MNAR) 가설 세우고 대체 전략 선택

#### E. 시험 답안형 한 줄
- "EDA 질문은 분석 전에 데이터 리스크를 계량화하여 전처리/수집 재설계를 결정하기 위한 의사결정 장치다."

### 11.3 상관분석: 공분산에서 상관계수까지

#### A. 원문 핵심 추출
- 공분산은 방향을 보여주지만 크기 해석은 어렵다.
- 상관계수는 공분산을 표준화한 지표다.
- 상관이 커도 인과를 의미하지 않는다.

#### B. 개념 설명(정의 + 쉬운말)
- 공분산은 두 변수가 함께 움직이는 방향(+/-)을 본다.
- 상관계수는 그 관계를 -1~1 범위로 맞춰 강도 비교가 가능하다.
- Pearson/Spearman/Kendall은 데이터 형태와 가정에 따라 선택한다.

#### C. 질문의 저의(왜 중요한가)
- 관계를 수치로 요약하되, 잘못된 인과 해석을 막기 위해서다.

#### D. 적용 방법(지표/행동)
- 선형 연속형: Pearson
- 단조/서열형: Spearman
- 소표본/동순위 많음: Kendall tau
- 후속 조치: 시간 선후관계 확인, 교락 통제, 필요 시 실험 설계

#### E. 시험 답안형 한 줄
- "상관분석은 변수 관련성의 방향과 강도를 보여주지만, 인과추론은 교락 통제와 추가 설계 없이는 성립하지 않는다."

### 11.4 텍스트 마이닝

#### A. 원문 핵심 추출
- 텍스트마이닝은 텍스트에서 고품질 정보를 추출해 의사결정을 지원하는 과정이다.
- 정형 데이터는 사전정의 스키마 기반, 비정형 데이터는 원시 형태이며 기업 데이터의 다수는 비정형이다.
- 텍스트 데이터는 이메일/채팅/SNS/리뷰/로그/보고서 등 다양한 소스에서 폭증 중이다.
- 응용은 요약/시각화, 담론 네트워크 분석, 특허 문서 중요문장 추출까지 확장된다.

#### B. 개념 설명(정의 + 쉬운말)
- 핵심은 "문장을 숫자로 바꾸는 것"이 아니라 **의미를 보존한 채 벡터화**하는 것이다.
- 정형 데이터는 바로 분석하기 쉬우나, 비정형 텍스트는 전처리/표현학습 단계를 거쳐야 분석 가능해진다.

#### C. 질문의 저의(왜 중요한가)
- AI/데이터사이언스의 실제 현장에서 증가하는 데이터는 비정형이므로, 텍스트 처리 역량이 분석 경쟁력을 좌우한다.
- "읽을 수 있는 데이터"를 "의사결정 가능한 데이터"로 전환하는 단계가 바로 텍스트마이닝이다.

#### D. 적용 방법(지표/행동)
- 프로세스: 문제 정의 -> 수집 -> 전처리 -> 모델링/평가
- 분류: Accuracy/F1, 감성: Macro-F1, 군집: 실루엣 + 해석 가능성
- 한국어는 토크나이저/사전/정규화 품질을 우선 개선
- 전처리 최소 체크:
  - 문자 정규화(대소문자/기호/중복공백)
  - 토큰화/불용어/표제어 처리
  - 도메인 사전(약어/신조어/오탈자 규칙) 구축
- 데이터 소스 확장: API + 크롤링 + 내부 로그를 결합하되, 출처/수집시점/라벨 품질 메타데이터를 함께 관리

응용별 실행 프레임:
- 연설문/담화 분석: 키워드 추출 -> 기간 분할 -> co-occurrence 네트워크 -> 중심성/커뮤니티 비교
- 특허 동향 분석: 중요 문장 추출 -> 키워드/인용 네트워크 결합 -> 클러스터별 트렌드 해석
- 시각화 산출물: 워드클라우드(탐색용), 네트워크 그래프(구조용), 타임라인(변화용) 병행

#### E. 시험 답안형 한 줄
- "정형 데이터는 분석이 쉽지만 비정형 텍스트가 데이터의 큰 비중을 차지하므로, 텍스트마이닝은 비정형 데이터를 의사결정 가능한 지식으로 변환하는 핵심 방법론이다."

### 11.6 추천시스템: 단순가중평균 (A~E)

#### A. 원문 핵심 추출
- 단순가중평균은 이웃 사용자 평점을 유사도 가중치로 합산해 미평가 아이템 평점을 예측한다.
- 핵심 기호는 \(N(u)\), \(sim(u,v)\), \(r_{v,i}\) 이다.

#### B. 개념 설명(정의 + 쉬운말)
- 타겟 사용자와 비슷한 사람들의 의견을 더 크게 반영해 "좋아할 점수"를 추정하는 방식이다.
- 즉, "나와 비슷한 사람들이 높게 준 아이템이면 나도 높게 줄 가능성이 크다"는 가정이다.

#### C. 질문의 저의(왜 중요한가)
- 추천시스템의 핵심은 미평가 아이템의 선호를 추정하는 것이며, 단순가중평균은 가장 직관적인 기본 모델이기 때문이다.

#### D. 적용 방법(지표/행동)
- 수식:
\[
\hat r_{u,i} = \frac{\sum_{v \in N(u)} sim(u,v)\,r_{v,i}}
{\sum_{v \in N(u)} |sim(u,v)|}
\]
- 기호:
  - \(N(u)\): 사용자 \(u\)의 이웃 집합(아이템 \(i\)를 평가한 사용자)
  - \(sim(u,v)\): 사용자 유사도(코사인/피어슨)
  - \(r_{v,i}\): 이웃 \(v\)의 실제 평점
- 실무 체크:
  - 유사도 임계치(또는 top-k 이웃) 설정
  - 데이터 희소성(평점 부족) 완화 전략 확보
  - 평가 지표(RMSE/MAE, Top-N Precision/Recall) 병행

#### E. 시험 답안형 한 줄
- "단순가중평균 협업필터링은 유사한 이웃 사용자 평점을 유사도 가중합으로 정규화해 타겟 사용자의 미평가 아이템 평점을 예측하는 방법이다."

### 11.5 데이터 시각화

#### A. 원문 핵심 추출
- DATA -> SORTED -> ARRANGED -> PRESENTED VISUALLY
- 목적/청중/차트 선택/색상 강조/오해 방지/단순성 원칙

#### B. 개념 설명(정의 + 쉬운말)
- 시각화는 그림이 아니라 의사결정 메시지를 빠르게 전달하는 정보 압축 방식이다.

#### C. 질문의 저의(왜 중요한가)
- 같은 데이터라도 표현 방식에 따라 해석이 달라지고, 잘못된 시각화는 잘못된 결정을 유도한다.

#### D. 적용 방법(지표/행동)
- 시간: 막대/선
- 분포: 히스토그램/박스플롯
- 관계: 산점도
- 비교: 히트맵/레이더
- 공간: 지도
- 실행 체크: 축 단위/범례/색상 의미/주석 문장 확인

#### E. 시험 답안형 한 줄
- "효과적인 시각화는 미적 요소보다 목적 적합성, 인지 친화성, 오해 방지 원칙을 충족할 때 성립한다."
