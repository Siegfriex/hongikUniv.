## 2. 데이터 기반 의사결정 4유형

| 유형 | 핵심 질문 | 대표 산출물 | 강의 사례 |
|------|-----------|-------------|-----------|
| **기술적 분석** | 무슨 일이 일어났는가? | 대시보드, KPI 요약 | 매출·방문자·수율 현황 |
| **진단적 분석** | 왜 일어났는가? | 원인분석, Root Cause | 공정 불량 원인 추적 |
| **예측적 분석** | 앞으로 무엇이 일어날까? | 예측값/확률 | 수요·이탈·수율 예측 |
| **처방적 분석** | 무엇을 해야 하는가? | 행동 권고, 최적화안 | 정비 시점·물류 전략 추천 |

### 2.1 유형 간 연결 규칙

- **기술 -> 진단:** 현상 집계만으로 끝내지 않고 원인 후보를 분해한다.
- **진단 -> 예측:** 원인 변수를 특징(feature)으로 구조화해 미래 결과를 예측한다.
- **예측 -> 처방:** 예측 결과를 정책/전략의 의사결정 규칙으로 변환한다.

### 아마존 예측 배송 사례 해석

- 구매 전 고객 수요를 예측해 물류창고에 선배치하는 전략은 **예측적 + 처방적 분석** 결합 사례다.
- 데이터(검색·장바구니·구매패턴) -> 예측모델 -> 선배치 의사결정으로 연결된다.
- 결과 지표는 배송시간, 고객만족도, 판매량, 재고회전율로 평가할 수 있다.

### 2.2 반도체 사례 해석

- 기술적 분석: 공정 KPI를 대시보드로 관측한다.
- 진단적 분석: 특정 공정/장비 요인과 불량률의 관계를 추적한다.
- 예측적 분석: 배치 수율을 사전 예측한다.
- 처방적 분석: 유지보수 시점/생산계획을 조정한다.

핵심은 **같은 데이터라도 질문 수준이 올라가면 가치와 복잡도가 함께 상승**한다는 점이다.

## 3. 텍스트 마이닝: 개념·프로세스·도전과제

### 3.1 핵심 정의

- 텍스트 마이닝은 비정형 텍스트에서 고품질 정보를 추출해 의사결정에 활용하는 과정이다.
- `Mining`은 알고리즘 중심, `Analytics`는 문제해결·활용 중심으로 설명할 수 있다.

### 3.2 대표 응용

- 요약·키워드 추출·시각화
- 문서 분류(스팸 필터링)
- 감성 분석(긍·부정·중립)
- 문서 군집화(레이블 없는 그룹 탐색)
- 자연어이해(QA)

### 3.3 도전과제

| 범주 | 예시 |
|------|------|
| 오탈자/표기 변형 | 산업데이터공학과 vs 산업대이터공학과 |
| 띄어쓰기/형태소 | 아버지가 방에 들어가신다 vs 아버지 가방에 들어가신다 |
| 다의어/동음이의어 | AI(인공지능) vs AI(조류인플루엔자) |
| 이음동의어 | 조립/Assembly/어셈블리 |
| 문맥의존성 | 부산에서 배를 탄다 vs 과일 배 |
| 신조어 | 좋댓구알, JMT |

### 3.4 텍스트 마이닝 프로세스 (강의 흐름 기준)

1. 문제 정의 및 필요 데이터 정의  
2. 데이터 수집 (API, 스크래핑 등)  
3. 전처리 (정규화, 토큰화, 불용어 제거 등)  
4. 모델링 및 평가

### 3.5 한국어 텍스트 처리에서의 실무 포인트

- 띄어쓰기/형태소 오류는 임베딩 품질을 직접 저하시킬 수 있다.
- 도메인 고유어(약어, 은어, 제품명)를 사전에 반영하지 않으면 분류 성능이 흔들린다.
- 전처리 개선은 종종 모델 교체보다 비용 대비 효과가 크다.

### 3.6 최소 성능 점검 지표

- 분류: 정확도(Accuracy), 정밀도(Precision), 재현율(Recall), F1
- 감성/불균형 문제: Macro-F1, 클래스별 재현율
- 군집: 실루엣 점수 + 정성적 토픽 해석 가능성

## 4. 추천시스템: 비즈니스 적용과 모델 선택

### 4.1 강의 포인트

- 추천은 업셀링·크로스셀링에 직접 연결되는 의사결정 기술이다.
- 넷플릭스 사례처럼 정확도를 올리는 것만으로는 부족하고, **속도·복잡도·설명력·운영 가능성**을 함께 봐야 한다.

### 4.2 협업필터링 직관

- 유사 사용자 이웃 집합 \(N(u)\), 유사도 \(\mathrm{sim}(u,v)\), 이웃 평점 \(r_{v,i}\)를 사용해 타겟 사용자 \(u\)의 아이템 \(i\) 선호를 추정한다.
- 단순 가중평균, 편차 기반 가중평균으로 확장 가능하다.

\[
\hat r_{u,i} = \frac{\sum_{v \in N(u)} \mathrm{sim}(u,v)\,r_{v,i}}{\sum_{v \in N(u)}|\mathrm{sim}(u,v)|}
\]

### 4.3 운영에서 반드시 보는 3가지

1. **정확도:** 추천 품질이 실제 클릭/시청/구매로 이어지는가
2. **지연시간:** 서비스 응답시간 SLA를 만족하는가
3. **설명가능성:** 왜 이 추천이 나왔는지 최소 수준의 해석이 가능한가

### 4.4 실패 패턴과 대응

- 콜드스타트(신규 사용자/아이템): 인기 기반 + 콘텐츠 기반 하이브리드
- 편향 강화(필터 버블): 탐색 추천 슬롯 분리, 다양성 제약
- 과최적화: 오프라인 점수 외 온라인 A/B 지표를 함께 최적화

## 5. 데이터 분석 및 시각화 설계 가이드

### 5.1 시각화 단계

`DATA -> SORTED -> ARRANGED(EDA) -> PRESENTED VISUALLY`

### 5.2 시각화 목적

1. 이해를 쉽게 만들기  
2. 추세·이상치 식별  
3. 데이터 스토리 전달  
4. 주장 강화  
5. 핵심 강조

### 5.3 좋은 시각화 원칙

- 목적·청중 우선
- 차트 타입 적합성
- 라벨 최소화·명확화
- 색상으로 포인트 강조
- 오해 유발 표현 회피
- 단순하고 일관된 디자인

### 5.4 유형별 권장 차트

| 분석 목적 | 권장 차트 |
|-----------|-----------|
| 시간 흐름 | 막대, 누적막대, 점그래프 |
| 분포 | 히스토그램, 트리맵(구성) |
| 관계 | 산점도, 버블차트 |
| 비교 | 히트맵, 레이더/스파이더 |
| 공간 | 지도 시각화 |

### 5.5 자주 발생하는 시각화 오류

- 축을 과도하게 잘라 효과를 과장하는 경우
- 범주 정렬 기준이 없어 메시지가 분산되는 경우
- 색상 의미가 일관되지 않아 해석이 뒤집히는 경우

### 5.6 발표용 한 장 구성 템플릿

`핵심 질문 -> 근거 데이터 -> 시각화 1개 -> 해석 2줄 -> 실행 권고 1줄`

## 6. 4강에서 5강으로의 연결

- 4강은 **전처리·EDA·상관 해석**까지였다.
- 5강은 이를 기반으로 **텍스트 데이터(비정형) 분석**, **모델링 유형 선택**, **시각화 커뮤니케이션**으로 확장한다.
- 연결식:

`전처리 품질 -> EDA 통찰 -> 분석문제 정의(회귀/분류/군집/이상치/추천) -> 모델링 -> 시각화/의사결정`

### 6.1 과목 흐름에서의 위치

- 4강이 "데이터를 믿을 수 있게 만드는 단계"였다면,
- 5강은 "믿을 수 있는 데이터를 행동으로 바꾸는 단계"다.

## 7. 실습 로드맵 (분석·시각화)

### 실습 A: 텍스트 마이닝 미니 파이프라인

- 입력: 뉴스/리뷰 텍스트
- 분석: 빈도 + TF-IDF 키워드 + 감성 분류
- 시각화: 상위 키워드 막대그래프, 감성 비율 도넛차트
- 제출물: 데이터 설명 5줄 + 전처리 규칙표 + 결과 차트 2개 + 해석 1단락

### 실습 B: 분석 질문별 모델 선택

- 회귀: `How much?`
- 분류: `Which category?`
- 군집: `Which group?`
- 이상치: `Is this weird?`
- 추천: `Which option should be taken?`
- 제출물: 각 질문에 대해 입력변수/목표변수/평가지표를 1행 표로 정리

### 실습 C: 시각화 리디자인

- 동일 데이터에 대해 나쁜 차트/좋은 차트 1쌍 제작
- 개선 포인트(축 범위, 색상, 라벨, 정렬)를 체크리스트로 검증
- 제출물: Before/After 비교 + 왜 더 나아졌는지 인지 관점 설명

## 8. 인텔리전스 브리핑

### 8.1 이번 5강의 전략적 의미

- 4강에서 확보한 전처리·EDA 역량을 5강에서 **의사결정 자동화(예측/추천)** 로 연결했다.
- 텍스트 마이닝은 비정형 데이터 활용의 핵심이며, 추천시스템·시각화는 **실행 가능한 액션**으로 전환하는 마지막 단계다.

### 8.2 웹 그라운딩 핵심 근거

| 주제 | 확인 내용 | 링크 |
|------|-----------|------|
| Amazon 예측 배송 | `anticipatory shipping` 특허(US20120072363A1) 기반의 사전 배송 개념이 공개적으로 확인됨 | [Google Patents](https://patents.google.com/patent/US20120072363A1/en) |
| Netflix Prize 운영 적용 | 대회 우승 알고리즘은 정확도 향상에도 불구하고 운영 복잡도/비즈니스 변화로 전면 적용되지 않았다는 공개 설명 존재 | [FlowingData 요약](https://flowingdata.com/2012/04/17/why-1m-netflix-algorithm-never-went-to-production/) |
| 한국어 텍스트 난제 | 교착어 특성, 띄어쓰기/형태소 분석 결합 필요성이 최근 연구에서 지속 확인됨 | [IEEE Xplore](https://ieeexplore.ieee.org/document/9070557), [ACL Anthology](https://aclanthology.org/2026.eacl-short.22/) |

### 8.3 강의 내용 기반 추론 (리포트 결론)

1. **정확도 단독 최적화는 실패 위험이 높다.**  
   추천·예측 모델은 정확도 외에 추론시간, 유지보수성, 설명가능성을 함께 최적화해야 실제 운영 가치가 생긴다.
2. **텍스트 전처리 품질이 상한선을 결정한다.**  
   특히 한국어는 형태소/띄어쓰기/신조어 처리가 성능을 좌우하므로, 모델 변경보다 전처리 파이프라인 안정화가 우선일 수 있다.
3. **시각화는 결과물이 아니라 의사결정 인터페이스다.**  
   동일 성능 모델이라도 시각화 설계(목적·청중·오해 방지)에 따라 현업 채택률이 크게 달라진다.

### 8.4 다음 주차 실행 체크리스트

- [ ] 분석 질문을 5유형(회귀/분류/군집/이상치/추천)으로 먼저 매핑
- [ ] 텍스트 데이터에 대해 도메인 사전 + 형태소/띄어쓰기 전처리 규칙 문서화
- [ ] 모델 평가지표를 `정확도 + 지연시간 + 해석성` 3축으로 설계

제목데이터 사이언스 주제에 따른 분석 기법
기계학습 방법론 분류
• 지도 학습 (Supervised Learning)
입력 값(x)과 그에 대한 정답(y, Label)이 함께 주어지는 데이터를 통해 학습하는 방식
새로운 데이터가 들어왔을 때 정답을 정확히 예측하는 것
- 회귀 (Regression):
• 출력값이 연속적인 숫자, 수치형일 때 사용
• 예시: 집값 예측, 내일의 기온 예측, 주식 가격 예측.
- 분류 (Classification):
• 출력값이 범주형(Discrete) 데이터일 때 사용, 데이터를 정해진 클래스 중 하나로 구분/분류
• 예시: 스팸 메일 여부(Yes/No), 손글씨 숫자 인식(0~9), 질병 유무 판독.

28
제목데이터 사이언스 주제에 따른 분석 기법
기계학습 방법론 분류
• 비지도 학습 (Unsupervised Learning)
비지도 학습은 정답(y) 없이 입력 데이터(x)만 있는 상태에서 데이터의 숨겨진 패턴이나 구조를 찾아내는 방식
- 군집화 (Clustering):
• 데이터 간의 유사성을 측정하여 비슷한 특성을 가진 데이터들끼리 그룹으로 묶는 기법
• 분류와 달리 그룹의 이름(Label) 정보가 없음
• 예시: 고객 행동 패턴에 따른 시장 세분화, 유사 뉴스 기사 묶기
- 이상치 탐지 (Anomaly Detection):
• 정상적인 데이터의 분포를 학습한 뒤, 이 분포에서 크게 벗어나는 '특이치'를 찾아내는 방법
• 예시: 신용카드 부정 결제 탐지, 제조 공정의 장비 고장 감지
