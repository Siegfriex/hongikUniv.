## 3. 자원배분(Resource-Allocation) 문제 — 모형화 절차 요약 9단계

**출처:** 교재·슬라이드의 *Summary of Formulation Procedure for Resource-Allocation Problems* (자원배분형 LP의 스프레드시트 구축 절차).  
**3강 강의록 참고:** `20250316.md` — Wyndor Glass Co. 제품믹스 · DEVELOPING A SPREADSHEET MODEL Step #1~#4 · SUMPRODUCT · 시행해.

아래는 각 단계를 **한국어로 풀어쓴 뒤**, 동일 세션에서 다룬 **Wyndor** 예시에 **씌워서** 대응시킨 것이다.

### 3.1 절차별 한국어 풀이

| 단계 | 영문 요지 | 한국어 풀이 |
|------|-----------|-------------|
| **1** | Identify the activities | 문제에서 **활동(activity)** 이란 “수준을 정할 대상”이다. 보통 **제품·서비스·프로젝트** 등 **결정변수 하나가 대응하는 단위**가 된다. |
| **2** | Identify an appropriate overall measure of performance | **전체 성과를 숫자 하나로** 나타낸다. 자원배분형에서는 흔히 **이익(profit)** 을 **최대화**한다. (비용 최소는 별 문제 유형에서 다룸.) |
| **3** | For each activity, estimate the contribution per unit | 활동 **1단위**가 성과에 기여하는 양(**단위당 계수**)을 추정한다. LP에서는 이것이 목적함수의 **\(c_j\)** 가 된다. |
| **4** | Identify the resources that must be allocated | **한정된 자원**이 무엇인지 목록화한다. (시간, 원료, 기계시간, 예산 등.) |
| **5** | For each resource, available amount and used per unit of each activity | 자원마다 **가용량(RHS)** 과, 활동 **단위당 소비량(기술계수 \(a_{ij}\))** 을 적는다. |
| **6** | Enter the data in steps 3 and 5 into data cells | 3·5단계 숫자를 스프레드시트 **데이터 셀**에 넣는다. (단위이익 행, 계수 행렬, 가용량 열.) |
| **7** | Designate changing cells for the decisions | **결정변수**(각 활동의 수준)를 넣을 **변경 셀**을 지정한다. Solver의 *By Changing Variable Cells*에 연결된다. |
| **8** | Each resource row: SUMPRODUCT for total used; `<=` and available in adjacent cells | 자원 **행마다** “총 사용량 = \(\sum_j a_{ij} x_j\)”를 **SUMPRODUCT(해당 행 계수, 변경 셀)** 로 두고, 옆에 **`<=`**, **가용량** 셀을 두어 **Resource constraint (LHS ≤ RHS)** 형태로 읽히게 한다. |
| **9** | Designate an objective cell; SUMPRODUCT for performance | **목적 셀** 하나에 “총 성과 = \(\sum_j c_j x_j\)”를 **SUMPRODUCT(단위 기여, 변경 셀)** 로 넣고, Solver에서 Max(또는 Min)한다. |

**한 줄 요약:** 1~5는 **세상을 수학으로 읽기**(활동·목표·계수·자원·한도), 6~9는 **엑셀에 옮기기**(데이터 / 변수 / 제약 LHS / 목적).

### 3.2 Wyndor Glass Co. 제품믹스에 대입 (3강 구체 예시)

3강 슬라이드·강의록의 **WYNDOR GLASS CO. PRODUCT MIX** 와 스프레드시트 배치(`20250316.md` Step #1~#4, 수식 표)를 그대로 맞춘다.

| 단계 | Wyndor에서의 대응 |
|------|-------------------|
| **1 활동** | 신제품 두 가지 생산 **활동**: **Doors(문)** , **Windows(창문)**. 결정변수는 주당 생산률 \(D, W\). |
| **2 성과 지표** | **주당 총이익(Total profit)** — \(\max\) 대상. |
| **3 단위당 기여** | 문 1단위 **\$300**, 창문 1단위 **\$500** → 데이터 셀 **C4:D4** (단위이익). 목적함수 \(P = 300D + 500W\). |
| **4 자원** | 세 공장의 **주당 가용 생산시간**: Plant 1, 2, 3 (각각 알루미늄·목재·유리/조립 공정). |
| **5 가용량·단위당 사용** | **가용량:** Plant1 4시간, Plant2 12시간, Plant3 18시간 (**G7:G9**). **단위당 사용(표):** Plant1 — 문 1, 창 0 / Plant2 — 문 0, 창 2 / Plant3 — 문 3, 창 2 (**C7:D9** 행렬). |
| **6 데이터 셀** | 단위이익 **C4:D4**, 기술계수 **C7:D9**, 가용시간 **G7:G9** 에 입력. |
| **7 변경 셀** | **C12** = \(D\), **D12** = \(W\) (생산량). 초기값 0 또는 시행해(예: 4, 3). |
| **8 자원 행 SUMPRODUCT·≤** | **E7** `=SUMPRODUCT(C7:D7,C12:D12)` → Plant1 사용시간; **E8**, **E9** 동일 패턴. **E7:E9 ≤ G7:G9** (표시는 E, F에 `<=`, G에 가용량). |
| **9 목적 셀** | **G12** `=SUMPRODUCT(C4:D4,C12:D12)` = \(300D+500W\). Solver **Set Objective** → **Max**. |

**시행해와의 연결 (3강):** \(D=4, W=3\) 이면 **E7=4, E8=6, E9=18**, **G12=2,700**; Plant2만 **slack**(6≤12). 최적해는 그래프·심플렉스와 같이 **\((D^\*,W^\*)=(2,6)\), \(P^\*=3,600\)** (3강 메모).

## 4. 예제 1–2: Super Grain Corp. (한 케이스의 두 단계)

같은 **광고 믹스** 문제를 **(A) 자원 제약만 있는 LP** 로 세우고, **(B) 편익·쿠폰 등식** 을 더해 **Mixed** 로 확장한다. 슬라이드에서 예제 번호가 1·2로 나뉘어 있어도 **하나의 스토리**로 묶어 보면 된다.

### 4.A 예제 1 (해당): Advertising-Mix — LP 기본 (엑셀·템플릿 즉시 적용)

**목표:** 크런치 스타트(Crunchy Start) 홍보 — **기대 노출 수(exposures) 최대화** (Max problem).  
**활동(결정변수) 3개:** TV 광고 횟수, 잡지 광고 횟수, 일요판 부록(SS) 광고 횟수.  
**제한 자원:** 광고비 예산 **\$4M**, 기획비 예산 **\$1M**, TV 스팟 **최대 5회**.

#### 4.A.1 단위 정리 (슬라이드·스프레드시트와 맞추기)

| 항목 | 스프레드시트에서의 단위 | 비고 |
|------|-------------------------|------|
| 노출 | **천 명(thousands)** | 행 4 계수 1,300 = 주어진 표의 1,300,000명과 동일 스케일 |
| 비용(광고·기획) | **천 달러(\$ thousands)** | 예산 4,000 = \$4,000,000 |
| 결정변수 | 광고 **횟수**(정수로 두어도 되고 LP는 연속 완화) | — |

#### 4.A.2 대수 모형 (Algebraic Formulation)

\(TV, M, SS\) = 각 매체별 광고 횟수.

\[
\max\; Z = 1300\,TV + 600\,M + 500\,SS \quad (\text{총 노출, 천 명 단위})
\]

\[
\text{s.t.}\quad
\begin{cases}
300\,TV + 150\,M + 100\,SS \le 4000 & \text{(Ad Spending, \$ thousands)} \\
90\,TV + 30\,M + 40\,SS \le 1000 & \text{(Planning cost, \$ thousands)} \\
TV \le 5 & \text{(TV 스팟 상한)} \\
TV,\, M,\, SS \ge 0
\end{cases}
\]

#### 4.A.3 스프레드시트 배치 (슬라이드 *Spreadsheet Formulation* 와 동일 구조)

열 **C–E** = TV / Magazine / SS. **노란색** = 변경 셀, **주황** = 목적 셀.

| 행 | A | B | C | D | E | F | G | H |
|----|----|----|----|----|----|----|----|----|
| 1 | *(제목)* | | Super Grain Corp. Advertising-Mix Problem | | | | | |
| 3 | | | TV Spots | Magazine Ads | SS Ads | | | |
| 4 | | Exposures per Ad (thousands) | 1300 | 600 | 500 | | | |
| 6 | | | | | | Budget | | |
| 7 | | | | | | | | |
| 8 | | Ad budget — cost/Ad (\$k) | 300 | 150 | 100 | **=SUMPRODUCT($C$8:$E$8,$C$13:$E$13)** | <= | 4000 |
| 9 | | Planning — cost/Ad (\$k) | 90 | 30 | 40 | **=SUMPRODUCT($C$9:$E$9,$C$13:$E$13)** | <= | 1000 |
| 11 | | | | | | Total Exposures (thousands) | | |
| 12 | | | TV Spots | Magazine Ads | SS Ads | | | |
| 13 | | Number of Ads | **0** | **20** | **10** | | | **=SUMPRODUCT($C$4:$E$4,$C$13:$E$13)** |
| 14 | | *(TV 한도 표시)* | <= | | | | | |
| 15 | | Max TV Spots | **5** | | | | | |

- **계수 블록:** `C8:E8` = 광고비 행(300,150,100), `C9:E9` = 기획비 행(90,30,40). `SUMPRODUCT` 는 **계수 행과 변경 셀 행이 같은 열**이면 `C8:E8`·`C13:E13` 로 묶어도 됨.  
- **변경 셀:** `C13:E13` (광고 횟수). 시행해는 슬라이드와 같이 (0, 20, 10) → **총 노출 H13 = 17,000** (천 명).  
- **자원 제약 LHS:** `F8`, `F9` — 행별 `SUMPRODUCT(해당 행 비용계수, C13:E13)`.  
- **TV 상한:** 슬라이드는 **C14에 `<=`**, **C15에 5** — **`C13 <= C15`** 로 Solver 등록. (템플릿 통일을 원하면 행 하나를 더 두고 **`C10=1, D10=0, E10=0`**, **`F10=SUMPRODUCT($C$10:$E$10,$C$13:$E$13)`**, **`F10 <= 5`** 로 세 자원 행과 동일 패턴으로 쓸 수 있음.)

**수식 한 줄 요약**

- `F8` `=SUMPRODUCT($C$8:$E$8,$C$13:$E$13)`  
- `F9` `=SUMPRODUCT($C$9:$E$9,$C$13:$E$13)`  
- `H13` `=SUMPRODUCT($C$4:$E$4,$C$13:$E$13)`  *(슬라이드에선 주황 **Total Exposures** 셀 — 행 11–12 라벨만 다를 수 있음)*  

*(목적 셀 위치만 슬라이드와 맞추면 되고, 원칙은 **SUMPRODUCT(단위 노출 행, 변경 셀)** 하나.)*

#### 4.A.4 Solver 설정 (복사용 체크리스트)

- **Set Objective:** 목적 셀 (위에서는 `H13` 또는 동일 수식 셀) → **Max**  
- **By Changing Variable Cells:** `C13:E13`  
- **Subject to:**  
  - `F8 <= H8` (또는 `F8 <= 4000`)  
  - `F9 <= H9` (또는 `F9 <= 1000`)  
  - `C13 <= 5` (또는 `C13 <= C15`)  
- **Make Unconstrained Variables Non-Negative:** 체크  
- **Solving Method:** Simplex LP (선형)

#### 4.A.5 *Template for Mixed Problems* 와의 대응

슬라이드 **Mixed Problems** 템플릿에서 이 예제가 쓰는 블록은 다음과 같다.

| 템플릿 영역 | Super Grain에서의 내용 |
|-------------|-------------------------|
| **Unit profit or cost (상단)** | 행 4 — **Exposures per Ad** (목적 계수 \(c_j\)) |
| **resource used per unit** | 행 8–9 — 매체별 **광고비·기획비** 소비; TV 한도는 **(1,0,0)** 행을 추가해 `SUMPRODUCT` 한 줄로 넣거나 **`TV ≤ 5`** 로 별도 제약 |
| **Resources Used · SUMPRODUCT** | `F8`, `F9` (+ 필요 시 TV용 LHS 셀) |
| **`<=` · Resources Available** | `G8:H9` 및 TV 한도 |
| **changing cells** | `C13:E13` |
| **Total Profit or Cost (주황)** | `H13` — `SUMPRODUCT(행4, C13:E13)` |

이 문제는 **Benefit (≥)** 이나 **Fixed (=)** 행이 없고, 전부 **Resource (≤)** 형이므로 템플릿의 **윗부분(자원 행)** 만 채우면 된다. **≥**·**=** 가 붙은 확장은 **§4.B** 에서 다룬다 (Benefit / Fixed-requirement 행 + Solver에서 **`=`** 제약).

### 4.B 예제 2 (해당): Super Grain 확장 — **제약이 한 번 더** (Mixed LP)

**상황:** §4.A 스프레드시트 모형에 **추가 고려**를 넣어 확장한다 (강의 p.4–6 이어서).  
**핵심:** §4.A의 **Resource (≤)**·목적·변수는 유지하고, **편익(Benefit, ≥)** 과 **고정요구(Fixed-requirement, =)** 제약만 얹는다. **제약조건이 한 번 더 등장**하는 전형이다.

#### 4.B.1 §4.A → §4.B: 무엇이 **새로 붙는가**

| 구분 | §4.A | §4.B에서 **추가** |
|------|--------|---------------------|
| 목적 | 노출 Max (동일) | 동일 |
| 결정변수 | \(TV, M, SS\) | 동일 |
| 자원 제약 | 광고비·기획비·TV 스팟 상한 | **동일** (계수·한도는 §4.A와 같은 표 사용) |
| **편익 제약** | 없음 | **어린이** ≥ 500만 명, **부모** ≥ 500만 명 (표는 **백만 명** 단위로 계수·RHS) |
| **등식 제약** | 없음 | **쿠폰 할액**이 **정확히** \$1,490,000 (스프레드시트에선 **천 달러** 단위로 **1,490**) |

즉 **풀이의 방점**은 “새 목적을 세운다”가 아니라, **기존 LP에 행(제약)을 더하고 부등호/등호를 구분해 스프레드시트·Solver에 넣는 것**이다.

#### 4.B.2 추가 데이터 (슬라이드 *Benefit and Fixed-Requirement Data*)

**A. Benefit — 타깃 도달 (백만 명 단위, LHS ≥ RHS)**

| 타깃 | TV 1회 | 잡지 1회 | SS 1회 | 최소 달성(Minimum acceptable) |
|------|--------|----------|--------|--------------------------------|
| Young children | 1.2 | 0.1 | 0 | **5** |
| Parents of young children | 0.5 | 0.2 | 0.2 | **5** |

**B. Fixed-requirement — 쿠폰 (천 달러 단위로 표기하면 RHS = 1,490)**

| | TV | 잡지 | SS | Required |
|--|-----|------|-----|----------|
| Coupon redemption | 0 | **40** | **120** | **1,490** |

의미: 잡지·SS 광고 1회가 쿠폰 예산에 기여하는 금액이 각각 \$40,000, \$120,000이고, **그 합이 정확히 \$1,490,000** 이어야 한다 → **등식** \(40M + 120SS = 1490\) (\$ thousands).

#### 4.B.3 대수 모형 (§4.A + 추가 제약)

§4.A와 동일한 기호·단위(노출·비용은 **천** 단위, 타깃 도달은 **백만** 명)를 쓴다.

\[
\max\; Z = 1300\,TV + 600\,M + 500\,SS
\]

**Resource available (§4.A와 동일)**

\[
\begin{aligned}
300\,TV + 150\,M + 100\,SS &\le 4000 && \text{(Ad Spending, \$k)} \\
90\,TV + 30\,M + 40\,SS &\le 1000 && \text{(Planning, \$k) — §4.A 표와 동일; 슬라이드에 30SS로 보이면 교수·교재 기준 확인} \\
TV &\le 5
\end{aligned}
\]

**Benefit needed (≥)**

\[
\begin{aligned}
1.2\,TV + 0.1\,M &\ge 5 && \text{(Young children, millions)} \\
0.5\,TV + 0.2\,M + 0.2\,SS &\ge 5 && \text{(Parents, millions)}
\end{aligned}
\]

**Coupons — Fixed-requirement (=)** ← **§4.B의 결정적 차이**

\[
40\,M + 120\,SS = 1490 \quad (\$ \text{ thousands})
\]

\[
TV,\,M,\,SS \ge 0
\]

#### 4.B.4 **등호(=) 제약**이 \(\le\)·\(\ge\) 와 다른 점 — “확실히 잡는” 방법

| 항목 | \(\le\) / \(\ge\) | **\(=\) (이퀄 제약)** |
|------|---------------------|------------------------|
| 의미 | “이하/이상만 맞추면 됨” (여유·슬랙 가능) | **LHS와 RHS가 정확히 같아야 함** (초과·미달 불가) |
| 스프레드시트 | LHS 셀 `SUMPRODUCT` 한 개, 기호 열에 `<=` 또는 `>=`, RHS 셀 | **같은 방식으로 LHS·RHS 셀을 두되**, Solver 관계만 **`=`** 로 지정 |
| Solver | `F7 <= H7` 형태로 추가 | **`F15 = H15`** 처럼 **Equal** 관계로 **별도 한 줄** 추가 (≤ 행에 끼워 넣지 말 것) |
| 흔한 실수 | — | `<=` 와 `>=` 를 동시에 넣어 “사실상 등식”으로 착각 (불필요·오류 가능) / **목적함수에 페널티**로만 맞추려 함 (LP 표준 풀이 아님) |

**엑셀 Solver에서 등식을 확실히 거는 절차**

1. **LHS 셀** 하나에만 수식: 예) `F15 = SUMPRODUCT($C$15:$E$15,$C$19:$E$19)` (계수 0, 40, 120).  
2. **RHS**는 상수 데이터 셀: 예) `H15 = 1490`.  
3. **Solver → Subject to the Constraints → Add**  
   - **Cell Reference:** `F15`  
   - **드롭다운:** **`=`** (Equal)  
   - **Constraint:** `H15` 또는 `1490`  
4. **Simplex LP** 사용 시 등식 제약은 **지원**된다. (문제가 불가능·퇴화하면 Solver가 **infeasible** 을 줄 수 있음 — 등식이 다른 제약과 모순되지 않았는지 확인.)

**한 줄 요약:** 등호는 **“F15가 H15와 같다”** 를 **한 줄의 제약**으로 넣는다. `SUMPRODUCT` 결과가 **정확히** RHS와 같아지도록 Solver가 \(TV,M,SS\) 를 조정한다.

#### 4.B.5 스프레드시트 배치 (슬라이드 *Spreadsheet Formulation* · Mixed 템플릿)

§4.A와 달리 **변경 셀 행이 아래로 내려간** 캡처(행 19) 기준으로 정리한다. (행 번호는 캡처에 맞추고, 원리는 동일.)

| 블록 | 위치(예시) | 내용 |
|------|------------|------|
| 목적 계수 | 행 4 (C4:E4) | 1300, 600, 500 |
| Resource 계수 | 행 7–8 등 | 광고비·기획비 (§4.A와 동일) |
| **Benefit 계수** | 행 11–12 (C:E) | 1.2,0.1,0 / 0.5,0.2,0.2 |
| **Coupon 계수** | 행 15 (C:E) | **0, 40, 120** |
| LHS | F열 | 각 행 `SUMPRODUCT(해당 행 계수, $C$19:$E$19)` |
| 기호 | G열 | `<=` (자원), `>=` (편익), **`=`** (쿠폰) |
| RHS | H열 | 가용량 / 최소 달성 / **1,490** |
| 변경 셀 | **C19:E19** | TV, M, SS |
| 목적 | **H19** 등 | `=SUMPRODUCT(C4:E4,C19:E19)` → Max |

**시행해 (슬라이드 값):** \(TV=3,\; M=14,\; SS=7.75\) → 총 노출 **16,175** (천 명); 기획비 \(90(3)+30(14)+40(7.75)=1000\); 쿠폰 \(40(14)+120(7.75)=560+930=1490\) → **등식 만족**.

#### 4.B.6 Mixed Problems 템플릿으로 보면

- **윗부분 (Resource):** `<=` — §4.A와 동일.  
- **가운데 (Benefit):** “benefit achieved per unit” 행 + `SUMPRODUCT` + **`>=`** + “Benefit Needed”.  
- **아래 (Fixed):** “contribution per unit” 행 + `SUMPRODUCT` + **`=`** + “Required Amount” — **쿠폰 행이 여기**.

§4.A에서 “나중에 ≥, = 채운다”고 했던 칸이 **§4.B에서 실제로 채워진 상태**라고 보면 된다.

## 5. 예제 2: TBA Airlines — **정수계획법(IP)** · 가분성 가정 위배

**스토리:** 지역 항공사 TBA가 **소형기·대형기** 구매로 확장하려 한다. **순연간 이익**을 최대화하되, **자본 한도**와 **소형기 구매 상한**이 있다.  
**문제의 특성:** 비행기 대수는 **0, 1, 2, …** 만 의미 있고 **1.5대** 같은 **분수**는 불가능하다 → 선형계획의 **가분성 가정(Divisibility Assumption)** 이 깨진다.

### 5.1 LP 가정과의 충돌 (Violates Divisibility)

- **Divisibility (LP):** 결정변수는 제약을 만족하는 한 **연속값**(분수 포함)을 가질 수 있다고 본다.  
- **이 문제:** \(S, L\) = 구매 **대수** → **정수**여야 현실과 맞다.  
- 따라서 **연속 LP만** 풀면 “최적해가 2.3대”처럼 나올 수 있어, **정수 제약을 명시한 모형**이 필요하다.

### 5.2 정수계획 모형 (Integer Programming Formulation)

\(S\) = 소형기 구매 대수, \(L\) = 대형기 구매 대수. (단위: 이익·자본은 **백만 달러**)

\[
\max\; Z = 7S + 22L
\]

\[
\text{s.t.}\quad
\begin{cases}
25S + 75L \le 250 & \text{(Capital Available)} \\
S \le 5 & \text{(Max small airplanes)} \\
S,\, L \ge 0 \\
S,\, L \in \mathbb{Z}
\end{cases}
\]

마지막 줄이 **정수 조건**이다. 시험·슬라이드에서는 **“S, L are integers”** 로 따로 쓰기도 한다.

### 5.3 스프레드시트 모형 (슬라이드·첨부 이미지와 동일 템플릿)

**색 구분:** 파란 = **데이터(상수)**, 노란 = **변경 셀**, 주황 = **목적 셀**, 빨간 박스 = **자원 제약 LHS ≤ RHS**.

| 행·열 | 내용 |
|--------|------|
| **C4:D4** | Unit Profit (\$ millions): **7**, **22** |
| **C8:D8** | Capital per unit purchased (\$ millions): **25**, **75** |
| **C12:D12** | **Number Purchased** (변경 셀, 노란) — 시행해 **1**, **3** |
| **E8** | `=SUMPRODUCT($C$8:$D$8,$C$12:$D$12)` → **Capital Spent** (시행해 \(25·1+75·3=250\)) |
| **F8:G8** | `<=` , **250** (Capital Available, 파란) |
| **C13:C14** | `<=` , **5** (Max Small — **C12 ≤ C14**) |
| **G12** (또는 동일 열 목적 셀) | `=SUMPRODUCT($C$4:$D$4,$C$12:$D$12)` → **Total Profit** (주황, 시행해 \(7+66=73\)) |

**대수식과의 대응:** \(E8\) 이 \(25S+75L\), **G12** 가 \(7S+22L\), **C12≤5** 가 소형기 상한.

### 5.4 분지한계법(branch-and-bound) — 강의에서의 위치

- **연속 완화(LP relaxation):** 정수 조건을 잠시 빼고 풀면 **선형계획**으로 빠르게 상·하한을 얻을 수 있다.  
- **정수 최적해:** 일반적으로 **분지한계법**(가능하면 **단순x·컷** 등)으로 **정수해**를 탐색한다. 엑셀 Solver는 정수·이진 제약을 넣으면 **내부적으로** 이런 탐색(분지한계 계열)을 수행한다.  
- 수업에서는 **알고리즘 세부**가 이어질 수 있으므로, 여기서는 **“IP = LP + 정수 조건, 풀이는 분지한계법으로 연장”** 정도만 잡아 두면 된다.

### 5.5 엑셀 Solver — **정수해** 확실히 거는 방법

1. **Set Objective:** `G12`(총이익) → **Max**  
2. **By Changing Variable Cells:** `C12:D12`  
3. **제약 (LP와 동일):**  
   - `E8 <= G8` (또는 `E8 <= 250`)  
   - `C12 <= C14` (또는 `C12 <= 5`)  
4. **정수:** **Add** → Cell Reference `C12`, 중간 드롭다운 **`int`** (정수) → OK. `D12` 도 동일하게 **`int`**.  
   - *(한 줄로:* `C12: D12` = **integer** 로 잡을 수 있으면 한 번에 지정.)  
5. **Non-Negative:** 체크 유지.  
6. **Solving Method:** 정수 제약이 있으면 Solver는 **단순형 단독(Simplex LP)** 만으로 끝나지 않을 수 있다. 버전에 따라 **“LP/비선형 혼합”** 또는 **Evolutionary** 안내가 나올 수 있음 — **선형 목적·선형 제약 + 정수** 이면 **Simplex 기반 + 분지한계**(내부) 조합으로 이해하면 된다. *(실습: 제약 추가 후 **Solve** 하면 \(S,L\) 가 **정수**로 나오는지 확인.)*  
7. **옵션(§5.6):** **정수 제약 무시** 끄기, **정수 최적성(%)** 의미 — 제출용이면 특히 읽을 것.

**시험/과제에서 “정수해를 찾아라”** 로 나오면: **모형에 \(S,L\in\mathbb{Z}\)** 를 쓰고, 스프레드시트에서는 **변경 셀에 `int`** + 위 자본·대수 제약을 그대로 두면 된다.

### 5.6 Solver 옵션 — **정수 제약 무시** vs **정수 최적해**, 그리고 **정수 최적성(%)** 이 무엇인가

엑셀 **데이터 → Solver → 옵션(Options)** 안에 **정수 제약(Integer Constraints)** 과 **정수 최적성(Integer Optimality)** 관련 설정이 있다. (버전·언어에 따라 **“정수 최적화 비율”** 등으로 번역되기도 한다.)

#### (1) “해 찾기”에서 **정수 제약 조건 무시** 체크의 의미

| 설정 | 효과 |
|------|------|
| **무시(체크)** | 정수·이진 제약을 **잠시 빼고** **연속 LP(완화 문제)** 만 푼다. **분수 해**(예: 2.3대)가 나올 수 있다. |
| **포함(체크 해제, 기본)** | `int` / `bin` 제약을 **실제로 적용**해 **정수(또는 0-1)해**를 찾는다. |

**용도:** 완화 문제만 풀면 **상한(Max 문제에서 이론적 최댓값의 천장)** 을 빠르게 보거나, 모형이 이상 없는지 **디버깅**할 때 무시를 켠다. **과제·보고서 제출용 정수 최적해**는 **무시 끄기**로 둔다.

#### (2) **정수 최적성(%)** = 무엇인가 (Integer optimality tolerance)

**한 줄 정의:** 분지한계법이 돌면서 **“아직 더 나은 정수해가 있을지”** 를 판단할 때 쓰는 **조기 종료(early stop) 허용 폭**이다. **목적함수 값** 기준으로, **현재까지 찾은 최선의 정수해**와 **알고리즘이 아직 “가능하다”고 보는 상한(또는 하한)** 사이의 **상대 갭(gap)** 이 이 비율 **이하**로 좁혀지면 “충분히 좋다”고 보고 **멈출 수 있다**.

- **최대화** 예: \(Z^{\mathrm{IP}}\) = 지금까지 찾은 최선 **정수** 목적값, \(Z^{\mathrm{bound}}\) = 분지한계로부터 나온 **상한**(더 이상 넘을 수 없다고 증명된 천장).  
  **갭** \(\displaystyle = \frac{Z^{\mathrm{bound}} - Z^{\mathrm{IP}}}{\max(|Z^{\mathrm{bound}}|,\varepsilon)}\) (또는 Solver 구현에 근사한 식)이 **정수 최적성 %** 이하이면 종료 후보.

즉 **“정수 최적화 비율”** 이라고 부를 때의 **비율**은 **목적함수 척도에서의 허용 오차(상대 갭)** 에 가깝고, “몇 프로까지 차이 나도 된다”는 **시간 절약용** 옵션이다.

#### (3) 왜 **0~5%** 같은 구간이 붙어 있나

- **0%에 가깝게:** 갭을 거의 **0**까지 줄여야 멈춤 → **진짜 최적해에 가깝게** 찾으려 함. 시간은 더 걸릴 수 있음.  
- **몇 %(예: 5%)까지:** “상한과 현재 최선 정수해의 차이가 **전체 스케일 대비 5% 이내**면 더 파지 않아도 된다”고 보는 것. **대규모 정수 문제**에서 탐색을 끊어 **실무적으로 쓸 만한 해**를 빨리 얻기 위함.  
- 엑셀 Solver UI에서는 이 값을 **너무 크게** 두면 엉성한 해에서 멈출 수 있어, **기본·권장 범위를 0~5% 근처로 제한**하는 식으로 두는 경우가 많다(버전마다 상한·기본값은 다름). **“왜 하필 5%냐”** 는 **절대 불변의 수학 상수**라기보다, **속도와 질의 절충**을 위해 소프트웨어가 둔 **실용적 상한·기본값**에 가깝다.

**시험·소규모 예제(TBA 같은 2변수 문제)** 에서는 **0%** 에 두고 풀어도 순식간에 끝나는 경우가 많다. **“정확히 전역 최적 정수해”** 를 요구하면 **0(또는 최소)** 쪽이 안전하다.

#### (4) 그림으로 보는 **단계적** 직관 (1차원으로 압축)

**최대화**이고, 가능한 **정수 목적값**만 떠 있다고 생각하자.

```
     상한 Z^bound ───────────────►  (알고리즘이 증명한 천장)
                    ◄── 갭 ──►
     현재 최선 정수 Z^IP ───────►
```

1. 처음에는 정수해를 하나 찾으면 그게 **현재 최선** \(Z^{\mathrm{IP}}\).  
2. 분지를 더 하면 **상한** \(Z^{\mathrm{bound}}\) 이 아래로 **내려오거나**(더 타이트해짐), 더 좋은 정수해가 나와 \(Z^{\mathrm{IP}}\) 가 **올라간다**.  
3. **갭** = 둘 사이의 **남은 개선 여지**. 이 갭이 목적 스케일 대비 **정수 최적성 % 이하**이면 “더 파는 데 쓸 시간 대비 이득이 작다”고 보고 **멈춤**.

**2차원 가능영역**에서는 “연속 최적점”이 분수일 수 있고, **격자(정수점)** 만 허용된다. 분지한계는 영역을 잘라 가며 **어느 조각에도 \(Z^{\mathrm{bound}}\) 이하로는 목적을 못 올린다**고 증명되면 그 가지를 버린다. **정수 최적성 %** 는 그 과정에서 **“이미 찾은 격자점이 상한에 충분히 가깝다”** 면 탐색을 줄이는 **실용적 스톱 규칙**이다.

#### (5) 정리 — 설정 시 체크리스트

| 목적 | 정수 제약 무시 | 정수 최적성(%) |
|------|----------------|------------------|
| 제출용 **정수 최적해** | **끄기** | **0** 또는 작게 (작은 문제) |
| 완화만 빠르게 / 상한 확인 | **켜기** | 해당 없음 |
| 큰 문제·시간 부족 | **끄기** | 교재·지시 % (과제에서 지정 시 따름) |

## 6. 예제 3: Think-Big Development — **자본예산(Capital Budgeting)** · 누적 제약

**주안:** “1년 안에 들어갈 돈·2·3년에 들어갈 돈”이 **각각 따로 한도**가 아니라, 문제가 말하는 **자원 1~4** 는 **시점까지의 누적 가용자금**과 **프로젝트당 누적 소요자금**을 맞추는 구조다. 여기를 읽지 않으면 제약식을 **연도별**로 잘못 세우기 쉽다.

### 6.1 문제 읽기 — 결정변수 \(OB,\,H,\,SC\) 가 의미하는 것

- Think-Big는 세 건설 프로젝트(오피스·호텔·쇼핑센터)에 **파트너로 참여**하며, 각 프로젝트에 대해 **참여 지분(participation share)** 을 정한다.  
- **\(OB\)** = 오피스 프로젝트 전체에 대한 참여 비율, **\(H\)** = 호텔, **\(SC\)** = 쇼핑센터.  
- 질문 *“각 프로젝트에 얼마나 참여할까?”* → 수학적으로는 **연속 변수**(몇 %까지 참여할지). **가분성**을 쓰는 전형(1.5% 단위까지 허용 등). (전부 0 또는 1만 허용하면 **IP**로 바뀜.)

### 6.2 현금흐름·NPV·이자 — 이 모형에서 함정 없이 쓰는 범위

| 슬라이드 가정 | 모형에서의 처리 |
|----------------|-----------------|
| **이자 수입은 제외** | 제약식의 “투입 현금”은 **명목 누적액**으로만 맞춤. |
| **남은 투자자금은 다음 해로 이월** | 그래서 **“지금까지 쓸 수 있는 총액”** 을 **누적 상한**으로 두는 것과 일치 → 제약을 **연도별 독립 한도**가 아니라 **누적 한도**로 쓴다. |
| **NPV는 프로젝트당 주어짐** | 목적함수 계수 **45, 70, 50** (\$M)은 이미 **할인·환산된 순현재가치**(프로젝트 **전체** 기준). **“얼마를 조달해야 하냐”** 는 제약의 LHS로, **“그 참여로 얻는 가치가 얼마냐”** 는 목적의 **NPV×지분**으로 **한 번씩** 들어간다. 제약에 **이자율을 또 곱하지 않는다**(문제에서 이자 제외·이월만 문장으로 고정). |

즉 **“현재가치에 이자율을 어떻게 넣나?”** → **제약의 현금**은 명목 누적, **가치 평가**는 **주어진 NPV 계수**에 맡긴다는 뜻이다.

### 6.3 자원 1~4 — **누적 가용자금** (함정 방지)

**연도별 새로 들어오는 돈:** 지금 25, 1년 뒤 +20, 2년 뒤 +20, 3년 뒤 +15 (\$M).

| 자원 | 의미 | 누적 가용 (\$M) |
|------|------|----------------|
| 1 | Now | **25** |
| 2 | End of year 1까지 쓸 수 있는 **총액** | \(25+20=\) **45** |
| 3 | End of year 2까지 | \(25+20+20=\) **65** |
| 4 | End of year 3까지 | \(25+20+20+15=\) **80** |

**함정:** “2번 자원 = 20”처럼 **해당 연도에 새로 생기는 돈만** 쓰면 안 되고, **이월을 반영한 누적 한도**가 45, 65, 80이다.

### 6.4 프로젝트 쪽 계수 — **누적 투자 소요** (프로젝트 전체 기준)

각 프로젝트 **전체**에 파트너들이 **시점까지** 부담해야 할 투자의 **누적**이 표와 같다 (연도별 40+60+… 를 더한 값).

| 자원 | Office | Hotel | Shopping | (검산 예: Office) |
|------|--------|-------|----------|---------------------|
| 1 (Now) | 40 | 80 | 90 | 연도0만 |
| 2 (≤1년) | 100 | 160 | 140 | 40+60 |
| 3 (≤2년) | 190 | 240 | 160 | 40+60+90 |
| 4 (≤3년) | 200 | 310 | 220 | 전 연도 합 |

### 6.5 대수 모형 (Algebraic Formulation)

\[
\max\; NPV = 45\,OB + 70\,H + 50\,SC \quad (\$ \text{ millions})
\]

\[
\text{s.t.}\quad
\begin{cases}
40\,OB + 80\,H + 90\,SC \le 25 \\
100\,OB + 160\,H + 140\,SC \le 45 \\
190\,OB + 240\,H + 160\,SC \le 65 \\
200\,OB + 310\,H + 220\,SC \le 80 \\
OB,\, H,\, SC \ge 0
\end{cases}
\]

- 해석: 왼쪽은 “내가 맡은 지분만큼 **그 시점까지** 내가 부담하는 누적 투자”, 오른쪽은 “그 시점까지 쓸 수 있는 누적 한도”.  
- **\(OB,H,SC \le 1\)** 은 “프로젝트 100%를 넘을 수 없다”를 묶어 쓸 때 **추가**할 수 있다. 슬라이드·교재에 명시되면 제약으로 넣는다.

### 6.6 스프레드시트 (첨부 *Spreadsheet Formulation* 와 동일 구조)

**데이터(파란), 변경(노랑), 목적(주황), 자원 제약(빨간 박스 = LHS ≤ RHS).**

| 위치 | 내용 |
|------|------|
| **C5:E5** | 각 프로젝트 **NPV** (45, 70, 50) |
| **C9:E12** | 위 표의 **누적 투자 계수** (4행×3열) |
| **F9:F12** | `=SUMPRODUCT($C9:$E9,$C$16:$E$16)` 행마다 복사 → **누적 투입(LHS)** |
| **G9:G12** | `<=` |
| **H9:H12** | **25, 45, 65, 80** |
| **C16:E16** | **Participation share** (변경 셀) — 슬라이드 시행해 예: 0%, 16.5%, 13.11% 등 |
| **H16** | `=SUMPRODUCT($C$5:$E$5,$C$16:$E$16)` → **Total NPV** (Max) |

*(셀에 **퍼센트 서식**이면 16.5% = 내부값 0.165 — **계수 행과 단위를 통일**하면 됨.)*

**Binding 예 (슬라이드 수치):** Year 0 과 Year 3 에서 **지출 = 한도**(25=25, 80=80)로 꽉 찬 경우가 많다고 설명할 수 있음.

### 6.7 Solver (연속 LP)

- **Objective:** `H16` → **Max**  
- **Changing:** `C16:E16`  
- **Constraints:** `F9:F12 <= H9:H12`, 변수 **≥ 0**  
- **Simplex LP**  
- 지분 상한 1이 문제에 있으면 `C16:E16 <= 1` 추가.

## 7. 예제 4: 포트폴리오 **동적 계획** — 보조변수·현금·이자

**주안:** 목적이 “4년 초 현금 최대”처럼 **한 시점의 상태**로 주어져도, 제약이 **연초마다 현금 ≥ 0**·**이자·재투자**로 얽히면 **\(X,Y\) 두 개로 압축**하면 지저분해진다. **투자액 \(A,\ldots,E\)** 는 **결정변수**, **각 연초 잔액 \(y_1,\ldots,y_4\)** 는 **보조변수**로 **시점별로 쪼개** 쓰는 것이 정석이다.

### 7.1 데이터 (1억원을 1단위로 투자할 때의 연초 현금흐름)

| 대안 | 1년초 | 2년초 | 3년초 | 4년초 |
|------|-------|-------|-------|-------|
| A | -1.0 | 0.6 | 0.9 | 0 |
| B | 0 | -1.0 | 0.4 | 1.1 |
| C | -1.0 | 1.3 | 0 | 0 |
| D | -1.0 | 0 | 0 | 1.6 |
| E | 0 | -1.0 | -0.5 | 2.0 |

- 음수 = 해당 연초 **추가 투입**, 양수 = **회수·수입**. 모두 **연초**에만 발생한다고 가정.  
- **가용 자금 120억**, 대안별 **최대 70억**(-1.0이 처음 나오는 시점의 투자 한도; 슬라이드: 분산·위험관리).  
- **미투자 현금**은 연 **8.1%** 이자. **회수금은 즉시 재투자** 가능. **차입 불가** → 매 연초 **현금 잔액 ≥ 0**.

### 7.2 결정변수·보조변수·목적

| 기호 | 의미 |
|------|------|
| \(A,B,C,D,E\) | 각 대안에 넣는 **투자금액**(억 원 스케일; 슬라이드·엑셀과 동일 단위로 통일) |
| \(y_1,y_2,y_3,y_4\) | **각 연초**의 **현금 잔액**(보조변수). **목적:** \(\max\; Z = y_4\) |

**동적 식 (슬라이드·모형화 가이드):**  
\(t\)년 초 현금 = \((1+r)\times (t-1)\)년 초 잔액 + \(t\)년 초 순현금흐름, 여기서 \(r=0.081\).

### 7.3 대수 모형 (연립·비음)

\[
\max\; Z = y_4
\]

\[
\begin{aligned}
y_1 &= 120 - A - C - D \\
y_2 &= (1+0.081)\,y_1 + 0.6A - B + 1.3C - E \\
y_3 &= (1+0.081)\,y_2 + 0.9A + 0.4B - 0.5E \\
y_4 &= (1+0.081)\,y_3 + 1.1B + 1.6D + 2.0E
\end{aligned}
\]

\[
A,B,C,D,E \le 70,\quad A,B,C,D,E \ge 0,\quad y_1,y_2,y_3,y_4 \ge 0
\]

- \(y_1\) 식: 1년 초에 **A,C,D**만 해당 연도 -1.0 투입이 있음 (B,E는 1년 초 0).  
- \(y_2\sim y_4\) 의 괄호 안은 표의 **해당 연초** 계수와 \(A\sim E\) 의 **선형 결합**이다.  
- **엑셀**에서는 보통 **\(y_i\)** 를 **한 줄 수식**으로 두고, `B28`(=이자 반영된 이월) 등으로 **\( (1+r)y_{t-1} \)** 과 **당기 SUMPRODUCT** 를 분리해 적기도 한다 (첨부 스프레드시트와 동일 논리).

### 7.4 스프레드시트 (첨부 *Dynamic Portfolio* 시트)

| 블록 | 내용 |
|------|------|
| **B3** | 초기 가용 **120** |
| **B4** | 이자율 **0.081** |
| **B5** | 대안당 상한 **70** |
| **B9:E13** | 위 현금흐름 표 (행=A~E) |
| **B17:B21** | **변경 셀** \(A\sim E\) |
| **C17:C21** `<=` **D17:D21**(70) | 투자 한도 |
| **B24:E24** | **\(y_1\sim y_4\)** (각 연초 잔액). `B24 = B3 + SUMPRODUCT(B9:B13,$B$17:$B$21)` 등 **열이 맞는** SUMPRODUCT |
| **B28** 등 | 이후 연초: **(이전 잔액)×(1+이자)** + `SUMPRODUCT`(해당 연도 열, 투자금) — 슬라이드 빨간 박스 수식과 동일 |
| **E24** | **목적 셀** — \(\max\) \(y_4\) (4년초 현금) |

**시행해가 실패하는 이유:** 예를 들어 \(A,C,D\) 각 40을 넣으면 1년 초에 120을 다 써서 **\(y_1=0\)** 이 되지만, 2년 초 흐름 때문에 **\(y_2<0\)** 이 될 수 있음 → **제약 \(y_i\ge 0\)** 으로 **실행 불가**가 드러난다 (첨부 빨간 화살표).

**최적해 예 (슬라이드):** \(A=50,\; B=70,\; C=70,\; D=0,\; E=51\) → **\(y_4 \approx 230.35\)억** (목적 셀).

### 7.5 Solver

- **Objective:** `E24` (또는 4년초 잔액 셀) → **Max**  
- **Changing:** `B17:B21`  
- **Constraints:** `B17:B21 <= D17:D21`, **`B24:E24 >= 0`** (또는 `>=` 0 셀), 투자금 **≥ 0**  
- **Simplex LP**  
- \(y_i\) 는 수식 셀이므로 **변경 변수가 아니다** — 보조변수는 **연립으로 결정**된다.

### 7.6 모형화 절차 9단계 — **Benefit / 최소 달성** 버전을 이 예제에 직접 대입

교재의 *Formulation Procedure* (성과=**편익·최소 달성 수준** + `SUMPRODUCT` + `>=`)를 이 문제에 맞게 읽으면 다음과 같다. (단, **목적**은 “비용 최소”가 아니라 **\(y_4\) 최대**.)

| 단계 | 이 예제에서의 대응 |
|------|---------------------|
| **1** Activities | 투자 **활동** 5개 = 대안 **A~E** |
| **2** Measure of performance | **4년 초 현금** \(y_4\) (최대화) |
| **3** Contribution per unit | \(y_4\) 는 \(A\sim E\) 에 대해 **비선형적으로 한 줄로** 안 쓰이고, **\(y_1\!\to\!y_4\) 연립**으로 들어감 → **3번은 “단위 기여” 한 줄 대신 동적 구조**로 대체 |
| **4** Benefits to achieve | **“각 시점에서 현금이 음수가 아니다”** = 4개의 **편익(상태)** |
| **5** Minimum level & activity contribution | 각 시점 **최소 0**; 달성량 = **해당 연초 잔액 \(y_t\)** (수식으로 `SUMPRODUCT`+이월과 동일 역할) |
| **6** Data cells | 현금흐름 표 **B9:E13**, 이자 **B4**, 한도 **B5**, 초기 **B3** |
| **7** Changing cells | **B17:B21** (\(A\sim E\)만) |
| **8** Benefit rows | **각 \(y_t \ge 0\)** 행: 잔액 셀 — `>=` — **0** (슬라이드 25~26행) |
| **9** Objective cell | **E24** = \(y_4\) (또는 동일 정의의 4년초 잔액) |

**정리:** 자원배분형 9단계(§3)는 “한 행에 SUMPRODUCT 한 번”에 잘 맞고, 이 예제는 **편익형 9단계**에 가깝지만 **편익이 \(y_t\)** 이고 **이자·재투자** 때문에 **보조변수 연립**이 필수다. **\(X,Y\)로 뭉치면** 이자와 시점이 섞여 **제약을 빼먹기 쉽다.**

## 8. 예제 5: Union Airways **Personnel Scheduling** — **Min 비용** · 커버리지 행렬

**질문:** 5개의 8시간 교대(Shift 1~5)에 **각각 몇 명**을 배치하면, **요구 인원**을 모두 만족하면서 **일일 총 인건비**를 최소화하는가? → **Min 문제**.

| Shift | 근무 시간 |
|-------|-----------|
| 1 | 6:00 AM – 2:00 PM |
| 2 | 8:00 AM – 4:00 PM |
| 3 | Noon – 8:00 PM |
| 4 | 4:00 PM – midnight |
| 5 | 10:00 PM – 6:00 AM |

### 8.1 스케줄 표(체크) → 부등식 — 논리적 연결

- 하루를 **10개 시간대**로 쪼개고, 각 시간대마다 **최소 필요 인원**이 있다.  
- 어떤 교대 \(S_i\) 가 그 시간대에 **근무 중이면** 체크(√) → 수학적으로 **계수 1**, 아니면 **0**.  
- 한 시간대에 실제로 근무 중인 **총 인원** = (그 시간대의 0/1 행)과 \((S_1,\ldots,S_5)\) 의 **가중합** = **선형식**  
  \[
  a_{t1}S_1 + a_{t2}S_2 + \cdots + a_{t5}S_5 \ge b_t
  \]
  여기서 \(b_t\) = 그 시간대 **최소 인원**, \(a_{ti}\in\{0,1\}\).

슬라이드 *Schedule Data* 체크표와 동일하게 **10개 부등식**을 한 줄씩 쓴다:

| 시간대 | 활성 교대 | 제약 |
|--------|-----------|------|
| 6 AM–8 AM | 1 | \(S_1 \ge 48\) |
| 8 AM–10 AM | 1, 2 | \(S_1+S_2 \ge 79\) |
| 10 AM–noon | 1, 2 | \(S_1+S_2 \ge 65\) |
| noon–2 PM | 1, 2, 3 | \(S_1+S_2+S_3 \ge 87\) |
| 2 PM–4 PM | 2, 3 | \(S_2+S_3 \ge 64\) |
| 4 PM–6 PM | 3, 4 | \(S_3+S_4 \ge 73\) |
| 6 PM–8 PM | 3, 4 | \(S_3+S_4 \ge 82\) |
| 8 PM–10 PM | 4 | \(S_4 \ge 43\) |
| 10 PM–midnight | 4, 5 | \(S_4+S_5 \ge 52\) |
| midnight–6 AM | 5 | \(S_5 \ge 15\) |

**일일 비용(목적):** 교대 \(i\) 당 **1명당 일비** \(c_i\) 가 주어지므로  
\[
\min\; Z = 170S_1 + 160S_2 + 175S_3 + 180S_4 + 195S_5
\]
\(S_i \ge 0\) (정수를 요구하면 IP; 연속 LP로 두면 **실무 근사**·교재에 따름.)

### 8.2 **SUMPRODUCT** 를 어디에 쓰는지 — 왜 그 위치인가 (이해 중심)

| 셀 블록 | 역할 | `SUMPRODUCT` 가 하는 일 | 근거 한 줄 |
|---------|------|---------------------------|------------|
| **목적 (예: `J21`)** | 총비용 | `SUMPRODUCT(일당 비용 행, S1~S5)` = \(\sum_i c_i S_i\) | 비용 = **(교대별 단가)** × **(그 교대 인원)** 의 합 — Wyndor의 `SUMPRODUCT(단위이익, 생산량)` 과 **같은 문법** |
| **제약 LHS (예: `H8:H17`)** | 시간대별 **가동 인원** | `SUMPRODUCT(해당 시간대의 0/1 행, $C$21:$G$21)` | 한 시간대에 “켜져 있는” 교대만 \(S_i\) 가 **더해져야** 그 시간 **창구에 서 있는 총 인원**이 됨. 수작업으로 \(S_1+S_2\) 쓰면 행이 10개라 **실수·누락**이 나기 쉬움 |

**논리:**  
1) **열** = 교대(결정변수 \(S_1\sim S_5\)).  
2) **행** = 시간대.  
3) **행벡터(0/1)** 는 “이 시간에 이 교대가 겹치나?”를 인코딩한다.  
4) 그 행과 변수벡터의 내적 = **그 순간 근무 중인 인원 수의 합**.  
5) 그 값이 **최소 요구 \(b_t\) 이상**이어야 하므로 **`>=`** 와 짝을 이룬다.

즉 `SUMPRODUCT` 는 **장식이 아니라**, “**선형계획의 한 줄 LHS**”를 엑셀이 한 셀에 담게 해 주는 도구다.

### 8.3 스프레드시트 (첨부 *Spreadsheet Formulation*)

| 위치 | 내용 |
|------|------|
| **C5:G5** | 교대별 **일당 비용** 170, 160, 175, 180, 195 |
| **C8:G17** | **커버리지 행렬** (1 = 그 시간대에 해당 교대 근무) |
| **C21:G21** | **변경 셀** \(S_1\sim S_5\) |
| **H8** | `=SUMPRODUCT(C8:G8,$C$21:$G$21)` → 아래로 복사 |
| **I8:I17** | `>=` |
| **J8:J17** | 각 시간대 **최소 인원** (48, 79, …, 15) |
| **J21** (주황) | `=SUMPRODUCT(C5:G5,C21:G21)` → **Min** |

**시행해 (슬라이드):** \(S_1=48,\; S_2=31,\; S_3=39,\; S_4=43,\; S_5=15\) → **총비용 30,610**.

### 8.4 Solver

- **Objective:** `J21` → **Min**  
- **Changing:** `C21:G21`  
- **Constraints:** `H8:H17 >= J8:J17` (또는 LHS 셀과 RHS 직접), `C21:G21 >= 0`  
- **Simplex LP**  
- (선택) 인원이 정수여야 하면 `int` 제약.

### 8.5 교재 **Benefit 절차 9단계**를 이 예제에 직접 대응

(§3 자원배분 9단계와 달리, 슬라이드에 나오는 **“편익·최소 달성”** 절차를 **인력 스케줄**에 맞춘 버전.)

| 단계 | Union Airways 에서의 의미 |
|------|---------------------------|
| **1** Activities | **교대별 배정** 5개 = \(S_1\sim S_5\) |
| **2** Performance measure | **총 일일 비용** 최소 (Min) |
| **3** Contribution to performance | 교대 \(i\) **1명당 일비** \(c_i\) → 목적 \(\sum c_i S_i\) |
| **4** Benefits to achieve | 각 **시간대**에 “최소 **가동 인원**” 이상 확보 |
| **5** Min level & contribution | 최소 \(b_t\); 대안 \(i\) 가 시간 \(t\) 에 **커버하면** 기여 **1**, 아니면 **0** → LHS \(=\sum_i a_{ti} S_i\) |
| **6** Data | **C5:G5** 비용, **C8:G17** 0/1, **J8:J17** 최소 인원 |
| **7** Changing | **C21:G21** |
| **8** Benefit rows | **H8:H17** `SUMPRODUCT` — `>=` — **J8:J17** |
| **9** Objective | **J21** `SUMPRODUCT`(비용, 인원) → **Min** |

**한 줄:** 이 문제는 **자원(≤)** 이 아니라 **“각 시간대 인원 ≥ 기준”** 이라 **Benefit(≥)** 형이고, `SUMPRODUCT` 는 **그 LHS**와 **비용 목적** 두 곳에 **같은 변수벡터**를 꽂는다.
