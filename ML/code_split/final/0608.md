## 1. 오늘 첫 문장

딥러닝을 제일 처음부터 보면, 이 한 문장이다.

```text
모델은 X를 보고 y를 맞히도록 학습되는 함수다.
```

여기서 아직 `Dense`, `ReLU`, `Adam`, `Keras`, `CNN` 생각하지 마라. 제일 먼저 볼 것은 이것이다.

```text
X = 문제지
y = 정답지
model = 문제지를 보고 정답을 예측하는 함수
ŷ = 모델이 낸 답
loss = ŷ가 y와 얼마나 다른지 나타내는 숫자
```

6강 자료는 이 기본 구조를 명확히 둔다. 예측변수, 즉 feature (X)는 모델 입력 변수이고, 반응변수 또는 target (y)는 모델이 맞혀야 하는 클래스 라벨이라고 정리한다. 지도학습은 (X)와 정답 (y)가 함께 주어진 데이터로 학습하는 방식이다.

## 2. 아주 쉬운 예시: Iris 분류

Iris 문제를 보자.

```text
꽃받침 길이
꽃받침 너비
꽃잎 길이
꽃잎 너비
→ 이 꽃이 setosa / versicolor / virginica 중 무엇인가?
```

이때 (X)와 (y)는 이렇게 된다.

```text
X = 꽃의 측정값 4개
y = 꽃의 품종 이름
```

표로 쓰면 이렇다.

| sepal_length | sepal_width | petal_length | petal_width | species    |
| -----------: | ----------: | -----------: | ----------: | ---------- |
|          5.1 |         3.5 |          1.4 |         0.2 | setosa     |
|          7.0 |         3.2 |          4.7 |         1.4 | versicolor |
|          6.3 |         3.3 |          6.0 |         2.5 | virginica  |

여기서 모델에 들어가는 것은 보통 왼쪽 네 열이다.

```text
X = [
  [5.1, 3.5, 1.4, 0.2],
  [7.0, 3.2, 4.7, 1.4],
  [6.3, 3.3, 6.0, 2.5],
  ...
]
```

정답은 오른쪽 한 열이다.

```text
y = [
  setosa,
  versicolor,
  virginica,
  ...
]
```

6강 자료도 Iris 예시에서 (X)를 `sepal_length`, `sepal_width`, `petal_length`, `petal_width`로, (y)를 `species`로 매핑한다. 

첫 번째 고정 문장:

```text
X는 모델이 보는 입력이고,
y는 모델이 맞혀야 하는 정답이다.
```

## 3. 모델은 무엇을 하는가

모델은 결국 함수다.

```text
model(X) = ŷ
```

수식으로 쓰면:

[
\hat{y} = f_\theta(X)
]

여기서 (\theta)는 모델 안의 파라미터다. 신경망에서는 보통 weight (W)와 bias (b)가 여기에 해당한다.

처음에는 모델이 아무것도 모른다. 그래서 예측이 틀린다.

```text
X = 꽃 측정값
y = 실제 품종
ŷ = 모델이 예측한 품종
```

예를 들어 실제 정답은 setosa인데 모델이 versicolor라고 하면 틀린 것이다. 그런데 컴퓨터는 “틀렸다”라는 말을 바로 이해하지 못한다. 그래서 틀린 정도를 숫자로 바꾼다. 그 숫자가 **loss**다.

```text
loss = 예측 ŷ와 정답 y의 차이
```

8강 자료는 Neural Network의 핵심 3요소를 Architecture, Loss, Backprop+GD로 잡는다. 구조가 예측을 만들고, 예측과 정답의 차이가 loss가 되며, loss 기준으로 gradient를 계산하고, gradient 반대 방향으로 파라미터를 수정한다고 정리한다.

## 4. 딥러닝 학습 루프: 네 단계

이제 오늘 교재의 첫 핵심 루프다.

```text
X_batch
→ net.forward(X_batch)
→ loss_fn.forward(logits, y_batch)
→ loss_fn.backward()
→ net.backward(dloss)
→ optimizer.step(net)
```

아직 코드처럼 보지 말고, 말로 바꿔라.

```text
1. X를 넣는다.
2. 모델이 예측한다.
3. 정답 y와 비교해서 loss를 계산한다.
4. loss를 줄이려면 각 weight를 어떻게 고쳐야 하는지 계산한다.
5. optimizer가 weight를 실제로 수정한다.
```

이걸 강의식 이름으로 쓰면:

```text
Forward → Loss → Backward → Update
```

8강 자료는 이 네 단계를 정확히 이렇게 정의한다. Forward는 입력이 층을 통과해 예측값을 만드는 단계, Loss는 예측값과 정답의 거리를 하나의 숫자로 계산하는 단계, Backward는 각 가중치가 loss에 얼마나 책임이 있는지 역방향으로 계산하는 단계, Update는 그 책임 크기만큼 가중치를 수정하는 단계다. 

---

## 5. 네 단계를 사람 말로 다시 쓰기

### 5.1 Forward

```text
X → model → ŷ
```

모델이 현재 weight를 가지고 예측한다.

예시:

```text
입력 X: 꽃잎 길이 1.4, 꽃잎 너비 0.2, ...
모델 예측 ŷ: setosa일 확률 0.60, versicolor일 확률 0.30, virginica일 확률 0.10
```

Forward는 아직 학습이 아니다. 그냥 현재 모델로 한 번 예측해보는 것이다.

---

### 5.2 Loss

```text
ŷ와 y를 비교한다.
```

예를 들어 정답이 setosa라면, 모델이 setosa 확률을 높게 주면 loss가 작다. 모델이 versicolor나 virginica 확률을 높게 주면 loss가 크다.

```text
정답 y = setosa
예측 ŷ = setosa 확률 0.60
→ 그럭저럭 맞음 → loss 중간

정답 y = setosa
예측 ŷ = setosa 확률 0.05
→ 많이 틀림 → loss 큼
```

Loss는 “얼마나 틀렸는지”를 숫자로 만든 것이다.

---

### 5.3 Backward

```text
각 weight가 이 loss에 얼마나 책임이 있는지 계산한다.
```

여기서 처음으로 gradient가 나온다.

```text
이 weight를 올리면 loss가 커지는가?
이 weight를 내리면 loss가 작아지는가?
얼마나 바꿔야 하는가?
```

이 질문에 대한 숫자 답이 gradient다.

Backpropagation은 최종 loss에서 시작해서 각 파라미터의 책임을 chain rule로 계산한다. 8강의 최종 개념 지도도 `output → loss → backpropagation → parameter update` 흐름으로 정리한다. 

---

### 5.4 Update

```text
gradient를 이용해 weight와 bias를 수정한다.
```

기본 아이디어는 이 식이다.

[
\theta \leftarrow \theta - \eta \nabla_\theta J(\theta)
]

여기서 (\theta)는 weight와 bias 전체, (\eta)는 learning rate, (\nabla_\theta J(\theta))는 loss가 증가하는 방향이다. 그래서 loss를 줄이려면 gradient의 반대 방향으로 이동한다. 

오늘은 이 식을 이렇게만 기억한다.

```text
gradient = loss가 커지는 방향
update = 그 반대 방향으로 parameter를 움직임
```

## 6. 제일 중요한 책임 분리

여기서 오늘 첫 번째 큰 구분이 나온다.

```text
Backprop은 gradient를 계산한다.
Optimizer는 계산된 gradient로 parameter를 움직인다.
```

이 둘을 섞으면 안 된다.

13강에서는 12강의 구조를 한 단계 더 나누어, `Layer`는 forward/backward와 gradient 계산을 책임지고, `Optimizer`는 파라미터를 어떤 규칙으로 움직일지 책임진다고 정리한다. 그래서 SGD, Momentum, RMSProp, Adam으로 자연스럽게 확장된다. 

오늘 교재 첫 셀의 핵심 문장도 여기에 있다.

```text
Optimizer는 X/y를 보지 않는다.
Optimizer는 layer가 들고 있는 param과 grad만 읽고 parameter를 update한다.
```

즉:

```text
X/y → forward/loss/backward에서 gradient를 만드는 데 필요
optimizer → 이미 만들어진 gradient로 parameter를 update
```

이걸 도식으로 쓰면:

```text
X_batch, y_batch
    ↓
forward
    ↓
loss
    ↓
backward
    ↓
각 layer에 grad 저장
    ↓
optimizer.step(net)
    ↓
parameter update
```

13강의 직접 구현 예시도 `pred = net.forward`, `loss = loss_fn.forward`, `grad = loss_fn.backward`, `net.backward(grad)`, `optimizer.step(net)` 순서로 학습 루프를 정리한다.

## 7. 왜 신경망을 쓰는가

그럼 전통적인 머신러닝과 신경망의 차이는 무엇인가?

8강 자료는 기존 ML의 공통 병목을 feature engineering으로 잡는다. 선형회귀, Naive Bayes, K-NN, SVM, Decision Tree는 서로 다른 방식으로 예측하지만, 공통적으로 사람이 좋은 feature를 설계해줘야 성능이 잘 나오는 문제가 있다. 반면 DNN은 데이터로부터 feature 변환까지 함께 학습하려는 방향이다. 

쉽게 말하면:

```text
기존 ML:
사람이 좋은 feature를 만들어줌
→ 모델이 예측 규칙을 학습

Deep Learning:
입력 데이터
→ hidden layer가 중간 feature를 학습
→ 모델이 예측
```

그렇다고 신경망이 모든 일을 자동으로 하는 것은 아니다. 8강 자료도 사람이 여전히 문제 정의, 타깃 정의, 데이터 정리, train/validation/test split, 정규화, 모델 구조, loss, optimizer, overfitting 검증을 책임져야 한다고 정리한다. 

오늘의 정확한 문장:

```text
신경망은 feature engineering의 일부를 hidden layer 안으로 옮긴다.
하지만 X/y 정의, 전처리, loss 선택, metric 선택, validation은 사람이 한다.
```

## 8. 오늘 첫 블록의 전체 그림

지금까지를 한 번에 묶으면:

```text
Raw data
→ X/y 분리
→ preprocessing
→ model.forward(X)
→ prediction ŷ
→ loss(ŷ, y)
→ backward로 gradient 계산
→ optimizer.step으로 parameter update
→ 다시 forward
```

13강의 Keras 모델링 절차도 같은 흐름이다. `Data preparing`에서 (X)와 (y)를 구성하고, EDA에서 shape와 분포를 확인하고, preprocessing에서 split/scaling을 한 뒤, modeling에서 구조 정의와 `compile`, `fit`을 수행하고, validation/test에서 metric과 예측값을 비교한다. Keras는 원리를 숨기는 도구가 아니라 직접 구현했던 `forward → loss → backward → update` 루프를 안정적인 API로 감싼 도구라고 설명한다. 

그래서 `model.fit()`은 마법이 아니다.

```text
model.fit()
= forward/loss/backward/update를 여러 epoch 동안 반복하는 함수
```


## 10. 미니 체크

이제 네가 답해야 할 첫 문제다. 길게 쓰지 말고, 각 줄에 한 문장씩 답하면 된다.

```text
문제:
Iris 데이터에서 꽃받침 길이, 꽃받침 너비, 꽃잎 길이, 꽃잎 너비로
꽃 품종 3개 중 하나를 맞히려고 한다.

1. X는 무엇인가?
2. y는 무엇인가?
3. 이 문제는 회귀인가 분류인가?
4. Forward는 무엇을 만드는가?
5. Loss는 무엇과 무엇을 비교하는가?
6. Optimizer는 X/y를 직접 보는가?
```
X는 모델에 입력되는 feature matrix이고,
y는 모델이 맞혀야 하는 target, 즉 정답값이다.

모델은 X를 입력받아 예측값 ŷ를 만든다.
이 과정이 forward이다.

loss는 예측값 ŷ와 정답 y가 얼마나 다른지를 하나의 숫자로 나타낸 것이다.
학습의 목표는 이 loss를 최소화하는 것이다.

backward는 loss를 기준으로 각 parameter, 즉 weight와 bias가 loss에 얼마나 책임이 있는지 gradient로 계산하는 과정이다.

optimizer는 X와 y를 직접 보는 것이 아니라,
backward 결과로 각 layer에 저장된 gradient와 parameter를 이용해
W, b를 update하는 규칙이다.

따라서 딥러닝 학습은
X → forward → ŷ → loss(ŷ, y) → backward → gradient → optimizer update
의 반복이다..
---------
문제:
Iris 분류에서 X shape가 (150, 4)이고,
y는 0, 1, 2 세 개 class label이다.

1. 이 문제는 회귀인가 분류인가?
2. output layer는 Dense 몇 개여야 하는가?
3. 마지막 activation은 무엇을 써야 하는가?
4. loss는 무엇을 써야 하는가?
5. metric은 무엇을 쓰는가?
6. 왜 Dense(1)이 아니라 Dense(3)인가?

Iris 데이터의 X는 꽃받침 길이, 꽃받침 너비, 꽃잎 길이, 꽃잎 너비 네 개 feature로 이루어진 feature matrix이며 shape은 (150,4)이다.

원래 y는 0, 1, 2로 표현된 class index이므로 shape은 (150,)이다.
이 값들은 수치 크기나 순서를 의미하는 것이 아니라 setosa, versicolor, virginica라는 nominal class label이다.

따라서 이 문제는 회귀가 아니라 단일 정답 다중분류 문제다.
0,1,2를 연속값처럼 보고 Dense(1)+MSE로 학습하면 안 된다.

출력층은 class 개수와 같은 Dense(3)을 사용한다.
마지막 출력은 각 class에 대한 logit 또는 softmax 확률분포이며, softmax를 적용하면 세 class 확률의 합이 1이 된다.

one-hot target을 사용하면 Y shape은 (150,3)이 되고, loss는 categorical cross entropy 또는 SoftmaxCE를 사용한다.
정수 label y를 그대로 사용하면 sparse categorical cross entropy를 사용한다.

metric은 기본적으로 accuracy를 쓰고, class별 성능을 공평하게 보고 싶으면 macro F1을 추가할 수 있다.

------------------------

마지막 Dense가 Dense(8,3)이므로 n_in=8, n_out=3이다.
mini-batch size가 16이므로 이 layer에 들어오는 X는 (16,8)이다.

강의 convention은 Z = X @ W.T + b 이므로
W는 (3,8), b는 (3,)이고,
logits Z는 (16,8) @ (8,3) = (16,3)이 된다.

SoftmaxCE.backward()는 (p-y)/B를 반환하므로 gradient dZ의 shape은 logits와 같은 (16,3)이다.

Dense.backward에서는
dW = dZ.T @ X = (3,16) @ (16,8) = (3,8),
db = dZ.sum(axis=0) = (3,),
dX = dZ @ W = (16,3) @ (3,8) = (16,8)
이 된다.

--1. Dense(n_in, n_out)을 읽는다.
2. batch size B를 확인한다.
3. X = (B, n_in)
4. W = (n_out, n_in)
5. b = (n_out,)
6. Z = (B, n_out)
7. loss backward gradient dZ = Z와 같은 shape
8. dW는 W와 같은 shape
9. db는 b와 같은 shape
10. dX는 X와 같은 shape

-->네가 요청한 대로, 4→8→3 Iris 네트워크를 파이썬으로 한 번 흘려보고, 그걸 시각화한 그림을 만들었다.

## 1. 그림에 담긴 내용 요약
그림은 두 패널로 구성되어 있다.

1) 왼쪽: 입력 공간 (X의 첫 두 feature)  

- X의 shape는 `(16, 4)`이고, 여기서 첫 두 feature `(x1, x2)`만 꺼내서 scatter로 그렸다.  
- 각 점의 색깔은 해당 샘플의 class label(y_idx)을 나타낸다 (0, 1, 2 중 하나).  
- 이 패널은 “입력 미니배치 16개가 실제로는 4차원이지만, 그 중 앞의 2차원만 보면 이런 분포를 가진다”는 걸 보여준다.

2) 오른쪽: 마지막 Dense(8→3)에서 나온 logits  

- Dense₂ forward 결과 Z₂는 shape `(16, 3)`이다.  
- 그 중 첫 3개 샘플에 대해, 각 클래스(0,1,2)의 logit 값을 bar chart로 그렸다.  
- x축: class 0,1,2  
- 각 색깔/offset: sample 0, sample 1, sample 2에 대한 logits.  
- 이 패널은 “각 샘플이 output layer에서 3차원 logits로 표현된다”는 걸 눈으로 보여준다.

***
## 2. 코드 상에서 실제로 한 일 (forward/backward)
코드는 다음과 같은 순서로 4→8→3 네트워크를 forward/backward 했다.

1) 네트워크 파라미터와 입력 세팅

- 배치 크기 B=16, 입력 차원 nin=4, hidden=8, output=3.  
- `X`: `(16, 4)` 랜덤 입력 (Iris의 4차원 feature를 흉내).  
- `W1`: `(8, 4)`, `b1`: `(8,)`  
- `W2`: `(3, 8)`, `b2`: `(3,)`  

2) forward pass

- Dense₁:  
  - `Z1 = X @ W1.T + b1` → `(16, 8)`  
  - `A1 = ReLU(Z1)` → `(16, 8)`  
- Dense₂:  
  - `Z2 = A1 @ W2.T + b2` → `(16, 3)`  
- Softmax:  
  - `P = softmax(Z2)` → `(16, 3)`  
- 타깃:  
  - y_idx: `(16,)`에서 0~2 정수  
  - Y = one-hot: `(16, 3)`  
- Cross Entropy loss:  
  - `loss = -mean(sum(Y * log P, axis=1))` → scalar  

3) backward pass

- SoftmaxCE backward:  
  - `G = (P - Y) / B` → `(16, 3)`  
- Dense₂ backward:  
  - `dW2 = G.T @ A1` → `(3, 8)`  
  - `db2 = G.sum(axis=0)` → `(3,)`  
  - `dA1 = G @ W2` → `(16, 8)`  
- Dense₁ backward (ReLU 포함):  
  - `mask = (Z1 > 0)` → `(16, 8)`  
  - `dZ1 = dA1 * mask` → `(16, 8)`  
  - `dW1 = dZ1.T @ X` → `(8, 4)`  
  - `db1 = dZ1.sum(axis=0)` → `(8,)`  
  - `dX = dZ1 @ W1` → `(16, 4)`  

코드 출력 shape들도 모두 우리가 앞에서 수식으로 유도한 것과 일치한다.

***
## 3. 이 그림이 왜 의미 있는지
이 그림은 단순한 데모가 아니라, 네가 “shape를 암기식이 아니라 구조로 이해”하도록 돕는 시각적 도구다.

1) 왼쪽 scatter:  
   - 입력 X가 `(16, 4)`라는 사실을 **“각 샘플은 4차원 벡터”**라는 관점으로 보여준다.  
   - 우리는 그 중 두 축만 꺼내서 그렸지만, 나머지 두 축까지 포함하면 hidden layer에서 8차원으로 매핑된다.

2) 오른쪽 logits bar chart:  
   - 각 샘플이 hidden layer를 거쳐 Dense₂에서 3차원 logits에 매핑된다는 걸 숫자와 그림으로 보여준다.  
   - Softmax는 이 logits를 확률 분포 `(16,3)`로 바꾸고, CE loss는 그 확률과 one-hot target의 차이를 측정한다.  

3) forward/backward 쉐입:  
   - 코드 내부에서 기록한 `shapes` dict는 우리가 수식으로 유도한 모든 shape (X, Z1, A1, Z2, P, G, dW2, db2, dA1, dW1, db1, dX)를 그대로 보여준다.  
   - 이걸 보면 “각 단계의 행렬 곱과 미분이 어떤 shape를 가져야 하는지” 직접 확인할 수 있다.

## 4. 다음 단계 제안
이제부터는 네가 직접 조금만 수정해 보면서 “몸에 익히기” 모드로 가는 게 좋다.

예를 들어:

- hidden dimension을 8→16으로 바꾸고,  
  - W1, W2 shape, Z1, A1, dW1, dW2 shape가 어떻게 바뀌는지 코드를 통해 확인해보기.  
- batch size를 16→32로 바꾸고,  
  - X, Z1, Z2, G의 첫 dimension이 어떻게 달라지는지 확인해보기.  
- SoftmaxCE에서 `(P - Y) / B`를 `(P - Y)`로 바꿔보고,  
  - gradient scale이 어떻게 변하는지, loss 크기와 비교해보기.  

. 마지막 Dense에 ReLU를 안 다는 이유 (분류 출력층의 의미)
4-1. Softmax 전 단계의 Dense는 “logits”를 제공해야 한다
Softmax는 제약 없는 실수(logits) 를 받아서 확률로 바꾸는 함수다.
입력: logits zk∈Rzk​∈R
출력: pk=exp⁡(zk)∑jexp⁡(zj)pk​=∑j​exp(zj​)exp(zk​)​
여기서 중요한 점:
Softmax 입력 z는 음수/양수 상관없이 자유로운 실수여야 한다.
이 실수들 사이의 차이가 클래스 간 “선형 decision boundary”를 만들어준다.
4-2. ReLU를 logits 앞에 달면 생기는 문제
ReLU는 음수를 잘라서 0으로 만든다.
만약 마지막 Dense(8→3) 뒤에 ReLU를 달면:
Z₂: logits (음수/양수)
A₂ = ReLU(Z₂): 음수는 0으로 잘리고 양수만 남는다.
Softmax는 A₂를 받아서 확률로 만든다.
문제:
음수 logits를 사용해서 “한 클래스는 크게 음수, 다른 클래스는 양수” 같은 풍부한 표현을 할 수 있었던 자유도가 줄어든다.
음수 방향의 정보가 모두 0으로 깎여 나가서, decision boundary 표현력이 비효율적이 된다.
특히 multi-class에서, ReLU로 잘린 클래스는 항상 0 이상의 값만 가지게 되어 “softmax 이전 분포”를 인위적으로 왜곡하게 된다.
