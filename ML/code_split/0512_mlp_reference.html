파일 전체 구조

mlp_scratch.py 안에는 무엇이 있나?

이 파일에는 크게 3개의 것이 들어 있습니다:

① 두 개의 함수: sigmoid(z), sigmoid_prime_from_output(a) — 도구 함수

② 하나의 클래스: MLP — 신경망 설계도. 안에 __init__, forward_with_cache, backward, train, predict 등의 메서드가 있음

③ 검증용 함수들: gradient_check(...), train_xor(...) — 학습이 잘 됐는지 확인용

파일 구조 요약 mlp_scratch.py ├─ sigmoid(z) ← σ(z) 계산 함수 ├─ sigmoid_prime_from_output(a) ← σ'(z) = a(1-a) 계산 함수 │ ├─ class MLP: ← 신경망 설계도 │ ├─ __init__ ← 가중치 초기화 │ ├─ forward ← 예측만 (간단 버전) │ ├─ forward_with_cache ← 예측 + 중간값 저장 │ ├─ backward ← 9개 편미분 계산 │ ├─ train ← 학습 루프 │ └─ predict ← 여러 샘플 예측 │ ├─ verification_example() ← 손계산 검증용 ├─ gradient_check(...) ← 수치 미분 vs 분석 미분 비교 └─ train_xor() ← XOR 학습 데모
2

클래스와 인스턴스 — `mlp = MLP(...)` 의 의미

클래스 = 설계도, 인스턴스 = 만들어진 물건

class MLP: 라는 코드는 "MLP라는 이름의 신경망 설계도를 정의한다"는 뜻입니다. 설계도일 뿐, 아직 신경망 자체는 만들어지지 않았습니다.

아래 한 줄을 실행해야 비로소 실제 신경망 한 개가 만들어집니다:

mlp = MLP(n_input=2, n_hidden=2, n_output=1)

이 한 줄로 mlp라는 이름의 신경망이 메모리에 생깁니다. 같은 설계도로 여러 개를 만들 수도 있습니다 (mlp2 = MLP(...)).

비유 MLP 클래스는 자동차 설계도. mlp = MLP(...)는 그 설계도로 자동차 한 대를 실제로 만든 것. mlp.forward(x)는 그 자동차에게 "주행해" 라고 명령하는 것.

self는 "자기 자신"

클래스 안의 함수(메서드)는 첫 번째 인자가 항상 self입니다. self.W1은 "이 mlp 객체가 자기 안에 가지고 있는 W1"이라는 뜻입니다.

mlp를 두 개 만들면 각각 자신의 W1을 따로 갖습니다. 한 mlp의 W1을 바꿔도 다른 mlp는 영향 없음.

mlp1 = MLP()      # mlp1 자기만의 W1, W2, b1, b2
mlp2 = MLP()      # mlp2 자기만의 W1, W2, b1, b2  (mlp1과 별개)

mlp1.W1 = ...     # mlp1의 W1만 바뀜. mlp2는 그대로.
3

`__init__` — 가중치를 self에 저장하기

__init__ 은 "인스턴스가 만들어질 때 자동으로 실행되는 함수"입니다. mlp = MLP(...) 라고 쓰면 NumPy가 자동으로 __init__을 호출해서 가중치를 만듭니다.

mlp_scratch.py 클래스 안의 __init__ 메서드 
class MLP:
    def __init__(self, n_input=2, n_hidden=2, n_output=1):
        self.W1 = np.random.randn(n_hidden, n_input) * 0.5
        self.b1 = np.zeros(n_hidden)
        self.W2 = np.random.randn(n_output, n_hidden) * 0.5
        self.b2 = np.zeros(n_output)
한 줄씩 설명
self.W1 = np.random.randn(2, 2) * 0.5
(2×2) 크기의 작은 랜덤 가중치 행렬을 만들어 mlp 자신의 W1에 저장. 곱하기 0.5로 값 크기를 줄임 (학습 안정성).
self.b1 = np.zeros(2)
크기 2짜리 0벡터를 만들어 b1에 저장. 바이어스는 보통 0으로 시작.
self.W2, self.b2
출력층 가중치와 바이어스. W2는 (1×2), b2는 크기 1짜리.
핵심 __init__ 이 끝나면 mlp 객체 안에 W1, b1, W2, b2 4개의 행렬·벡터가 준비됩니다. 이후 모든 메서드는 이 4개를 사용해 계산합니다.
4

`forward_with_cache` — 예측 + 중간값 보관

입력 x를 받아 예측값과 중간 계산 결과를 함께 반환합니다. 중간값을 저장하는 이유는, 뒤이어 호출될 backward가 이 값들을 재사용하기 때문입니다.

mlp_scratch.py forward_with_cache 메서드 
    def forward_with_cache(self, x):
        z1 = self.W1 @ x + self.b1      # 은닉층 pre-activation
        a1 = sigmoid(z1)                  # 시그모이드 통과
        z2 = self.W2 @ a1 + self.b2     # 출력층 pre-activation
        a2 = z2                           # 출력 (활성화 없음)

        return {"x": x, "z1": z1, "a1": a1, "z2": z2, "a2": a2}
수식이 코드 줄
$\mathbf{z}^{(1)} = \mathbf{W}^{(1)}\mathbf{x} + \mathbf{b}^{(1)}$ z1 = self.W1 @ x + self.b1
$\mathbf{a}^{(1)} = \sigma(\mathbf{z}^{(1)})$ a1 = sigmoid(z1)
$z^{(2)} = \mathbf{W}^{(2)}\mathbf{a}^{(1)} + b^{(2)}$ z2 = self.W2 @ a1 + self.b2
$a^{(2)} = z^{(2)}$ a2 = z2
핵심 수식 한 줄 = 코드 한 줄. 1:1 대응이 정확히 보입니다. self.W1 은 __init__ 에서 만들어둔 그 W1을 가져다 쓰는 것.
5

cache, grads — dict의 역할

dict는 "이름표가 붙은 사물함"

코드에서 cache와 grads는 dict 타입입니다. 여러 값을 묶어서 한 번에 넘기되, 각 값에 이름표를 붙여둔 보관함입니다.

# forward_with_cache가 반환한 cache 안에 들어 있는 것:
cache = {
    "x":  [1.0, 1.0],
    "z1": [0.3, 0.7],
    "a1": [0.5744, 0.6682],
    "z2": [0.6881],
    "a2": [0.6881]
}

# 값을 꺼낼 때는 이름표로:
a1_value = cache["a1"]    # → [0.5744, 0.6682]
비유 cache가 만약 그냥 list [x, z1, a1, z2, a2] 였다면 cache[2]로 a1을 꺼내야 합니다. 인덱스를 외워야 하니 헷갈림. dict로 만들면 cache["a1"]로 이름 그대로 꺼낼 수 있어서 명확합니다.

backward가 반환하는 grads도 같은 구조입니다:

grads = {
    "dW1": ...,  # ∂L/∂W⁽¹⁾
    "db1": ...,  # ∂L/∂b⁽¹⁾
    "dW2": ...,  # ∂L/∂W⁽²⁾
    "db2": ...   # ∂L/∂b⁽²⁾
}

# 가중치 편미분 꺼낼 때:
dW2_value = grads["dW2"]
6

`backward` — 9개 편미분 계산

forward에서 만든 cache와 정답 y를 받아 9개 편미분을 한 번에 계산해서 dict로 반환합니다. 이게 backpropagation 구현의 핵심.

mlp_scratch.py backward 메서드 
    def backward(self, cache, y):
        x, a1, a2 = cache["x"], cache["a1"], cache["a2"]

        # 1. 출력층 오차
        dL_da2 = a2 - y

        # 2. 출력층 가중치/바이어스 편미분
        dW2 = np.outer(dL_da2, a1)
        db2 = dL_da2

        # 3. 에러를 은닉층으로 역전파
        dL_da1 = self.W2.T @ dL_da2

        # 4. 시그모이드 미분 통과
        delta1 = dL_da1 * a1 * (1.0 - a1)

        # 5. 은닉층 가중치/바이어스 편미분
        dW1 = np.outer(delta1, x)
        db1 = delta1

        return {"dW1": dW1, "db1": db1, "dW2": dW2, "db2": db2}
수식 (Backward Pass)이 코드 줄
cache에서 forward 결과 꺼내기 x, a1, a2 = cache["x"], cache["a1"], cache["a2"]
$\delta^{(2)} = a^{(2)} - y$ dL_da2 = a2 - y
$\partial L / \partial \mathbf{W}^{(2)} = \delta^{(2)} \cdot (\mathbf{a}^{(1)})^\top$ dW2 = np.outer(dL_da2, a1)
$\partial L / \partial b^{(2)} = \delta^{(2)}$ db2 = dL_da2
$\partial L / \partial \mathbf{a}^{(1)} = (\mathbf{W}^{(2)})^\top \cdot \delta^{(2)}$ dL_da1 = self.W2.T @ dL_da2
$\boldsymbol{\delta}^{(1)} = \partial L / \partial \mathbf{a}^{(1)} \odot \mathbf{a}^{(1)} \odot (1 - \mathbf{a}^{(1)})$ delta1 = dL_da1 * a1 * (1.0 - a1)
$\partial L / \partial \mathbf{W}^{(1)} = \boldsymbol{\delta}^{(1)} \cdot \mathbf{x}^\top$ dW1 = np.outer(delta1, x)
$\partial L / \partial \mathbf{b}^{(1)} = \boldsymbol{\delta}^{(1)}$ db1 = delta1
핵심 backward 코드는 12줄 남짓이지만, 그 안에 강의에서 손으로 유도한 9개 편미분이 모두 들어 있습니다.
7

인자가 어떻게 흐르는가 (전체 흐름)

학생이 직접 작성하는 코드(호출 쪽)와 mlp_scratch.py 안의 코드(정의 쪽)가 어떻게 서로 값을 주고받는지를 한 그림으로 정리합니다.

Forward 호출 흐름 [호출 쪽: 학생이 작성] [정의 쪽: mlp_scratch.py 안] x = np.array([1.0, 1.0]) │ │ 인자로 전달 ▼ mlp.forward_with_cache(x) ───────→ def forward_with_cache(self, x): z1 = self.W1 @ x + self.b1 a1 = sigmoid(z1) z2 = self.W2 @ a1 + self.b2 a2 = z2 ┌─────── return ←──── return {"x":x, "z1":z1, ...} ▼ cache = {...} ← 반환된 dict가 cache에 들어감
Backward 호출 흐름 [호출 쪽] [정의 쪽] y = np.array([0.0]) cache (forward 결과) │ │ 두 개 모두 인자로 전달 ▼ mlp.backward(cache, y) ──────────→ def backward(self, cache, y): x, a1, a2 = cache["x"], ... dL_da2 = a2 - y dW2 = np.outer(dL_da2, a1) ... ┌─────── return ←──── return {"dW1":..., "dW2":..., ...} ▼ grads = {...} ← 9개 편미분이 들어 있음 print(grads["dW2"]) ← 이런 식으로 꺼내 사용
왜 cache를 넘기나? backward는 forward에서 계산한 a1, a2 같은 중간값이 필요합니다. 그래서 forward가 끝나면 그 값들을 cache에 담아 돌려주고, backward 호출 시 다시 넘겨주는 것입니다. forward 결과를 재사용해서 backward가 빨라집니다.
8

`train` — 학습 루프

지금까지 본 forward와 backward는 한 번의 계산입니다. 학습은 이걸 수천 번 반복해서 가중치를 점점 좋게 만드는 과정입니다.

mlp_scratch.py train 메서드 (핵심 골격만) 
    def train(self, X, Y, epochs=10000, lr=0.1):
        for epoch in range(epochs):           # 10,000번 반복
            total_dW1 = np.zeros_like(self.W1)
            # ... 다른 gradient도 0으로 초기화

            for x, y in zip(X, Y):              # 4개 샘플 각각에 대해
                cache = self.forward_with_cache(x)  # ① forward
                grads = self.backward(cache, y)      # ② backward

                total_dW1 += grads["dW1"]            # gradient 누적
                # ... 다른 gradient도 누적

            # 평균 gradient로 가중치 업데이트
            N = len(X)
            self.W1 -= lr * total_dW1 / N        # ③ update
            # ... self.W2, self.b1, self.b2도 동일
학습은 단순한 3단계 반복
① forward — 예측
현재 가중치로 예측해본다.
② backward — 편미분 계산
예측이 얼마나 틀렸는지 보고, 각 가중치를 어떻게 바꿔야 할지 계산한다.
③ update — 가중치 갱신
self.W1 -= lr * gradient 로 가중치를 한 발짝 옮긴다.

업데이트 한 줄 풀어보기

학습의 본질이 들어 있는 한 줄:

self.W1 -= lr * total_dW1 / N

이걸 분해하면:

total_dW1 / N 4개 샘플의 gradient를 평균낸 값
lr * ... 학습률(보폭)만큼 곱함. 보통 0.1 ~ 0.5
self.W1 -= ... 그만큼 빼서 W1을 갱신

빼는 이유: gradient는 손실이 증가하는 방향을 가리킵니다. 우리는 손실을 감소시키고 싶으니 반대 방향(빼기)으로 움직입니다. 이게 gradient descent(10주차에서 배운 내용).

9

한 페이지 요약

MLP 클래스의 3개 핵심 메서드

메서드입력출력역할
__init__ (크기) — self.W1, b1, W2, b2 만들기
forward_with_cache x cache (dict) 예측 + 중간값 저장
backward cache, y grads (dict) 9개 편미분 계산
train X, Y, epochs, lr — 위 둘을 반복하며 가중치 업데이트

학습의 한 줄 요약

forward → backward → 가중치 업데이트   (10,000번 반복)

코드로 다시 쓰면:

for epoch in range(10000):
    for x, y in data:
        cache = mlp.forward_with_cache(x)
        grads = mlp.backward(cache, y)
    mlp.W1 -= lr * grads["dW1"]   # (실제로는 배치 평균)

이게 전부입니다. 이 단순한 반복이 XOR도 학습하고, 더 큰 네트워크에서는 이미지 분류까지 합니다.
