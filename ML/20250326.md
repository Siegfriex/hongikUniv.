## 1. 3강 복습 및 4강 개요

**3강 요약**
- **NumPy**: `ndarray`, 동질 dtype, 축(axis)·shape, 고속 벡터화 연산 — 머신러닝·과학 계산의 **수치 밑바닥**.
- **Pandas**는 3강에서 NumPy와 **역할을 구분**해 두었고, 4강에서는 그중 **표(tabular) 데이터**를 다루는 **Pandas**를 본격적으로 다룬다.

**4강에서 다룰 내용**
- **학습 순서**: 3강 **NumPy**에서 **1차원 → 2차원 → 다차원**으로 넓혀 갔듯, **Pandas**도 **Series(1차원)** → **DataFrame(2차원·표)** 순으로 익힌다.
- **통일된 관점**: 값의 **dtype**이 무엇이든, “**레이블이 달린 배열**(labeled array)”로 본다 — 1차원이면 **인덱스(행·원소 이름)** 가 붙고, 2차원이면 **행 인덱스 + 열 이름**이 붙는다.
- **실무**: 결측·정리, CSV, 시계열, `describe`, 그룹·필터, `pivot`·`concat`, 시각화.
- **EDA**: **타이타닉** 등으로 탐색 절차 연습.

## 2. Pandas란 무엇인가

- **Pandas**는 파이썬에서 **표 형태(tabular) 데이터**를 다루기 위한 **데이터 조작(manipulation) 패키지**이다.
- 데이터는 **행(row)과 열(column)** 으로 구성되며, 이런 구조를 **DataFrame**이라고 부른다.
- 직관적으로 **엑셀 시트 한 장**에 가깝게 생각할 수 있다.

**기능 예시**
- 데이터 **변환**: 행 정렬, 부분 집합(subset) 추출 등.
- **요약 통계**: 평균(mean) 등 집계.
- **형태 바꾸기(reshape)**: 피벗 등.
- **조인**: 여러 DataFrame을 **결합(join)**.

**함께 쓰는 생태계**
- **NumPy**: 수치 연산.
- **Matplotlib / Seaborn**: 시각화.
- **scikit-learn**: 머신러닝.

| 구분 | 역할 |
|------|------|
| NumPy | 배열·수치 연산 기반 |
| Pandas | 표 데이터·레이블·결측·그룹·시계열 |
| matplotlib / seaborn | 그래프 |
| scikit-learn | 학습·예측 파이프라인 |

**NumPy와 맞춰 보는 확장**

| | NumPy (3강) | Pandas (4강) |
|---|-------------|--------------|
| 1차원 | 1D `ndarray` (위치 0,1,2…) | **Series** — 1차원 + **레이블(index)** |
| 2차원·표 | 2D `ndarray` | **DataFrame** — 행·열 **레이블** + 열마다 dtype 달라도 됨 |
| 강조 | 동질 dtype, 축·shape, 벡터화 | **레이블**로 선택·집계·실무 표현 |

## 3. 데이터 구조: Series — import pandas as pd부터

가장 먼저 **임포트**한다. 관례적으로 **`pd`** 를 쓴다. `np.nan` 등과 **NumPy를 같이 쓰는 예제**에서는 `import numpy as np`를 함께 둔다.

```python
import pandas as pd
```

**시작점: 1차원 + 레이블**

- **Series**는 **한 줄(1차원)** 짜리 데이터에, 각 칸마다 붙는 **이름표(index)** 가 있는 구조다.
- NumPy 1D 배열이 “**위치(정수 인덱스)** 로만 구분”이라면, Series는 “**위치 + 의미 있는 레이블**”로 같은 1차원을 다룬다.
- **dtype**은 정수·실수·문자열·불리언 등 **무엇이든** 담을 수 있다(실무에서는 열마다 타입이 다른 표를 DataFrame으로 두지만, **Series 하나** 안에서는 보통 한 가지에 가깝게 쓴다).

**정의(공식적 한 줄)**

- **Series**는 **1차원 라벨이 붙은 배열**(one-dimensional labeled array)이다.

**실무 맥락**
- 분석에서는 “깨끗한 데이터”보다 **불완전·결측이 섞인 데이터**를 자주 다룬다.
- Pandas는 결측을 **탐지·처리**하는 함수를 제공한다.
- **`isna()`**: 각 원소가 결측(NaN 등)인지 **불리언**으로 반환한다.

**왜 NumPy 1D와 비슷하게 느껴지는가**

- 둘 다 **한 줄(1차원)** 로 값을 담고, **원소 단위 연산·슬라이싱**이 가능하다.
- **한 타입에 가깝게** 쓰는 점도 비슷하다: NumPy `ndarray`는 **동질 dtype**(한 배열 안에서 `int64`만, `float64`만 등). Series도 보통 **한 Series 안에 하나의 dtype**에 맞춘다(교재: *Supporting a single data type*).

**그런데 “전부 float만”이 NumPy의 특징은 아니다**

- NumPy는 **꼭 float만** 담는 것이 아니라, **`int64`, `bool`, `object`** 등 **정해진 dtype 하나**로 통일된 배열을 만든다. 수치 예제에서 float가 많이 나와서 그렇게 느낄 수는 있다.

**차이의 핵심은 dtype이 아니라 “인덱스가 무엇을 가리키느냐”**

| | NumPy 1D `ndarray` | Pandas `Series` |
|---|-------------------|-----------------|
| **위치** | 기본은 **0, 1, 2, …** 정수 **위치** | **정수 위치** + **별도의 index 레이블**(문자·날짜 등 가능) |
| **접근** | `arr[0]`, 슬라이스가 **항상 위치 기준** | `s[0]` / `s["a"]` / `s.loc[…]` — **레이블**로 직접 집을 수 있음 |
| **연산 정렬** | 같은 위치끼리 맞춤 | Series끼리 연산 시 **인덱스(레이블)를 기준으로 정렬·맞춤**(alignment) |

즉, “한 가지 dtype만 담는다”는 점은 비슷하지만, **NumPy는 값의 줄에 붙는 이름이 사실상 “몇 번째 칸인가”뿐**이고, **Series는 그 줄 옆에 붙는 “이름표(index)”가 데이터와 분리되어 있고, 그 이름표를 기준으로 고르고 합친다**는 점이 가장 큰 실무적 차이다. (결측 `NaN`을 일상적으로 다루는 방식도 Pandas 쪽이 더 분석 친화적이다.)

**인덱스(index) — 교재 요지**

- 축 방향의 레이블을 통틀어 **index**라고 부른다. (*The axis labels are collectively referred to as the index.*)
- `data`가 `ndarray`이면 **index 길이는 data와 같아야** 한다. (*If data is an ndarray, index must be the same length as data.*)
- index를 넘기지 않으면 **`[0, 1, …, len(data) - 1]`** 이 자동 생성된다. (*If no index is passed, one will be created having values [0, …, len(data) - 1].*)
- Series는 **고정 크기 딕셔너리**와 비슷하게, **index 레이블로 값을 get/set** 할 수 있다. (*A Series is also like a fixed-size dictionary in that you can get and set values by index label.*)

**레이블로 접근한다는 뜻**

- `index=` 로 **우리가 정의한 이름(`'a'`, `'b'`, … 또는 날짜 등)** 을 붙이면, **특정 원소(element)에 접근할 때** 정수 위치(`0`, `1`, …)뿐 아니라 **그 레이블**을 써서 골라낼 수 있다.
- 즉 **“인덱스(여기서는 레이블)”가 가리키는 칸의 데이터**에 붙인 이름으로 접근하는 것이다. (`s["a"]` ↔ 딕셔너리의 `dict["a"]`와 같은 읽기 습관.)

**생성·접근 예제**

```python
import numpy as np
import pandas as pd

# (1) 기본 — 인덱스 생략 시 0, 1, 2, …
s1 = pd.Series([10, 20, 30])
# s1[0] → 10

# (2) 레이블 명시 — 의미 있는 index로 접근
s2 = pd.Series([10, 20, 30], index=["a", "b", "c"])
# s2["b"] → 20  (또는 s2.loc["b"])

# (3) 딕셔너리 — key가 index
s3 = pd.Series({"서울": 9, "부산": 15, "제주": 3})

# (4) 결측(np.nan) 포함 — 정수와 NaN이 섞이면 Series는 보통 float64로 올림(승격)
data = [1, 2, np.nan, 4]
indexed_se = pd.Series(data, index=["a", "b", "c", "d"])
print(indexed_se)
# a    1.0  /  b    2.0  /  c    NaN  /  d    4.0  ;  dtype: float64

indexed_se["a"], indexed_se["b"]  # (1.0, 2.0) — 레이블 'a', 'b'로 접근
```

- **리스트 + `index=`**: 값 순서와 레이블 순서를 **한 줄씩 짝지어** 만든다(강의 도표: 왼쪽 열 index, 오른쪽 열 data).

**딕셔너리와의 대응 — 키→index, 값→data**

- 파이썬 관점에서 Series는 **키(key)·값(value) 쌍**으로 익숙한 **딕셔너리**와 잘 맞물린다.
- **`dict`의 key** → Series의 **index(레이블)**  
- **`dict`의 value** → Series의 **data(각 원소의 값)**  
- 교재 슬라이드의 *key → index, value → data* 가 바로 이 대응이다. `pd.Series(딕셔너리)`를 쓰면 **별도로 `index=`를 주지 않아도** key가 곧 index가 된다.

```python
# 예: 월별 매출 — key가 월 이름(index), value가 금액(data)
income = {"1월": 9500, "2월": 6200, "3월": 6050, "4월": 7000}
income_se = pd.Series(income)
# 1월   9500
# 2월   6200
# 3월   6050
# 4월   7000
# dtype: int64

# 간단한 대응 확인
d = {"b": 1, "a": 0, "c": 2}
pd.Series(d)
# b    1
# a    0
# c    2
# dtype: int64
```

- 고정 크기 딕셔너리 비유는, **읽기·쓰기를 레이블로 한다**는 점에서 같지만, Series는 **정수 위치·슬라이스·벡터 연산** 등 배열 쪽 연산도 함께 쓴다는 점에서 dict보다 넓다.

**집계(aggregation) — Aggregation functions**

- Series **안에** 요약·통계를 위한 **메서드**가 들어 있다. 그래서 **다른 라이브러리 함수를 따로 부르지 않고도**, 객체에 붙인 **`.max()`**, **`.mean()`** 등으로 **같은 Series 데이터**를 바탕으로 값을 구할 수 있다. (교재: *Example of computing max and mean of series data.*)
- 대표 예: **`max()`** (최댓값), **`mean()`** (산술 평균). 이외에도 `sum()`, `min()`, `count()`, `std()` 등이 같은 방식으로 쓰인다.

```python
# 앞서 만든 income_se(월별 수익 Series)를 그대로 사용
print(
    "월 최대 수익:",
    income_se.max(),
    ", 월 평균 수익:",
    income_se.mean(),
)
# 월 최대 수익: 9500 , 월 평균 수익: 7187.5
```

- **NumPy 함수**(`np.max(s.values)` 등)로도 구할 수 있지만, 강의에서는 **Pandas Series 메서드**로 끝내는 패턴을 강조한다.

**다음 단계**

- **Series**로 “**레이블 달린 1차원**”에 익숙해지면, 같은 원리가 **행·열 두 축**으로 확장된 것이 **DataFrame**(§4)이다.

## 4. 데이터 구조: DataFrame

**1차원(Series)에서 2차원(DataFrame)으로**

- Series가 **한 줄의 레이블 + 값**이었다면, DataFrame은 **행과 열**이 있는 **표(2차원)** 이다. 같은 데이터를 **여러 변수(열)** 로 나란히 두고 싶을 때 쓴다.

**정의 (교재)**

- *DataFrame is a 2-dimensional labeled data structure with columns of potentially different types.*  
- **2차원**이며 **레이블이 붙은** 구조이고, **열(column)마다 dtype이 서로 달라도** 된다(한 열은 문자, 한 열은 정수 등).

**`index` / `columns` 인자 — 행·열 레이블 부여**

- 데이터만 넘기지 않고, **`index`(행 레이블)**, **`columns`(열 레이블)** 을 **선택적으로** 넘길 수 있다. (*Along with the data, you can optionally pass index (row labels) and columns (column labels) arguments.*)
- **행**에 붙는 이름 → **`index`**  
- **열**에 붙는 이름 → 생성 시에는 보통 **딕셔너리의 key** 또는 **`columns=`** 로 준다.  
→ 즉 **로우(행)와 컬럼(열) 모두**에 대해 **이름을 부여**할 수 있다.

**Series 딕셔너리로 생성 — Generation of DataFrame from dictionary of Series**

- **딕셔너리의 key** → **열 이름(column label)**  
- **딕셔너리의 value** → **그 열을 이루는 Series**(같은 길이면 행이 맞춰진다).

```python
month_se = pd.Series(["1월", "2월", "3월", "4월"])
income_se = pd.Series([9500, 6200, 6050, 7000])
expenses_se = pd.Series([5040, 2350, 2300, 4800])

df = pd.DataFrame({"월": month_se, "수익": income_se, "지출": expenses_se})
df
#    월    수익    지출
# 0  1월   9500   5040
# 1  2월   6200   2350
# 2  3월   6050   2300
# 3  4월   7000   4800
# 행 index는 생략 시 0, 1, 2, … 가 자동 부여된다.
```

- 노트북(Jupyter)에서는 마지막에 `df`만 적으면 **HTML 표**로 보기 좋게 나오고, **`print(df)`** 는 **텍스트**로 찍힌다. 둘을 바꿔 가며 출력 형식을 비교해 보면 된다.

**행 index를 명시하는 예**

```python
pd.DataFrame(
    {"월": month_se, "수익": income_se, "지출": expenses_se},
    index=["Q1-1", "Q1-2", "Q1-3", "Q1-4"],
)
```

**실무에서는: CSV → DataFrame이 중심**

- 앞에서는 이해를 위해 **Series를 붙여** `DataFrame`을 직접 만들었다. 그러나 **데이터 분석**을 목표로 할 때는, 보통 **공개 데이터셋·기관 파일·다운로드한 표**를 **파일 형태(대표적으로 CSV)** 로 받아 **`DataFrame`으로 변환**하는 흐름이 **주안**이 된다.
- *Pandas can convert .csv files directly into dataframes.* — **`pd.read_csv()`** 한 번으로 표를 읽어 온다.

**CSV란**

- **CSV** = **comma separated values**(쉼표로 구분된 값). 텍스트로 저장된 표 형식이라 **어디서나** 많이 쓰인다. (교재 표기 *comma separated variables* 와 같은 의미로 이해하면 된다.)

```python
# 원격 저장소(URL)에서 읽기
path = "https://github.com/dongupak/DataML/raw/main/csv/"
file = path + "vehicle_prod.csv"
df = pd.read_csv(file)  # 원격지 CSV를 읽어 DataFrame으로

# 로컬 파일(경로는 본인 PC 환경에 맞게)
# df = pd.read_csv(r"D:\data\vehicle_prod.csv")

print(df)
```

**추가 매개변수 없이 읽을 때 — 첫 행 = 열 이름**

- `read_csv()`에 **아무 옵션도 주지 않아도**, Pandas는 CSV **첫 번째 줄을 헤더**로 보고 **열 이름(columns)** 을 만든다. 즉 파일 안에서 **첫 행이 열 방향 정렬(컬럼 정의)** 에 쓰인다.
- **행 방향 index**는 별도 지정이 없으면 **`0, 1, 2, …`** 가 자동으로 붙는다(슬라이드: *자동으로 생성된 index*).

**읽은 뒤의 모습(예: `vehicle_prod.csv`)**

- 메모장으로 열면 첫 줄이 `,2007,2008,2009,2010,2011` 처럼 **맨 앞에 쉼표만 있고** 첫 열 헤더가 비어 있는 경우가 있다. 그러면 첫 번째 데이터 열이 **`Unnamed: 0`** 으로 붙고, 국가명(China, EU, …)이 **그 열의 값**으로 남는다. **행 index**는 여전히 `0 … 5` 같은 정수다.

**DataFrame의 index와 columns (교재)**

- *Dataframe has index (for row) and columns (for columns).*  
- **행**을 가리키는 이름 → **index**  
- **열**을 가리키는 이름 → **columns**  
- 읽기 직후 **`df.columns`**, **`df.index`** 로 무엇이 잡혔는지 확인하는 습관이 좋다.

**`index_col=0` — 첫 번째 열을 “행 index”로 (가장 기본에 가까운 패턴)**

- *If you give Pandas' `read_csv()` function a keyword parameter named `index_col` with an argument of `0`, the first column will be used as the index.*  
- 즉 **같은 CSV**라도, **`index_col=0`** 을 주면 **첫 번째 열**이 더 이상 “데이터 열”이 아니라 **행 레이블(index)** 로 올라간다. 국가명 같은 **식별자 열**이 있을 때 이렇게 읽는 경우가 많다. **실무에서 `read_csv`와 함께 가장 먼저 쓰게 되는 옵션 중 하나**로 보면 된다.

```python
df = pd.read_csv(file, index_col=0)
print(df)
# 행: China, EU, US, … / 열: 2007, 2008, … — 첫 열이 index로 승격된 모습
```

**불러온 뒤 구조 확인**

```python
df.columns
# Index(['2007', '2008', '2009', '2010', '2011'], dtype='object')  # 연도만 열 이름

df.index
# Index(['China', 'EU', 'US', 'Japan', 'Korea', 'Mexico'], dtype='object')  # 국가가 행 index
```

- **`index_col=0` 전**: `df.columns` 에 `Unnamed: 0` 이 섞이고, `df.index` 는 `RangeIndex(0, 6, …)` 에 가깝다.  
- **`index_col=0` 후**: **열**은 연도 등만 남고, **행**은 국가명이 index로 바뀐다 — 슬라이드 그림과 같은 **변환**이다.

**여기서 “기본”이라고 한 것과, 진짜로 중요한 것**

- 앞에서 **`index_col=0` 을 “기본에 가까운 옵션”** 이라고 한 것은, **읽기 패턴으로 자주 등장한다**는 뜻에 가깝다. **행 index(몇 번째 행인지·행 이름)** 가 모든 분석에서 항상 최우선 이슈는 아닐 수 있다.
- 반대로 **수천·수만 건**을 넘어가는 **대용량 데이터셋**을 다룰 때는, **각 컬럼에 무엇이 들어 있는지**(변수 이름, 의미, 단위, 범주형인지 수치인지, 결측 비율)를 **먼저** 파악하는 일이 **훨씬 더 중요**하다. 행이 아무리 많아도 **열을 잘못 해석하면** 이후 분석·모델이 전부 틀어진다.
- 그래서 실무에서는 **`df.columns`**, **`df.info()`**, **`head()`** / **`sample()`** 등으로 **열 스키마와 표본 몇 줄**을 익히는 단계를 **가장 먼저** 밟는다.

**인덱싱·열 연산** — 구체적인 선택·집계는 [§5 인덱싱과 선택 — 데이터 탐색](#5-인덱싱과-선택--데이터-탐색)에서 이어진다.

**`DataFrame.drop()` — 불필요한 행·열을 제거할 때**

- **DataFrame** 객체가 붙는 메서드 **`drop()`** 은 **이름(label)으로 지정한 행 또는 열을 삭제한 결과**를 만든다. (`pandas.DataFrame.drop`)
- 자주 쓰는 인자:
  - **첫 번째 인자(또는 `labels=`)**: 삭제할 **행 이름** 또는 **열 이름**(문자열·리스트).
  - **`axis`**: `0`(또는 `'index'`)이면 **행**, `1`(또는 `'columns'`)이면 **열** 방향으로 삭제.
  - **`inplace`**: 아래에서 설명 — **`drop()`과 함께 쓸 때** “원본 `df`를 바꿀지, 새 표만 받을지”가 갈린다.

**불러온 데이터셋 조작 — 결과만 쓸지, 원본을 남길지, 원본을 바꿀지**

- `read_csv`로 읽은 **`df`** 는 **그대로 두고** 가공한 **결과만** 쓰고 싶을 수도 있고, **원시(raw) 데이터**를 변수에 **그대로 보관**해 두고 실험만 새 객체로 할 수도 있다. 반대로 **원본 객체 안의 값 자체를 바꿔** 다음 단계까지 **같은 이름(`df`)** 으로 이어 가야 할 때도 있다.
- **`drop()`** 에서도 **`inplace`** 가 그 역할을 나눈다. (*If `True`: update an existing dataframe … If `False`: return the updated dataframe, leaving the existing dataframe intact.*)

| `inplace` | `df.drop(...)` 의 동작 |
|-----------|-------------------------|
| **`False`** (기본) | **열/행이 빠진 새 DataFrame**을 **반환**한다. **`df`는 그대로** — “삭제한 결과만 가져가기”에 적합하다. |
| **`True`** | **반환값에 의존하지 않고**, 호출한 **`df`(또는 `d_df`)** 의 **내용이 직접 갱신**된다. 같은 변수가 가리키는 표가 **실제로 줄어든다**. |

**예: `DataFrame.drop()` + `inplace` 연동 (열 `B` 삭제, `axis=1`)**

```python
d_df = pd.DataFrame(
    data=[[10, 20, 30, 40], [50, 60, 70, 80]],
    columns=["A", "B", "C", "D"],
)

# drop(..., inplace=False) — DataFrame.drop 메서드가 "새 표"를 반환
new_df = d_df.drop("B", axis=1, inplace=False)
print(new_df)   # A, C, D 열만
print(d_df)     # A, B, C, D — 변경 없음

# drop(..., inplace=True) — d_df 자체에서 B 열이 제거됨 (제자리 수정)
d_df.drop("B", axis=1, inplace=True)
print(d_df)     # A, C, D 만 남음
```

- **`inplace=True`** 를 쓰면 **`drop()`** 은 보통 **`None`** 을 반환하므로, **`d_df = d_df.drop(..., inplace=True)`** 처럼 **대입으로 결과를 받으려 하면 안 된다** — **객체는 이미 `d_df` 안에서 바뀐 상태**다.
- 다른 메서드(`rename`, `fillna` 등)도 **`inplace`** 가 같은 **패턴**으로 동작하는 경우가 많다. 여기서는 **`drop()`** 으로 연습한다.

**한 줄 요약**: **`drop(..., inplace=False)`** → **새 DataFrame만 반환·원본 유지** / **`drop(..., inplace=True)`** → **`drop`을 호출한 그 DataFrame을 제자리에서 수정**.

## 5. 인덱싱과 선택 — 데이터 탐색

**여기서부터 데이터 탐색이 본격적으로 시작된다**

- `read_csv`로 **`df`** 를 만든 뒤, **무엇이 반환되는지**(한 열은 Series인지, 여러 열은 DataFrame인지), **열 이름 목록**, **특정 열의 값들**을 짚는 것부터가 탐색이다.
- 슬라이드: *Indexing with column value* — **열 이름으로 인덱싱**해 부분을 꺼낸다. *Operation with indexing* — 꺼낸 부분에 **연산**을 걸어 **새 열**(`total`, `mean` 등)로 **인사이트**를 붙일 수 있다.

### 5.1 열 하나 꺼내기 — `df['열이름']`

- **한 열**만 고르면 자료형은 **`Series`** 이다(행 index는 그대로 유지).

```python
# 2007년 열만 — 국가별 값이 Series로 반환
df["2007"]
# China     7.71
# EU       19.02
# ...
# Name: 2007, dtype: float64
```

### 5.2 열 이름·값을 리스트로 — `tolist()`

- **`df.columns.tolist()`** — 열 이름들을 **파이썬 리스트**로 받는다. 스키마 확인·반복문에 쓰기 좋다.
- **`df["2007"].tolist()`** — 그 열의 **값만** 리스트로 받는다.

```python
df.columns.tolist()
# ['2007', '2008', '2009', '2010', '2011']

df["2007"].tolist()
# [7.71, 19.02, 10.47, 10.87, 4.04, 2.01]
```

### 5.3 행 방향 집계로 새 열 만들기 — `total`, `mean` 등

- 연도별 열 **`2007`~`2011`** 이 **같은 행(국가)** 에 대해 이어져 있을 때, **행마다** 합·평균을 내려 **새 컬럼**으로 붙일 수 있다.
- **`axis=1`**: 열을 따라가며 **한 행씩** 집계한다(슬라이드의 *sum/mean per row*).

```python
year_cols = ["2007", "2008", "2009", "2010", "2011"]
df["total"] = df[year_cols].sum(axis=1)
df["mean"] = df[year_cols].mean(axis=1)
print(df)
# total: 연도별 생산량(예시 데이터)의 행별 합, mean: 행별 평균
```

- 이렇게 **기존 열에서 파생된 열**을 추가하면, 뒤에서 정렬·시각화·모델 피처로 이어 가기 쉽다 — 슬라이드에서 말하는 **인사이트용 컬럼** 추가에 해당한다.

### 5.4 Indexing and selection — `.loc`, `.iloc`, 불리언

슬라이드 **Indexing and selection** 은 “**어떤 행·열을 집을지**”를 명확히 하는 도구다.

**`.loc` — 레이블(이름)으로 고른다**

- **행 index**나 **열 이름**이 **문자·날짜 등 “이름”** 일 때 쓴다. `index_col=0` 으로 **국가명이 행 index**이면, 한 나라만 보려면 **`df.loc["Korea"]`** 처럼 **레이블**로 직접 집는다. 결과는 **그 행 하나**이면 **Series**다.

```python
df.loc["Korea"]
# 2007    4.04
# 2008    3.78
# ...
# Name: Korea, dtype: float64
```

**`.iloc` — 정수 위치(0, 1, 2, …)로 고른다**

- **몇 번째 행·열인지**만 쓸 때. **이름이 아니라 순서**에 의존하므로, 데이터가 **정렬·필터**된 뒤에는 **같은 숫자가 다른 행**을 가리킬 수 있어 주의한다. “**정수 위치**”가 필요하면 **`iloc`**, “**붙어 있는 이름**”이면 **`loc`** 이라고 구분하면 된다.

```python
df.iloc[4]   # 5번째 행(0부터 세면 4) — 위와 다른 방식
```

**불리언 마스크 — 조건에 맞는 행만**

- **True/False** 로 이루어진 벡터(Series, 행 길이와 같음)를 **`df[조건]`** 에 넣으면, **True인 행만** 남긴 **DataFrame**이 된다.

```python
df[df["2009"] > 5]   # 2009년 값이 5 초과인 행만
```

**정수(`iloc`)·슬라이스**

- **`iloc`에 정수 하나** — `df.iloc[0]` 은 **한 행** → **Series**(열 이름이 index가 됨). `df.iloc[0, 1]` 처럼 **행·열 위치**를 같이 주면 **스칼라**.
- **`iloc`에 슬라이스** — `df.iloc[0:2]` 는 **0~1행** → **DataFrame**. `df.iloc[0:2, 0:3]` 은 **부분 표** → **DataFrame**.
- **행만 슬라이스 (`[]`)** — `df[0:3]` 은 **행 방향**으로 잘라낸다(기본 index가 `0,1,2…` 일 때 앞에서 연속된 행). → **DataFrame**.
- **Series** 에서는 `s[0]` 은 **한 칸**(스칼라에 가깝게), `s[0:3]` 은 **구간** → **Series**가 그대로 이어진다.

**Series냐 DataFrame이냐 — 결과 타입이 달라지는 경우**

| 대상 | 문법 | 반환 |
|------|------|------|
| **Series** | `s[i]` (정수·레이블 한 개) | **스칼라** 또는 한 값 |
| **Series** | `s[0:3]`, `s["a":"c"]` (슬라이스) | **Series** |
| **DataFrame** | `df["2007"]` (열 이름 **문자열 하나**) | **Series** (그 열) |
| **DataFrame** | `df[["2007"]]` (열 이름을 **리스트**로) | **DataFrame** (열이 하나여도 **2차원** 유지) |
| **DataFrame** | `df.iloc[0]` (행 **한 줄**) | **Series** |
| **DataFrame** | `df.iloc[[0]]` (행을 **리스트로**) | **DataFrame** (한 행만 있어도 **표** 형태) |
| **DataFrame** | `df[0:2]`, `df.iloc[0:2]` (행 **여러 줄**) | **DataFrame** |
| **DataFrame** | `df[불리언_Series]` | **DataFrame** |

- 요약: **한 줄·한 열을 “벡터(Series)”로** 받을지, **표(DataFrame)로** 남길지는 **`[]` 안이 스칼라 vs 리스트**, **`iloc`에 정수 vs 리스트** 같은 **문법 차이**로 갈린다. **후속 연산**(다른 메서드에 넘길 때 차원 맞추기)에서 자주 헷갈리므로, **`type(...)`** 이나 **`.shape`** 로 한 번 확인하는 습관이 좋다.

**교재 요약 표**

| Operation | Syntax | Result |
|-----------|--------|--------|
| 열 하나 선택 | `df[col]` | **Series** |
| **행** — 레이블 | `df.loc[label]` | **Series** |
| **행** — 정수 위치 | `df.iloc[loc]` | **Series** |
| 행 슬라이스 | `df[5:10]` | **DataFrame** |
| **불리언**으로 행 선택 | `df[bool_vec]` | **DataFrame** |

**왜 중요한가 — 향후 큰 데이터셋에서**

- 행·열이 커질수록 **전체를 한꺼번에** 만지기보다, **어떤 행을 건드릴지·어떤 컬럼만 쓸지**를 먼저 정하는 일이 중요하다. **`.loc` / `.iloc` / 불리언**으로 **대상만** 잘라 내면, 분석 범위를 통제하고 **메모리·실수**를 줄일 수 있다.

### 5.5 정리

| 하고 싶은 것 | 예시 |
|--------------|------|
| 한 열만 Series로 | `df["2007"]` |
| 모든 열 이름 | `df.columns`, `df.columns.tolist()` |
| 한 열의 값만 리스트로 | `df["2007"].tolist()` |
| 행마다 합·평균 열 추가 | `df[year_cols].sum(axis=1)`, `.mean(axis=1)` |
| 행 한 줄 (이름) | `df.loc["Korea"]` |
| 행 한 줄 (순서) | `df.iloc[n]` → Series / `df.iloc[[n]]` → DataFrame |
| 열 하나인데 DataFrame으로 | `df[["2007"]]` |
| 행·열 슬라이스 | `df.iloc[0:2, :]`, `df[0:2]` |
| 조건 맞는 행만 | `df[df["열"] > 값]` |

**데이터 탐험(EDA)의 출발점 — raw CSV를 받았을 때**

- 지금까지 다룬 흐름(**`read_csv`**, **`index_col`**, **인코딩**, **`head`**, **`info`**, **`shape`**, **`describe`**, **인덱싱·`.loc`/`.iloc`**, **`drop`/`inplace`**, **`plot`** 등)은 **특정 로(raw) CSV를 받은 직후** 공통으로 밟는 **탐색의 첫 단계**를 가리킨다.
- 그때 던지는 질문은 한 가지다: **「이 데이터가 무엇인가?」** — 행·열 이름, 타입, 규모, 값의 범위, 결측, 이상한 패턴을 **모델에 넣기 전에** 먼저 익히는 일이 **탐색의 시작점**이다. (이후 §13 EDA·타이타닉은 같은 정신으로 범위를 넓힌다.)

## 6. 시계열 데이터 분석

**CSV 읽기 → DataFrame 생성**

- 이 절의 **시계열 예제(`weather`)**는 위 **출발점**을 **날짜 index·한글 컬럼**이 있는 CSV에 적용한 사례다.
- 시계열 분석은 보통 **CSV를 읽어 DataFrame을 만드는 것**부터 시작한다.
- 한국어 헤더/값이 섞인 파일은 인코딩을 지정해야 깨지지 않는다(예: `encoding='cp949'`, `'utf-8'`).

```python
path = "https://github.com/dongupak/DataML/raw/main/csv/"
weather_file = path + "weather.csv"

weather = pd.read_csv(weather_file, index_col=0, encoding="cp949")
print(weather.head(3))
print("weather 데이터 shape :", weather.shape)
```

- `index_col=0`을 주면 첫 열(예: 날짜/일시)을 행 index로 쓴다.
- `shape`로 전체 크기(행, 열)를 바로 확인할 수 있다. 예: `(365, 3)`.

**모든 컬럼 정보 확인: `info()`**

- **`weather.info()`** 는 컬럼별 `dtype`, non-null 개수, 메모리 사용량을 한 번에 보여 준다.
- “전체 컬럼에 대해 어떤 데이터가 들어 있는지”를 빠르게 파악하는 기본 단계다.

**처음 몇 줄 확인: `head()`가 왜 유용한가**

- **`head()`** 는 데이터의 앞부분 샘플을 보여 준다. (기본 5행, `head(3)`처럼 개수 지정 가능)
- 컬럼명 오타, 인코딩 깨짐, 날짜/숫자 파싱 문제, 단위 이상치 같은 **초기 품질 이슈**를 초반에 잡아낸다.
- 즉 `head()`는 “분석 전 **데이터가 기대대로 읽혔는지**”를 확인하는 가장 빠른 체크포인트다.

**분포·특성을 더 알고 싶을 때 — 왜 “컬럼”이 중요한가**

- `head()`·`info()`로 **대략적인 구조**를 알았다면, 다음은 **각 변수가 어떤 분포를 갖는지**(크기·퍼짐·이상치 단서)를 보고 싶은 단계다.
- 데이터 분석에서 가장 자주 붙잡는 단위는 **행**이 아니라 **열(column)** 이다. 표를 설계할 때 **변수(특징)** 를 **열로 정의**하기 때문이다. **단일 변수**(한 열의 분포)·**복수 변수**(여러 열의 관계) 논의도 결국 **어떤 컬럼을 보느냐**에서 출발한다.

**`describe()` — 기술통계로 컬럼별로 요약**

- *`describe()`: method for descriptive statistics.*
- **기술통계(descriptive statistics)** 는 데이터 분포의 **중심 경향(central tendency)**, **퍼짐(dispersion)**, **분포의 모양(shape)** 을 요약하는 값들을 말한다. **`NaN`은 제외**하고 계산한다(슬라이드: *excluding NaN values*).
- **`DataFrame.describe()`** 는 기본적으로 **수치형(float/int) 열만** 골라, **열 하나당 한 줄씩**이 아니라 **열을 컬럼으로 둔 요약 표**를 반환한다 — 즉 **변수(컬럼)별**로 한 번에 비교하기 좋다.

```python
print(weather.describe())
```

- **`weather`** 예처럼 `평균기온`, `최대풍속`, `평균풍속`이 모두 **수치 변수**이면 `describe()`가 바로 의미 있다.
- 출력에서 **`count`** 를 열마다 비교하면 **결측 개수 차이**를 짐작할 수 있다(예: 한 열의 `count`가 더 작으면 그 열에만 `NaN`이 더 많다).
- **`mean`**, **`std`**, **`min`**, **`25%` / `50%`(중앙값) / `75%`**, **`max`** 로 **범위·중심·사분위**를 보면, 극단값·왜도에 대한 **감**을 잡을 수 있다.

**`mean()`, `std()`**

- 열(Series) 또는 `DataFrame`에 대해 **평균·표준편차만** 따로 쓸 때도 많다. `describe()` 한 번으로 비슷한 정보가 나오지만, **특정 열만** 빠르게 찍을 때는 `weather["평균기온"].mean()` 같은 식도 자주 쓴다.

## 12. 시각화: `plot()`으로 차트

**데이터 자체에서 `plot()` — 별도로 그래프 객체만 조립하지 않고**

- Pandas의 **`plot()`** 은 **Matplotlib** 위에 얹힌 **편의 메서드**다. **DataFrame**에도 **`Series`** 에도 붙어 있어, **표에서 뽑은 한 열(`df['2009']` 등)** 에 대해 **바로 막대·파이·선** 등을 그릴 수 있다. (*Visualizing a data frame with the `plot()` method* — 열 하나를 고르면 그 결과는 **Series**이므로 실무에서는 `Series.plot`과 `DataFrame.plot`을 함께 쓴다고 보면 된다.)

**`kind` — 어떤 차트인지**

- **`kind='bar'`**: 세로 막대, **`kind='pie'`**: 파이 차트, **`kind='line'`** 등 — 종류를 문자열로 넘긴다.

```python
# 2009년 열만 Series로 — index가 국가명이면 막대/파이의 눈금·조각 이름이 된다
df["2009"].plot(
    kind="bar",
    color=("orange", "r", "b", "m", "c", "k"),
)
# df["2009"].plot(kind="pie")
```

- **`color`**: 막대마다 색을 다르게 줄 때 튜플 등으로 넘길 수 있다(슬라이드 예).
- **막대 그래프**에서는 **가로축**이, **파이 차트**에서는 **조각 라벨**이 **Series의 index**에서 온다. 그래서 앞에서 **`index_col=0`** 으로 읽어 **행 index를 국가명**으로 두면, 그림 축·범례가 **바로 의미 있게** 나온다.

**환경**

- **Jupyter** 등에서는 실행 후 **그림이 셀 아래에 표시**된다. 스크립트(`.py`)에서는 **`import matplotlib.pyplot as plt`** 후 **`plt.show()`** 가 필요할 수 있다.

**용도**

- **탐색(EDA)**: 한 해·한 변수의 **크기 비교**(막대), **비율 감각**(파이), 추세(선) 등을 **빠르게** 본다 — 본격 **Seaborn**·축 커스텀 전에 **감 잡기**에 좋다.

## 13. 탐색적 데이터 분석(EDA)

**Exploratory Data Analysis (EDA)** 는 **초기 데이터 조사**에 쓰는 **통계적 접근**이다.

**목적(슬라이드)**
- **패턴 발견**(pattern discovery), **이상 탐지**(anomaly detection), **가설 검정**(hypothesis testing) 등.
- 데이터의 **구조**를 이해하고, **모델 선택**을 돕고, **추가 연구·분석 방향**을 찾는다.
- **분포와 값**을 살펴보면, 데이터가 담는 **현상**을 더 잘 이해하고 **잠재적 문제**(결측 등)를 짚을 수 있다.
- 문제 정의 단계에서 드러나지 않았던 **다양한 패턴**을 발견할 수 있다.

**체크리스트(슬라이드)**
1. 분석 **목적**과 관련 **변수**를 명확히 한다.
2. 데이터 **전체**를 살편다(이상치·**결측** 등).
3. **개별 속성** 값의 분포·특성을 관찰한다.
4. 속성 **사이의 관계**에 초점을 맞춘다(**상관**, **시각화**).

| 단계 | 내용 |
|------|------|
| 목적·변수 | 무엇을 밝힐지, 어떤 열이 관련 있는지 |
| 전체 점검 | 행·열 수, 결측, dtype |
| 개별 속성 | 히스토그램, 요약통계, 범주별 비율 |
| 관계 | 산점도, 상관행렬, 교차표 등 |

## 17. 개별 속성 관측: 생존율·박스플롯

**범주별 평균 생존율** — `groupby(...).mean()` 후 **가로 막대(`barh`)**, x축 `[0, 1]`로 **생존 비율**을 비교한다.

```python
import matplotlib.pyplot as plt

figbi, axesbi = plt.subplots(2, 4, figsize=(16, 10))
titanic.groupby("pclass")["survived"].mean().plot(kind="barh", ax=axesbi[0, 0], xlim=[0, 1])
titanic.groupby("sibsp")["survived"].mean().plot(kind="barh", ax=axesbi[0, 1], xlim=[0, 1])
titanic.groupby("parch")["survived"].mean().plot(kind="barh", ax=axesbi[0, 2], xlim=[0, 1])
titanic.groupby("sex")["survived"].mean().plot(kind="barh", ax=axesbi[0, 3], xlim=[0, 1])
titanic.groupby("embarked")["survived"].mean().plot(kind="barh", ax=axesbi[1, 0], xlim=[0, 1])
sns.boxplot(x="survived", y="age", data=titanic, ax=axesbi[1, 1])
sns.boxplot(x="survived", y="fare", data=titanic, ax=axesbi[1, 2])
plt.tight_layout()
plt.show()
```

- **연속형 age, fare**는 **박스플롯**으로 생존(0/1) 집단 간 **분포 차이**를 본다.

## 19. 해석: 성별·객실 등급·요금

슬라이드에서 강조한 **정성 해석**(영문 표현은 슬라이드에 맞춤):

- **성별(sex)**  
  - 남성 **생존율은 대략 20% 전후**, 여성은 **약 75%** 수준으로 관찰되는 예시가 제시된다.  
  - → **성별과 생존** 사이에 **강한 관계**가 있다고 해석할 수 있다.

- **객실 등급(pclass)**  
  - **1등급** 승객은 생존율이 **약 60%** 부근, **3등급**은 **약 22%** 부근 등으로 비교된다(대략적 수치는 그래프·표에 따름).  
  - → **등급이 높을수록 생존율이 높은 경향**이 뚜렷하다.

- **운임(fare)**  
  - 박스플롯 등으로 **생존 그룹과 요금 분포**가 다소 다름이 보이면, **요금과 생존** 사이에 **어느 정도 관계**가 있다고 볼 수 있다(슬라이드: *marginal relationship*).

## 20. 변수 간 관계: 상관행렬·히트맵

**수치형만** 골라 **피어슨 상관계수 행렬**을 구하고 **히트맵**으로 시각화한다.

```python
import numpy as np

numeric_data = titanic.select_dtypes(include=[np.number])
corr = numeric_data.corr()

plt.figure(figsize=(12, 10))
sns.heatmap(corr, annot=True, fmt=".2f", cmap="coolwarm")
plt.title("Correlation Matrix Heatmap")
plt.show()
```

**슬라이드에서 짚는 관계(표현은 원문 의도 유지, 철자만 정리)**

- **Fare ↔ Survived**: **양(+)의 상관** — 운임이 높을수록 생존과 함께 움직이는 경향.
- **Pclass ↔ Survived**: **음(-)의 상관** — 등급 숫자가 클수록(3등) 생존과 반대 방향으로 해석되기 쉬움(변수 정의에 따라 부호 해석 주의).
- **Fare ↔ Pclass**: **음(-)의 상관** — 등급이 높을수록(1등) 요금이 높으므로 등급 인코딩과 요금의 관계와 일관되게 읽는다.
- **Age ↔ Pclass**: **음(-)의 상관** 등이 언급된다 — 나이·등급 구조가 데이터 안에서 어떻게 겹치는지 **참고용**으로 본다.

> 상관계수는 **선형 관계**만 요약하며, **인과**를 뜻하지 않는다. 범주 변수는 원핫 인코딩 등으로 바꾼 뒤 상관을 보는 식으로 확장할 수 있다.
