## 1. 3강 복습 및 4강 개요

**3강 요약**
- **NumPy**: `ndarray`, 동질 dtype, 축(axis)·shape, 고속 벡터화 연산 — 머신러닝·과학 계산의 **수치 밑바닥**.
- **Pandas**는 3강에서 NumPy와 **역할을 구분**해 두었고, 4강에서는 그중 **표(tabular) 데이터**를 다루는 **Pandas**를 본격적으로 다룬다.

**4강에서 다룰 내용**
- **학습 순서**: 3강 **NumPy**에서 **1차원 → 2차원 → 다차원**으로 넓혀 갔듯, **Pandas**도 **Series(1차원)** → **DataFrame(2차원·표)** 순으로 익힌다.
- **통일된 관점**: 값의 **dtype**이 무엇이든, “**레이블이 달린 배열**(labeled array)”로 본다 — 1차원이면 **인덱스(행·원소 이름)** 가 붙고, 2차원이면 **행 인덱스 + 열 이름**이 붙는다.
- **실무**: 결측·정리, CSV, 시계열, `describe`, 그룹·필터, `pivot`·`concat`, 시각화.
- **EDA**: **타이타닉** 등으로 탐색 절차 연습.

## 2. Pandas란 무엇인가

- **Pandas**는 파이썬에서 **표 형태(tabular) 데이터**를 다루기 위한 **데이터 조작(manipulation) 패키지**이다.
- 데이터는 **행(row)과 열(column)** 으로 구성되며, 이런 구조를 **DataFrame**이라고 부른다.
- 직관적으로 **엑셀 시트 한 장**에 가깝게 생각할 수 있다.

**기능 예시**
- 데이터 **변환**: 행 정렬, 부분 집합(subset) 추출 등.
- **요약 통계**: 평균(mean) 등 집계.
- **형태 바꾸기(reshape)**: 피벗 등.
- **조인**: 여러 DataFrame을 **결합(join)**.

**함께 쓰는 생태계**
- **NumPy**: 수치 연산.
- **Matplotlib / Seaborn**: 시각화.
- **scikit-learn**: 머신러닝.

| 구분 | 역할 |
|------|------|
| NumPy | 배열·수치 연산 기반 |
| Pandas | 표 데이터·레이블·결측·그룹·시계열 |
| matplotlib / seaborn | 그래프 |
| scikit-learn | 학습·예측 파이프라인 |

**NumPy와 맞춰 보는 확장**

| | NumPy (3강) | Pandas (4강) |
|---|-------------|--------------|
| 1차원 | 1D `ndarray` (위치 0,1,2…) | **Series** — 1차원 + **레이블(index)** |
| 2차원·표 | 2D `ndarray` | **DataFrame** — 행·열 **레이블** + 열마다 dtype 달라도 됨 |
| 강조 | 동질 dtype, 축·shape, 벡터화 | **레이블**로 선택·집계·실무 표현 |

## 3. 데이터 구조: Series — import pandas as pd부터

가장 먼저 **임포트**한다. 관례적으로 **`pd`** 를 쓴다. `np.nan` 등과 **NumPy를 같이 쓰는 예제**에서는 `import numpy as np`를 함께 둔다.

```python
import pandas as pd
```

**시작점: 1차원 + 레이블**

- **Series**는 **한 줄(1차원)** 짜리 데이터에, 각 칸마다 붙는 **이름표(index)** 가 있는 구조다.
- NumPy 1D 배열이 “**위치(정수 인덱스)** 로만 구분”이라면, Series는 “**위치 + 의미 있는 레이블**”로 같은 1차원을 다룬다.
- **dtype**은 정수·실수·문자열·불리언 등 **무엇이든** 담을 수 있다(실무에서는 열마다 타입이 다른 표를 DataFrame으로 두지만, **Series 하나** 안에서는 보통 한 가지에 가깝게 쓴다).

**정의(공식적 한 줄)**

- **Series**는 **1차원 라벨이 붙은 배열**(one-dimensional labeled array)이다.

**실무 맥락**
- 분석에서는 “깨끗한 데이터”보다 **불완전·결측이 섞인 데이터**를 자주 다룬다.
- Pandas는 결측을 **탐지·처리**하는 함수를 제공한다.
- **`isna()`**: 각 원소가 결측(NaN 등)인지 **불리언**으로 반환한다.

**왜 NumPy 1D와 비슷하게 느껴지는가**

- 둘 다 **한 줄(1차원)** 로 값을 담고, **원소 단위 연산·슬라이싱**이 가능하다.
- **한 타입에 가깝게** 쓰는 점도 비슷하다: NumPy `ndarray`는 **동질 dtype**(한 배열 안에서 `int64`만, `float64`만 등). Series도 보통 **한 Series 안에 하나의 dtype**에 맞춘다(교재: *Supporting a single data type*).

**그런데 “전부 float만”이 NumPy의 특징은 아니다**

- NumPy는 **꼭 float만** 담는 것이 아니라, **`int64`, `bool`, `object`** 등 **정해진 dtype 하나**로 통일된 배열을 만든다. 수치 예제에서 float가 많이 나와서 그렇게 느낄 수는 있다.

**차이의 핵심은 dtype이 아니라 “인덱스가 무엇을 가리키느냐”**

| | NumPy 1D `ndarray` | Pandas `Series` |
|---|-------------------|-----------------|
| **위치** | 기본은 **0, 1, 2, …** 정수 **위치** | **정수 위치** + **별도의 index 레이블**(문자·날짜 등 가능) |
| **접근** | `arr[0]`, 슬라이스가 **항상 위치 기준** | `s[0]` / `s["a"]` / `s.loc[…]` — **레이블**로 직접 집을 수 있음 |
| **연산 정렬** | 같은 위치끼리 맞춤 | Series끼리 연산 시 **인덱스(레이블)를 기준으로 정렬·맞춤**(alignment) |

즉, “한 가지 dtype만 담는다”는 점은 비슷하지만, **NumPy는 값의 줄에 붙는 이름이 사실상 “몇 번째 칸인가”뿐**이고, **Series는 그 줄 옆에 붙는 “이름표(index)”가 데이터와 분리되어 있고, 그 이름표를 기준으로 고르고 합친다**는 점이 가장 큰 실무적 차이다. (결측 `NaN`을 일상적으로 다루는 방식도 Pandas 쪽이 더 분석 친화적이다.)

**인덱스(index) — 교재 요지**

- 축 방향의 레이블을 통틀어 **index**라고 부른다. (*The axis labels are collectively referred to as the index.*)
- `data`가 `ndarray`이면 **index 길이는 data와 같아야** 한다. (*If data is an ndarray, index must be the same length as data.*)
- index를 넘기지 않으면 **`[0, 1, …, len(data) - 1]`** 이 자동 생성된다. (*If no index is passed, one will be created having values [0, …, len(data) - 1].*)
- Series는 **고정 크기 딕셔너리**와 비슷하게, **index 레이블로 값을 get/set** 할 수 있다. (*A Series is also like a fixed-size dictionary in that you can get and set values by index label.*)

**레이블로 접근한다는 뜻**

- `index=` 로 **우리가 정의한 이름(`'a'`, `'b'`, … 또는 날짜 등)** 을 붙이면, **특정 원소(element)에 접근할 때** 정수 위치(`0`, `1`, …)뿐 아니라 **그 레이블**을 써서 골라낼 수 있다.
- 즉 **“인덱스(여기서는 레이블)”가 가리키는 칸의 데이터**에 붙인 이름으로 접근하는 것이다. (`s["a"]` ↔ 딕셔너리의 `dict["a"]`와 같은 읽기 습관.)

**생성·접근 예제**

```python
import numpy as np
import pandas as pd

# (1) 기본 — 인덱스 생략 시 0, 1, 2, …
s1 = pd.Series([10, 20, 30])
# s1[0] → 10

# (2) 레이블 명시 — 의미 있는 index로 접근
s2 = pd.Series([10, 20, 30], index=["a", "b", "c"])
# s2["b"] → 20  (또는 s2.loc["b"])

# (3) 딕셔너리 — key가 index
s3 = pd.Series({"서울": 9, "부산": 15, "제주": 3})

# (4) 결측(np.nan) 포함 — 정수와 NaN이 섞이면 Series는 보통 float64로 올림(승격)
data = [1, 2, np.nan, 4]
indexed_se = pd.Series(data, index=["a", "b", "c", "d"])
print(indexed_se)
# a    1.0  /  b    2.0  /  c    NaN  /  d    4.0  ;  dtype: float64

indexed_se["a"], indexed_se["b"]  # (1.0, 2.0) — 레이블 'a', 'b'로 접근
```

- **리스트 + `index=`**: 값 순서와 레이블 순서를 **한 줄씩 짝지어** 만든다(강의 도표: 왼쪽 열 index, 오른쪽 열 data).

**딕셔너리와의 대응 — 키→index, 값→data**

- 파이썬 관점에서 Series는 **키(key)·값(value) 쌍**으로 익숙한 **딕셔너리**와 잘 맞물린다.
- **`dict`의 key** → Series의 **index(레이블)**  
- **`dict`의 value** → Series의 **data(각 원소의 값)**  
- 교재 슬라이드의 *key → index, value → data* 가 바로 이 대응이다. `pd.Series(딕셔너리)`를 쓰면 **별도로 `index=`를 주지 않아도** key가 곧 index가 된다.

```python
# 예: 월별 매출 — key가 월 이름(index), value가 금액(data)
income = {"1월": 9500, "2월": 6200, "3월": 6050, "4월": 7000}
income_se = pd.Series(income)
# 1월   9500
# 2월   6200
# 3월   6050
# 4월   7000
# dtype: int64

# 간단한 대응 확인
d = {"b": 1, "a": 0, "c": 2}
pd.Series(d)
# b    1
# a    0
# c    2
# dtype: int64
```

- 고정 크기 딕셔너리 비유는, **읽기·쓰기를 레이블로 한다**는 점에서 같지만, Series는 **정수 위치·슬라이스·벡터 연산** 등 배열 쪽 연산도 함께 쓴다는 점에서 dict보다 넓다.

**집계(aggregation) — Aggregation functions**

- Series **안에** 요약·통계를 위한 **메서드**가 들어 있다. 그래서 **다른 라이브러리 함수를 따로 부르지 않고도**, 객체에 붙인 **`.max()`**, **`.mean()`** 등으로 **같은 Series 데이터**를 바탕으로 값을 구할 수 있다. (교재: *Example of computing max and mean of series data.*)
- 대표 예: **`max()`** (최댓값), **`mean()`** (산술 평균). 이외에도 `sum()`, `min()`, `count()`, `std()` 등이 같은 방식으로 쓰인다.

```python
# 앞서 만든 income_se(월별 수익 Series)를 그대로 사용
print(
    "월 최대 수익:",
    income_se.max(),
    ", 월 평균 수익:",
    income_se.mean(),
)
# 월 최대 수익: 9500 , 월 평균 수익: 7187.5
```

- **NumPy 함수**(`np.max(s.values)` 등)로도 구할 수 있지만, 강의에서는 **Pandas Series 메서드**로 끝내는 패턴을 강조한다.

**다음 단계**

- **Series**로 “**레이블 달린 1차원**”에 익숙해지면, 같은 원리가 **행·열 두 축**으로 확장된 것이 **DataFrame**(§4)이다.

## 4. 데이터 구조: DataFrame

**정의**
- **DataFrame**은 **2차원 라벨 구조**이며, **열(column)마다 서로 다른 타입**을 가질 수 있다. (Series 여러 개를 열 방향으로 붙인 표라고 보면 이해가 빠르다.)
- 데이터와 함께 **`index`(행 레이블)**, **`columns`(열 레이블)** 을 선택적으로 지정할 수 있다.

**생성**
- **Series들의 딕셔너리**로부터 생성할 수 있다(열 이름 → Series).

**CSV**
- **CSV**(comma separated values): 쉼표로 구분된 값.
- Pandas는 **`.csv` 파일을 바로 DataFrame으로 읽을 수 있다** (`read_csv` 등).

**index와 columns**
- DataFrame은 **행용 index**와 **열용 columns**를 갖는다.
- **`read_csv(..., index_col=0)`**: **첫 번째 열을 index**로 쓴다(슬라이드: keyword `index_col`, 인자 `0`).

**인덱싱**
- **열 값으로 인덱싱**, 인덱싱과 함께 **연산**하는 패턴이 강의에 나온다.

**열 삭제: `drop()`**
- **`inplace`**
  - `inplace=True`: 메서드 실행 후 **기존 DataFrame을 그 자리에서 갱신**.
  - `inplace=False`: **갱신된 새 DataFrame을 반환**하고, 원본은 그대로 둔다.

## 7. 데이터 정리와 결측값

**행 개수 확인**
- 주어진 데이터의 **행 수**를 확인한다.
- **`count()`** 메서드를 활용하는 방식이 언급된다(`.shape`과 용도 비교).

**결측이란**
- 수집 과정에서 값이 **저장되지 않은** 경우 등.

**탐지**
- **`isna()`** / **`isnull()`** (동일 계열, 별칭)로 결측 여부를 판별한다.

**처리 방식**
1. **삭제**: 결측이 있는 **행 전체 또는 열 전체**를 제거한다(가장 단순).
2. **대체**: **`fillna()`** 로 다른 값으로 채운다.

## 9. 그룹화와 필터링

**`groupby()`**

- 예: **월(month)별로 묶어 월평균** 등을 계산한다.

**필터링(filtering)**
- **조건을 만족하는 행만** 추출한다.
- 슬라이드 예: **3·4·5월**만 평균 풍속이 **4 m/s 초과**, 나머지 달은 그 미만 — 조건에 맞는 데이터만 남기는 식의 **부분 선택**.

## 13. 탐색적 데이터 분석(EDA)

**Exploratory Data Analysis (EDA)** 는 **초기 데이터 조사**에 쓰는 **통계적 접근**이다.

**목적(슬라이드)**
- **패턴 발견**(pattern discovery), **이상 탐지**(anomaly detection), **가설 검정**(hypothesis testing) 등.
- 데이터의 **구조**를 이해하고, **모델 선택**을 돕고, **추가 연구·분석 방향**을 찾는다.
- **분포와 값**을 살펴보면, 데이터가 담는 **현상**을 더 잘 이해하고 **잠재적 문제**(결측 등)를 짚을 수 있다.
- 문제 정의 단계에서 드러나지 않았던 **다양한 패턴**을 발견할 수 있다.

**체크리스트(슬라이드)**
1. 분석 **목적**과 관련 **변수**를 명확히 한다.
2. 데이터 **전체**를 살편다(이상치·**결측** 등).
3. **개별 속성** 값의 분포·특성을 관찰한다.
4. 속성 **사이의 관계**에 초점을 맞춘다(**상관**, **시각화**).

| 단계 | 내용 |
|------|------|
| 목적·변수 | 무엇을 밝힐지, 어떤 열이 관련 있는지 |
| 전체 점검 | 행·열 수, 결측, dtype |
| 개별 속성 | 히스토그램, 요약통계, 범주별 비율 |
| 관계 | 산점도, 상관행렬, 교차표 등 |

## 17. 개별 속성 관측: 생존율·박스플롯

**범주별 평균 생존율** — `groupby(...).mean()` 후 **가로 막대(`barh`)**, x축 `[0, 1]`로 **생존 비율**을 비교한다.

```python
import matplotlib.pyplot as plt

figbi, axesbi = plt.subplots(2, 4, figsize=(16, 10))
titanic.groupby("pclass")["survived"].mean().plot(kind="barh", ax=axesbi[0, 0], xlim=[0, 1])
titanic.groupby("sibsp")["survived"].mean().plot(kind="barh", ax=axesbi[0, 1], xlim=[0, 1])
titanic.groupby("parch")["survived"].mean().plot(kind="barh", ax=axesbi[0, 2], xlim=[0, 1])
titanic.groupby("sex")["survived"].mean().plot(kind="barh", ax=axesbi[0, 3], xlim=[0, 1])
titanic.groupby("embarked")["survived"].mean().plot(kind="barh", ax=axesbi[1, 0], xlim=[0, 1])
sns.boxplot(x="survived", y="age", data=titanic, ax=axesbi[1, 1])
sns.boxplot(x="survived", y="fare", data=titanic, ax=axesbi[1, 2])
plt.tight_layout()
plt.show()
```

- **연속형 age, fare**는 **박스플롯**으로 생존(0/1) 집단 간 **분포 차이**를 본다.

## 19. 해석: 성별·객실 등급·요금

슬라이드에서 강조한 **정성 해석**(영문 표현은 슬라이드에 맞춤):

- **성별(sex)**  
  - 남성 **생존율은 대략 20% 전후**, 여성은 **약 75%** 수준으로 관찰되는 예시가 제시된다.  
  - → **성별과 생존** 사이에 **강한 관계**가 있다고 해석할 수 있다.

- **객실 등급(pclass)**  
  - **1등급** 승객은 생존율이 **약 60%** 부근, **3등급**은 **약 22%** 부근 등으로 비교된다(대략적 수치는 그래프·표에 따름).  
  - → **등급이 높을수록 생존율이 높은 경향**이 뚜렷하다.

- **운임(fare)**  
  - 박스플롯 등으로 **생존 그룹과 요금 분포**가 다소 다름이 보이면, **요금과 생존** 사이에 **어느 정도 관계**가 있다고 볼 수 있다(슬라이드: *marginal relationship*).

## 20. 변수 간 관계: 상관행렬·히트맵

**수치형만** 골라 **피어슨 상관계수 행렬**을 구하고 **히트맵**으로 시각화한다.

```python
import numpy as np

numeric_data = titanic.select_dtypes(include=[np.number])
corr = numeric_data.corr()

plt.figure(figsize=(12, 10))
sns.heatmap(corr, annot=True, fmt=".2f", cmap="coolwarm")
plt.title("Correlation Matrix Heatmap")
plt.show()
```

**슬라이드에서 짚는 관계(표현은 원문 의도 유지, 철자만 정리)**

- **Fare ↔ Survived**: **양(+)의 상관** — 운임이 높을수록 생존과 함께 움직이는 경향.
- **Pclass ↔ Survived**: **음(-)의 상관** — 등급 숫자가 클수록(3등) 생존과 반대 방향으로 해석되기 쉬움(변수 정의에 따라 부호 해석 주의).
- **Fare ↔ Pclass**: **음(-)의 상관** — 등급이 높을수록(1등) 요금이 높으므로 등급 인코딩과 요금의 관계와 일관되게 읽는다.
- **Age ↔ Pclass**: **음(-)의 상관** 등이 언급된다 — 나이·등급 구조가 데이터 안에서 어떻게 겹치는지 **참고용**으로 본다.

> 상관계수는 **선형 관계**만 요약하며, **인과**를 뜻하지 않는다. 범주 변수는 원핫 인코딩 등으로 바꾼 뒤 상관을 보는 식으로 확장할 수 있다.
